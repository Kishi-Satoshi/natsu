# 文字起こしの候補を、この PC で比べる（bench-stt.ps1）

計画: `docs/plans/2026-10-27-stt-bench.md`。NaTsu には組み込まない、測るためだけの道具です。NaTsu の設定・取り込んだエンジン・議事録は変えません（NaTsu が取り込んだモデルは、同じ中身なら読むだけで使います）。

## 入っているもの

| ファイル | 役目 |
| --- | --- |
| `bench-stt.ps1` | 落とす・照らす・音声を直す・測る・表を作る（PowerShell 5.1） |
| `wavprep.js` | 会議の WAV を 16kHz・モノラル・16 ビットにし、75 秒ずつに切る |
| `cer.js` | 文字誤り率（CER）を出す（数だけ） |
| `probe.js` | ほかのアプリがもたつかないかの目安（時計の遅れ・決まった計算の時間）を測る |

`.js` の3つは、NaTsu.exe を Node として動かします（`ELECTRON_RUN_AS_NODE=1`。Claude デスクトップが NaTsu の MCP を起こすのと同じ使い方）。ほかに入れるものはありません。

## 1. 音声の用意（2〜3 本。1 本 10 分以上）

NaTsu は文字にした後に区切りの音声（`segbuf`）を消すので、NaTsu からは会議の音声を取り出せません。別に録ります。

1. Windows の「サウンド レコーダー」を開き、［…］→［設定］→「録音形式」を **WAV** にする（品質は「自動」のままでよい）。
2. 対面の打ち合わせ（または、スピーカーで鳴らす Web 会議）で、**NaTsu をいつもどおりオンライン（クラウドの文字起こし）で録りながら**、サウンド レコーダーでも録る。始めるのはなるべく同時に。
3. 社外秘・個人の話の多い会議は使わない。音声はこの PC の `%LOCALAPPDATA%\natsu-bench\stt` にだけ置き、送らない・git に入れない。

## 2. 実行

4 つのファイルを同じフォルダ（例: ダウンロードの下の `stt-bench`）に置き、PowerShell で:

```powershell
powershell -ExecutionPolicy Bypass -File .\bench-stt.ps1
```

- 候補のエンジンとモデルを落として SHA-256 を照らす（合わなければ取り直す。止まっても続きから）。
- WAV を1本ずつ窓へドラッグする（頭から 10 分を使う。`-MaxMinutes` で変えられる）。
- 参照を入れる: NaTsu で同じ会議を開き、文字起こしのタブの［コピー］→ 開いたメモ帳に貼って上書き保存。
- NaTsu をタスクトレイから［終了］して Enter。あとは放っておく（電源につなぎ、PC を触らない）。10 分の音声 3 本で **約 2〜3 時間**（今のモデルは音声の約 2 倍の時間がかかる見込み）。途中で止めても、次は続きから。

ほかの使い方: `-Only A0,C`（候補をしぼる）・`-Extra`（任意の候補 G も）・`-CerOnly`（参照を後から入れたとき、CER と表だけ作り直す）・`-Clean`（音声と文字を消す。表は残る）。

## 3. 送るもの

`%LOCALAPPDATA%\natsu-bench\stt\results\summary.md` の中身をそのまま貼る。**数だけ**で、会議の文・ファイルの名前・利用者のパスは入りません。候補の文字起こし（`raw\`）と参照（`ref\`）はこの PC の中に残るので、終わったら `-Clean` で消してください。
