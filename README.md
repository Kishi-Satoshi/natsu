# NaTsu

音声入力・議事録ツール。インターネットにつながっているときは、文字起こしをクラウド（会社の文字起こしの中継を通して OpenAI。
［設定］の「アカウント」で会社のメールアドレスでログインした PC だけ）で、要約をご自分の Claude Code で行います。
ローカル AI の準備（PC の中の文字起こしのエンジン。約 0.6GB の取り込み）は任意です。取り込んだ PC では、つながっていないときも
文字起こし（whisper.cpp）を PC の中で行います。取り込んでいない PC では、つながっていないときの音声を残し、
つながると文字起こしします（取り込み方は下の「エンジン（文字起こし）」。［ローカル AI を使う（約 0.6GB を取り込む）］を押します）。
要約は、いつもご自分の Claude Code で作ります（0.10.0 から）。会議の終わりにつながっていなければ「要約待ち（つながったら作ります）」と出し、つながったら自動で作ります。
何をどこへ送るかは下の「オンラインの文字起こしと要約」に書きました。
議事録は Notion 風のページ／ブロック構造で保存されます。

## このリポジトリについて

このリポジトリは作っている間は公開しています。会社の名前・会社のドメイン・人の名前・社内の情報は、コード・文書・テストに書きません（公開前の確認の決まり）。

## 中核 — 出典リンク

要約の各要点には、**根拠となった発言へのリンク**が自動で付きます。
`[1]` をクリックすると文字起こしの該当箇所へジャンプし、その発言がハイライトされます。

対応する発言が見つからない要点には、あえてリンクを張らず「根拠なし」と表示します。
LLM が創作した内容をそこで見分けられるようにするためです。

札は3種類を区別します。「根拠なし」は照合したが発言が見つからなかった要点、
「手書き」は自分で足した行（照合の対象外）、「編集済み」は本文を直した後に
出典を照合し直していない行です（「要約を再生成」で付け直せます）。
「🔗 出典 x/y」の分母には手書きの行を数えず、分子には編集済みの行を数えません。

技術的には、LLM にセグメントIDを出力させていません（3Bクラスのモデルは
存在しないIDを捏造するため）。生成後の要約と文字起こしを、
文字バイグラムのIDF重み付き一致で機械的に突き合わせています。

## 会議の種類とメモの型・打ち合わせの質

ページの上の「会議の種類」（0.11.0 から。録音中のページにもあります）で選んだ種類から、メモの見出しと要約の組み立て（メモの型）が決まります。
型を別に選ぶ欄はありません。

| 会議の種類 | メモの型 | 型の見出し |
|---|---|---|
| 朝会・内部定例会 / 部会・報告会 | 進捗・報告の確認（空・雨・傘） | 前回の宿題の状況 / 報告ごとに 事実（進捗・課題）・見立て（原因・リスク）・打ち手の案 |
| ブレスト・意見交換 | 会議の要点（論点整理） | 目的 / 論点ごとの要点 |
| 1on1 | 1on1の振り返り（GROW） | テーマ・目標（G） / 現状と困りごと（R） / 選択肢・上司の助言（O） |
| 採用面接・事前面談 | 面接の確認（STAR） | 経歴・スキル / 行動の具体例 / 本人からの質問・懸念 / 条件 |
| 商談 | 商談の確認（BANTC） | 課題・要望（N） / 時期（T） / 決め方・決裁者（A） / 予算（B） / 競合・比較先（C） |
| プレゼン形式 | プレゼン形式（要旨・質疑） | 発表の要旨 / 質疑応答 / 出た意見・懸念 |

- **自動:** 初めは「自動（文字起こしから判定）」で、題名と話の冒頭から要約のときに決めます。決まらなければ、前の同じ曜日・時刻ごろの会議で手で2回以上選んだ種類を使い、それでも決まらなければ会議の要点の型でまとめます。0.10.x までの「一般・その他」は無くなり、その会議は「自動」と出ます（要約の中身は変わりません）。
- **手で選ぶ:** 手で選んだ種類は自動の判定より先に効きます（変更後は［要約を再生成］で反映。要約の途中で変えたときも選んだ種類が残ります）。メモが空か型の見出しのままなら、その型の見出し（「■ 予算（B）」など）がメモに入ります。書いたメモは上書きしません。録音中に選ぶと、メモのタブに切り替わります。
- **要約の組み立て:** 型の見出しの後に、どの型にも締めの「決定事項」「持ち越し」「ToDo（誰が・何を・いつまでに）」「抜け・重なりチェック」と「次に気をつけること」が付きます。画面と［コピー］では締めの3つが先頭に並びます（保存の順は変えません）。話していない見出しは本文に出さず、「未確認: …」の1行にまとめます。メモにだけある内容には「（メモより）」が付きます。担当と期限は、文字起こしとメモに出てくるものだけを載せます（要約のモデルが書いても、発言に無ければ外します）。分からない ToDo は「担当: 要確認」「期限: 要確認」と出ます（データには書きません）。
- **打ち合わせの質:** 要約の最後に、会議の進め方の目安を 25 点で付けます（目的と結論・抜け・重なり・決定事項は AI、ToDo の具体さ・型の埋まり具合は NaTsu が数えます。合計は NaTsu が数え直します）。人の評価ではありません。文字起こしが短い（400 文字未満）会議と、AI の答えの形を読めなかったときは付けません。既定ではすべての会議に付け、［設定］→［要約］の「打ち合わせの質」で、1on1 と採用面接・事前面談を除く・付けない、を選べます。

## アクションアイテムの構造化

要約から担当者と期限を取り出し、**日本語の相対表現を実日付に変換**します。

- 「来週金曜」「今月末」「3日後」「8/30」「2週間後」などを会議日を基準に解釈
- 解釈できない表現は推測せず、元の表記のまま残します
- 「山田さん」「佐藤部長」などの敬称・役職は姓に名寄せ

サイドバーの「アクション」で全議事録を横断し、**期限超過 / 今日 / 今週中 / 先の予定 / 期限なし**
にグループ分けして表示します。担当者での絞り込みも可能です。
担当・期限のチップはクリックで手修正できます。

## 機能

### 議事録
- 録音 → 約75秒ごとにリアルタイム文字起こし（最初の1回は20秒で早く結果を出す）
- 終了時に要約を生成（メモの型の見出し／決定事項／持ち越し／ToDo／抜け・重なりチェック／次に気をつけること）。いつもご自分の Claude Code（つながっていなければ「要約待ち」にして、つながったら自動で作る）
- 会議の種類から決まるメモの型の要約構成（自動判定・手動変更可）と打ち合わせの質（25 点）
- 担当者・期限を自動抽出し、実日付へ正規化
- 出典リンク付きのブロック表示。テキストはクリックで直接編集可能
- 文字起こしもクリックで直接編集可能。直した区間の出典リンクは自動で引き直される（他の要点の出典は動かさない）
- Web会議の相手の声も記録（設定で有効化。Windows のみ）
- チェックボックス、行の追加（Enter）・削除（空行でBackspace）
- ［🔍 検索］（Ctrl+P）で開く検索の窓で、題名・要約・メモを探す。窓の中でアクション横断ビュー（期限順・担当者別）と文字起こし検索も選べる
  （発言したかどうかを探す用途では、編集されうる要約より原文の方が確かです）
- 上の帯の「···」の［コピー］で、開いているページの内容（議事録・文字起こし・メモ）をコピー（要約を再生成・削除も「···」の中）
- クラッシュ耐性: 文字起こしは区間ごとに自動保存され、強制終了しても次回起動時に復旧
- **録音バー（0.9.0 から）:** 録音中は小さな暗い録音バーが出ます（ロゴ・音の大きさの5つの点・経過時間・一時停止のボタン・赤い停止のボタン）。
  5つの点は、声が入ると左から伸び、無音のときは短いまま並びます。相手の声を録っているときは、相手が話している間だけスピーカーの印が青緑になります。
  置き場所は画面の8か所（四隅・上下の中央・左右の中央）で、［設定］→［録音］の「録音バーの置き場所」で選べます。録音中にドラッグして離すと、一番近い置き場所に吸い付きます。
  左右の中央では縦の形になり、縦のときは × で隠せます。隠した録音バーは、録音中のページの［録音バーを出す］か、トレイの［録音バーを表示］で出し直せます。
  前の版で動かした位置は、初めの1回だけ一番近い置き場所に直します。

### 画面の使い方（0.6.0 から）
- **サイドバー:** 左にいつも出ています。上から［🔍 検索］・［＋ 新しい議事録］・議事録の一覧、下に音声入力と設定。一覧の行に乗せると、日付・長さ・要約の有無と会議の種類（選んだか決まったときだけ）が出ます。幅は右の縁をドラッグするか、縁にフォーカスして ←／→ で変えられます。［«］か `Ctrl+\` で畳み、［»］か `Ctrl+\` で出します。
- **タブ:** 開いているページは上のタブに並びます。一覧を押すと今のタブで開き、`Ctrl+クリック`（またはホイールのクリック）で新しいタブで開きます。音声入力もタブで開きます。タブの × かホイールのクリックで閉じ、`Ctrl+Tab`／`Ctrl+Shift+Tab` で次・前のタブへ移ります。
- **設定（0.9.0 から）:** ［⚙️ 設定］は、今のページの上に開きます。左の列で項目を選び、上の欄で設定の名前を探せます。Esc か × で閉じます。項目は「アカウント」「一般」「録音」「要約」「ローカル AI」「更新」です（0.9.2 までは「ローカル AI」を「オフライン」、［オフラインモード］を「この会議は PC の中だけ」と呼んでいた）。
- **検索の窓:** ［🔍 検索］か `Ctrl+P` で開きます。打つと結果が変わり、↑↓で選んで Enter で開き、`Ctrl+Enter` で新しいタブで開きます。Esc で閉じます。
- **記録中のページ:** ［＋ 新しい議事録］を押すと録音の前のページが開きます（0.13.0 から。まだ録音しません）。会議の種類を選んだり［メモ］にアジェンダを書いたりしてから、青い［文字起こしを始める］を押すと記録が始まり、「記録中」のタブになります（クラウドで文字起こしする PC は［オフラインモードで始める］も選べます。録音を始めずにタブを閉じると何も残りません）。ページには「始めると、録音と文字起こしに参加者全員が同意したものとみなされます。」と音声の送り先が出ます。`Alt+M`・会議の知らせのパネル・トレイの［議事録の記録を開始］は、今までどおりすぐ始めます（録音の前のページを開いていれば、そのメモと種類のまま）。経過時間・［⏸ 一時停止］と［▶ 再開］（`Ctrl+Shift+P`）・赤い［■ 終了して作成］・流れる文字起こし・メモがあります。終わると、要約の入ったページに替わります。止めていた時間は文字起こしに印が付きます。
- **スリープ:** 会議中に PC がスリープしたら録音を一時停止にし、戻ったら「スリープから戻りました…」と知らせて再開を促します（自動では再開しません）。
- **話し声が無いとき（0.9.1 から）:** 話し声の無い時間が 10 分続くと、録音中のページの帯・録音バー・Windows の知らせ（録音中のページを見ていないとき）で「会議は終わりましたか？」と聞きます（［続ける］［終了して作成］）。5 分たっても答えが無く話し声も無ければ、録音を止めて議事録を作り、「最後の発言 51:28」のように知らせます（聞いている間に止めた議事録の所要時間には、話し声の無い終わりの部分を入れません）。一時停止の間は数えず、再開すると数え直します。［設定］→［録音］の「話し声が無いときに自動で止める」で切れ、「知らせるまでの時間」で 5〜60 分を選べます。
- **会議を出たとき（0.12.1 から）:** Teams・Zoom・Chrome・Edge の会議を出ると、会議のアプリがマイクを使わなくなったのを見て、聞かずに 6 秒ほどで録音を止めて議事録を作り、Windows の知らせ「会議を出たので録音を止めました。議事録を作っています。」を 1 回出します（押すとそのページが開きます）。所要時間は会議を出た時までです。会議に入るときなどの数秒の放しでは止めず、ミュートしただけでは止まらない見込みです。一時停止の間は数えません。誤って止まったら新しい議事録で録り直し、前の議事録の文字起こしを［コピー］して新しい議事録の［メモ］に貼れます（ヘルプの「会議を出たとき」）。［設定］→［録音］の「会議を出たら自動で止める」で切れます（オンの間は、録音中も Windows の「マイクを使っているアプリ」の記録を 2 秒ごとに読みます）。
- **音の無い区間（0.9.1 から）:** 音がほとんど無い区間（一番大きい 0.5 秒が -55 dBFS より小さい）は、クラウドにも PC の中の文字起こしにも送りません。文字起こしの答えが認識のヒントの言葉（「お疲れさまです。よろしくお願いします。」・業務の言葉・辞書の語）だけなら、議事録に書きません。
- **拡大:** `Ctrl+＋`（日本語のキーボードでは `Ctrl+；` のキー）・`Ctrl+－`・`Ctrl+0`、`Ctrl+ホイール` で大きさを変えます。200% で止まります。
- **外観（0.7.0 から）:** ［設定］の「一般」の「外観」で「システム設定を使用」「ライト」「ダーク」を選ぶと、すぐ配色が切り替わります。NaTsu の窓で `Ctrl+Shift+L` を押すと、ライトとダークを切り替えます（選んだものは設定に残ります）。
- **覚えるもの:** 窓の大きさと位置・最大化・拡大の倍率・サイドバーの幅と畳み・開いていたタブを、次に起動したときに戻します（録音中のタブと、消したページのタブは戻しません）。置き場所は `%LOCALAPPDATA%\natsu\window-state.json` です（議事録とは別の、この PC だけのファイル。消すと最初の大きさで開きます）。

### 音声入力
- どのアプリでも `Ctrl+Shift+Space` → 話す → カーソル位置へ自動貼り付け
- フィラー除去、ユーザー辞書、マイク選択、統計

### Web会議の相手の声

既定では、記録するのはマイクの音だけです。ヘッドホンを使っていると
相手の発言は一切入らないため、リモート会議の議事録としては成立しません。

[設定] → [議事録で相手の声も録る] を有効にすると、マイクに加えて
パソコンから出ている音（スピーカーやイヤホンへ流れている音）も一緒に記録します。

- **Windows のみ**動作します。他のOSではマイクだけで記録します。
- パソコンで鳴っている音はすべて入ります。通知音や動画の音も混ざります。
- スピーカーで会議をすると、相手の声がマイクからも入って二重になります。
  **イヤホンの使用をおすすめします。**
- 記録するのは Windows の「既定の再生デバイス」に出ている音です。
  録音の開始時点で決まり、途中でイヤホンを抜き差ししても切り替わりません。
- 取り込めなかった場合は、マイクだけで記録を続けます。
  録音バーの表示が「議事録を記録中（マイクのみ）」に変わります。
- 音声入力（ホットキー）は常にマイクだけを使います。
- **録音していることは、会議の参加者へ伝えてください。**

相手の声も、マイクの音と同じ扱いです（オンラインの文字起こしを「使う」にしていれば送り先へ送り、そうでなければ PC の中だけで処理します）。

#### 文字起こしの「自分」「相手」（0.12.0 から）

相手の声も録る会議では、マイクの音と、パソコンから流れた相手の声を別々に録り、別々に文字起こしします。

- 文字起こしの行の時刻の後に、マイクの行は「自分」、パソコンから流れた声の行は「相手」と付きます。行は話した時刻の順に並び、同時に話した所は両方の行が出ます。
- 同じ部屋の人の声もマイクから入るので「自分」になります。
- 声の無い所は文字起こしに送りません（クラウドの文字起こし）。PC の文字起こしでは、長い区間を whisper の文の時刻で文ごとの行に分けます。
- ヘッドホンを使わないと相手の声がマイクにも入ります。相手の行と同じ言葉の「自分」の行は除きますが、除ききれないことがあります。
- 札は要約に渡す文字起こし・文字起こしのタブの［コピー］・Claude から読むとき（MCP）にも入ります。要約の ToDo の担当は札だけでは決めません。
- 相手の声を録らない会議と、取り込みが途中で切れた後の行には札が付きません（切れたことは議事録の経過に残ります）。札は直せません。

### ホットキー
- `Ctrl+Shift+Space` … 音声入力（変更可）
- `Alt+M` … 議事録の開始／終了（変更可）
- 録音バーのボタンの名前には、そのホットキーが入ります（ボタンに乗せると出ます）。
- NaTsu の窓の中だけ: `Ctrl+P` … 検索の窓、`Ctrl+Shift+P` … 記録中の一時停止／再開、`Ctrl+\` … サイドバーを畳む／出す、`Ctrl+＋`・`Ctrl+－`・`Ctrl+0` … 拡大（200% まで）

## オンラインの文字起こしと要約

インターネットにつながっているときは、文字起こしをクラウドで、要約をご自分の Claude Code で行います。
つながっていないときの文字起こしは、PC の中の whisper.cpp で行います（区間ごとに決めます）。要約は、つながっていないときは作らずに
「要約待ち（つながったら作ります）」と出し、つながったら自動で1回作ります（0.10.0 から。PC の中では要約しません）。
どこで処理したかは、議事録の上の行に「☁ 文字起こし: クラウド（OpenAI）12・PC 2」「✨ 要約: Claude Code」のように出ます
（0.9.x で PC の中で作った要約は「🖥 要約: PC（オフライン）」のままです）。

**0.8.0 から、クラウドの文字起こしは会社の「文字起こしの中継」を通します。** PC には OpenAI の鍵を置きません。
［設定］の「アカウント」の［ログイン］から、会社のメールアドレスと、メールで届くコードでログインすると、クラウドで文字起こしします（ログインの画面は Cloudflare Access の英語の画面です）。
ログインしていないときと、つながっていないときは、PC の中で文字起こしします。
0.7.0 までの［詳細設定（管理者用）］の鍵の欄は無くなり、PC にしまってあった前の版の鍵（OpenAI・Groq など）は、0.8.0 の起動のときに消します（鍵そのものは OpenAI などの画面に残ります）。

### 文字起こしの道

音声の通る道は、**PC → 文字起こしの中継（Cloudflare の workers.dev）→ OpenAI** です。

- 中継の住所は `https://natsu-relay.natsu-code.workers.dev` です（会社名や人の名前は入れていません）。
- 中継は **Cloudflare Access**（Cloudflare の、ログインした人だけを通す仕組み）の後ろにあります。ログインしていない要求は、中継に届く前に Cloudflare が断ります。中継も、Cloudflare Access の札（JWT）を自分で確かめ、会社のドメインのメールアドレスだけを通します。
- PC は、録った区間の音声（WAV）と、ログインの cookie（Cloudflare Access の札）を中継へ送ります。中継は会社の OpenAI の鍵を付けて OpenAI（`gpt-4o-transcribe`）へ渡し、文字だけを PC へ返します。会社の鍵は Cloudflare の秘密の欄にだけあり、PC・リポジトリ・記録には出ません。
- **中継は音声も文字も保存しません。** 中継の記録に残すのは、状態の番号・かかった時間・音声の秒数などの数と符号だけです（メールアドレス・IP・文字・認識ヒントは残しません）。OpenAI での扱いは OpenAI の API の規約のとおりです。会社の情報を米国の会社（OpenAI・Anthropic）へ送ってよいかは、情報システムの確認を取ってください。
- 中継で文字起こしする会議は、区切りを **15 秒**にします（文字が早く出て、止まったときにすぐ気づけます）。PC の中で文字起こしする会議は今までどおり設定の長さ（既定 75 秒）です。
- 1人の1日の音声と、全員の1日の音声には上限があります（既定は 1人 4 時間・全体 100 時間。日本の日付で数えます）。上限に達した日は、残りを PC の中で文字起こしします。

### 何がどこへ送られるか

- **文字起こし:** 会議と音声入力（ホットキー）の音声を、区間ごとに WAV で中継へ送ります。認識ヒントとして、ユーザー辞書の語と直前の発言の終わりも一緒に送ります。
  送るのは、ログインしていて、中継につながるときだけです。会議を始めると「この会議の音声は OpenAI に送られます…」と知らせます。
- **ログイン:** ［ログイン］で開く窓（Cloudflare Access のログインの画面）に入れたメールアドレスは、Cloudflare へ送られます。コードのメールは Cloudflare（Cloudflare Access の One-time PIN）が送ります。NaTsu はメールアドレスとコードを扱いません（ログインした後に、中継が確かめたメールアドレスを設定の画面に出すだけです）。
- **要約:** 文字起こしの文・メモ・会議の種類から決まるメモの型の指示を、ご自分の Claude Code に標準入力で渡します。Claude Code はそれを Claude（Anthropic）へ送って要約します（要約は中継を通しません）。
- **送らないもの:** 録音の控え（`segbuf/`）・議事録・設定・PC のファイル。Claude Code には NaTsu が作る空の作業フォルダ（`%APPDATA%\natsu\claude-run`）だけを渡し、道具（ファイルの読み書き・コマンド）・MCP・あなたの `~/.claude` の CLAUDE.md・フック・プラグインは使わせません（`--safe-mode`）。会話も保存させません。

| 送り先 | 送るもの | 費用 | 保存の扱い |
| --- | --- | --- | --- |
| 文字起こしの中継（Cloudflare） | 音声・ログインの cookie | 会社が持つ（利用者は払わない） | 音声も文字も保存しない（数と符号の記録だけ） |
| Cloudflare Access（ログインの画面） | ログインするメールアドレス | 会社が持つ（Zero Trust Free。50 人まで無料） | Cloudflare の規約のとおり（だれがいつログインしたかを Cloudflare が残す） |
| OpenAI（中継の先） | 音声と認識ヒント | 会社が持つ（1分 約 1 円） | OpenAI の API の規約のとおり |
| Claude Code（要約） | 文字起こしの文・メモ | ご自分の Claude のプランの中（API の従量課金は使わない） | Claude（Anthropic）の規約のとおり |

### ログインの仕方（Cloudflare Access の One-time PIN）

1. ［設定］の「アカウント」の［ログイン］を押します。NaTsu の上に小さな窓が開き、Cloudflare（中継を守る仕組み）のログインの画面が出ます。画面は英語です。
2. 会社のメールアドレスを入れて［Send login code］を押します。数分以内に、Cloudflare から英語のメール（差出人は `noreply＠notify.cloudflare.com`。＠ は半角の @）が届きます。届かなければ迷惑メールのフォルダも見てください。
3. メールの 6 けたのコードを入れて［Sign in］を押します。コードは 10 分で切れ、1回だけ使えます。「already been used」と出たら、［Request new code］でコードを頼み直してください（会社のメールの検査が、先にコードを使ってしまうことがあります。続くときは管理者に知らせてください）。
4. 窓に「ログインできました。この窓は自動で閉じます。」と出て閉じ、カードが「ログイン中: {メール}（{M} 月 {D} 日まで、このままです）」になります。
5. ［ログアウト］でログアウトできます。中継に届かないときも、PC のログインは消します。ログアウトは、同じ人のほかの PC の NaTsu の Cloudflare Access のログインも切ります（Cloudflare の仕組み）。

- 使えるのは会社のメールアドレスだけです。会社のものでないアドレスでも画面は「A code has been emailed to you」と出ますが、メールは届きません（送ったかを明かさない Cloudflare の作りです）。
- ログインの窓は、押したときだけ開きます。ログインが切れても NaTsu が窓を勝手に開くことはありません。録音中に窓を開いたままでも、録音中のページの［■ 終了して作成］は押せます。
- ログインの cookie は Windows の仕組み（DPAPI）で暗号にして `%APPDATA%\natsu\secrets.json` にしまいます（ディスクに平文の cookie を残しません）。`settings.json`・`engine.log`・画面には出しません。暗号にできない PC ではログインできません。
- ログインは、管理者が決めた長さ（7 日）で切れます。切れたときと、管理者が取り消したときは「ログインが切れたため、PC の中で文字起こししています…」と［ログインし直す］が出ます。押すと「アカウント」が開きます。
- 止められたメールアドレスでは「このメールアドレスでは文字起こしの中継を使えないため、PC の中で文字起こしを続けます。管理者に知らせてください。」と出ます。

### インターネットにつながっていないときと［オフラインモード］

- **インターネットにつながっていないとき:** ローカル AI を取り込んだ PC では、PC の中で文字起こしします。要約は「要約待ち（つながったら作ります）」にして、つながったら自動で Claude Code で作ります。会議の途中で回線が切れても、その区間から PC の中で続け、つながり直すとクラウドに戻ります。会議の途中でネットワークから外れたときは、録音中のページの頭に「ネットワークにつながっていません。この PC で文字起こしを続けていますが、精度が落ちます。…」の帯が出ます（つながると消えます）。
- **ローカル AI を取り込んでいない PC:** ログインしてつながっていれば、会議も音声入力も使えます。会議の途中でクラウドで文字起こしできなくなったら、その区間の音声を残して「文字起こし待ち」にし、つながると自動で文字起こしします（会議の要約も、済んだら自動で作ります）。オフラインで始めた会議も、音声を残して同じように後で文字起こしします。音声入力はオフラインでは始めません（録った後でつながらなくなったときは音声を残し、戻ったら履歴に入れます。貼り付けはしません）。
- **中継に届かない・中継が止まっている・上限に達したとき:** その区間を PC の中で文字起こしし直して、録音はそのまま続けます（録音は中継に頼りません）。録音中のページの頭に理由と1つの行動（［もう一度］［ログインし直す］［エンジンを確かめる］）の帯が出て、戻れば消えます。録音中のページを見ていないときは、止まる・行動が要る問題だけ Windows の知らせで1回知らせます。
- **［オフラインモード］:** ネットワークが不安定なとき・つながらないときに、その会議の文字起こしを PC の中に固定するボタンです（クラウドと PC を行ったり来たりしません）。記録中に議事録の画面の［オフラインモード］を押してください。押した後の音声は中継へ送らず、PC の中で文字起こしします（押す前の区間はもう送ってあります）。要約は、ほかの会議と同じく Claude Code で作ります。そのとき文字起こしの文は Claude（Anthropic）へ送られます。つながっていなければ「要約待ち（つながったら作ります）」にして、つながったら自動で作ります。Claude との連携（MCP）で Claude に議事録を読んでもらうときも、オフラインモードの会議の文は Claude へ送られます。守秘のためのボタンではありません（1on1・面談で文字起こしの音声を中継へ送りたくないときには使えます）。ローカル AI を取り込んでいない PC で押すと、音声だけを PC に残します（［ローカル AI の準備］から取り込むと文字起こしします）。押した印は会議ごとで、戻すボタンはありません。次の会議では送る側に戻ります。落ちて復旧した会議でも印は残ります。

### Claude Code の入れ方とログイン

PowerShell を打たなくても、NaTsu の［設定］→［要約］のボタンでできます。

1. Claude Code が見つからないときは［Claude Code を入れる］が出ます。押すと PowerShell の窓が開き、Anthropic の公式の入れ方 `irm https://claude.ai/install.ps1 | iex` を窓の頭に見せてから実行します（管理者の権限は要りません。Git for Windows は無くても動きます）。終わったら窓を閉じてください。NaTsu が確かめ直します。
2. ［Claude Code にログイン］を押すと、見つけた `claude.exe` の `claude auth login` の窓が開きます。案内に従って claude.ai のアカウント（Pro・Max・Team・Enterprise のプラン）でログインし、窓が閉じたら NaTsu が確かめ直します。NaTsu はログインの情報（`~/.claude` の中身）を読みません。
3. ［Claude Code を確かめる］は、ログインの状態（`claude auth status`）を見た後に、決まった1語（`ping`）だけの小さな要求を Claude Code に1つ送ります（ご自分のプランの上限をほんの少し使います。文字起こしは送りません）。「ログイン済み（確かめ済み）」と出れば使えます。ログインの期限が切れているときは「Claude Code のログインが切れています。設定の［Claude Code にログイン］を押してください。」と出ます。

**［Claude Code を入れる］の注意:** インターネットから取った Anthropic の入れる命令を、そのまま PowerShell で実行します（ほかの人が手を入れたものでないかは、`https://claude.ai` を信じることになります）。会社の PC で決まりがあるときは、情報システムに確かめてから押してください。自分で入れるときは、PowerShell で同じ `irm https://claude.ai/install.ps1 | iex` を実行し、`claude auth login` でログインして、`claude auth status` で `"authMethod": "claude.ai"` と出ることを確かめます。

- Claude Code が API キー（`ANTHROPIC_API_KEY` など）で動く設定のときは、従量課金になるので NaTsu は要約を作らずに知らせます。NaTsu は Claude Code を呼ぶときに `ANTHROPIC_` で始まる環境変数を外します。
- `claude.cmd`（古い npm 版など）しか無いときは呼べません。［Claude Code を入れる］で入れ直すか、「Claude Code の場所」に `claude.exe` を指定してください。
- 「Claude Code が古いため…」と出たら、ターミナルで `claude update` を実行してください。

### 上限

- **要約:** ご自分の Claude のプランの上限（5時間ごと・週ごと。Claude のチャットと同じ上限）を使います。上限に達すると、戻る時刻を要約の欄に出します。戻ってから［要約を生成］を押してください。オンラインで Claude Code が使えないとき（上限・ログイン切れ・入っていない）は、PC の中の要約には切り替えません。
- **文字起こし:** OpenAI の上限に近いと、少し待ってから送り直します（待っていることを知らせます）。待ちきれないときは、その区間の音声を残し、議事録を閉じた後にもう一度試します。1日の上限（1人・全体）に達したとき・中継が使えないときは、その区間から PC の中で文字起こしします。

### 届かないとき（会社の通信の検査・Zscaler など）

中継につながらないときは、理由（証明書が差し替えられている・プロキシ）を知らせて、PC の中で文字起こしを続けます。
続くときは、情報システムに次の接続先への通信の許可を頼んでください（文字起こしとログインと要約で PC が直に話すのはこの4つだけです。OpenAI へは中継が送ります。更新の確かめは `api.github.com`・`github.com`、エンジンの取り込みは INSTALL.md の「通す必要のある接続先」の先を使います）。

- `natsu-relay.natsu-code.workers.dev`（文字起こしの中継）… ログインと文字起こし
- `<チームの名前>.cloudflareaccess.com`（Cloudflare Access のログインの画面。`<チームの名前>` は管理者が知っています）… ログイン
- `claude.ai`・`api.anthropic.com` … Claude Code のログインと要約

### Claude から議事録を読む（MCP）

0.10.0 から、Claude デスクトップに NaTsu を登録すると、Claude に「10/20 の議事録を読んでレポートして」「9/1 と 9/15 と 10/1 の議事録から提案資料を作って」のように頼めます。
Claude は頼みに関係のある箇所を NaTsu から受け取り、日付・題名・時刻の出典つきで答えます（資料を作るのは Claude です）。出典のリンクを押すと、NaTsu でその会議のその箇所が開きます。
ページの「···」の［リンクを写す］や、左の一覧の［選ぶ］で選んだ会議の［リンクを写す］で写したリンクを Claude への頼みに貼ると、その会議を読ませられます。

- **登録:** Claude デスクトップを終了してから（タスクトレイのアイコンからも）、［設定］→［要約］の「Claude との連携（MCP）」で［Claude デスクトップに登録］を押し、Claude デスクトップを起動します。Microsoft Store 版の Claude デスクトップも同じボタンで登録できます。外すときは［登録を外す］です。Claude デスクトップが動いている間は、NaTsu は登録を変えません（終了してから押してください）。
- **登録が消えたとき:** Claude デスクトップが設定を書き直して登録が消えることがあります。NaTsu は起動のときに確かめ、Claude デスクトップが終了していれば、自動で登録し直します。動いていれば知らせるので、Claude デスクトップを終了してから［登録し直す］を押してください。NaTsu を別の場所に入れ直したときも同じです。
- **送られるもの:** Claude に頼むと、Claude が読んだ議事録の題名・要約・メモ・文字起こしは Claude（Anthropic）へ送られます。［オフラインモード］で録った会議も、ほかの会議と同じに読めて、送られます。1on1・面談の議事録を扱う前に、Claude の設定のプライバシーで、会話をモデルの学習に使わない設定にしてください。1on1・採用面接・事前面談の議事録は、頼んだとき（会議の種類や会議を指したとき）だけ探します。
- **読むだけ:** Claude は議事録を読むだけで、書き換えません。NaTsu が閉じていても読めます。NaTsu はポートを開きません。Claude デスクトップが起こした NaTsu の読み手と、標準入出力だけで話します。
- **消したとき:** 議事録を消しても、Claude が一度読んだ内容は Claude の会話に残ります。Claude の側の会話も消してください。
- **入れ直し・アンインストールの前に、Claude デスクトップを終了してください**（タスクトレイのアイコンからも）。Claude デスクトップが NaTsu を動かしたままだと、インストーラーが「NaTsu が起動しています」「NaTsu が終了できません」と止まります。
- **つながらないとき:** ［設定］→［要約］の「Claude との連携（MCP）」の状態の文を見ます。Claude デスクトップの記録 `%APPDATA%\Claude\logs\mcp-server-natsu.log`（Microsoft Store 版は `%LOCALAPPDATA%\Claude-Data\claude_…\logs\mcp-server-natsu.log`）も見ます（NaTsu はここに議事録の文を書きません）。

詳しくはヘルプの記事「Claude から議事録を読む（MCP）」（`start/claude-mcp`）を見てください。

## 管理者の手順

中継（`relay/`）を出し、会社の鍵を入れ、ログインの決まりを決め、人を止めるのは管理者の仕事です。ブラウザと Cloudflare・GitHub・OpenAI の画面だけで行います（PowerShell は使いません）。

会社の回線からは、Cloudflare の画面での書き込み（Worker の秘密の欄の追加・変更、Access の決まりの変更など）ができません（会社の通信の検査が止めます）。管理の操作は、会社の外の回線（自宅の回線・スマートフォンのテザリングなど）で行ってください。見るだけの操作と、GitHub の［Run workflow］は会社の回線でもできます。

鍵やトークンは、メモ帳・チャット・メールに貼らず、作った画面からそのまま次の画面へ貼ってください。
ここでは、会社のメールの `@` より後ろを `<会社のドメイン>`、Cloudflare の Zero Trust のチームの名前を `<チームの名前>` と書きます。どちらもリポジトリ・アプリ・中継のコードには書きません（Cloudflare の設定と Worker の秘密の欄にだけ置きます）。

### 用意（初めの1回）

**中継を出す**

1. **Cloudflare のアカウントを作る:** https://dash.cloudflare.com で会社のメールアドレスで登録し、会社のカードを登録します（最初は無料のままでかまいません）。
2. **workers.dev の名前を決め、会社の PC で開く:** 左の［Workers & Pages］→［作成］→ 見本の「Hello World」を選びます。初めてなら workers.dev の「サブドメイン」を決める画面が出ます。**会社名や人の名前を含まない名前**にしてください（アプリとリポジトリに書くため）。Worker の名前は `natsu-relay` にして［デプロイ］。出た住所を会社の PC の Edge で開き、「Hello World!」が出るかを見ます。
3. **API トークンを作る:** 右上の人の印 →［My Profile］→［API Tokens］→［Create Token］→［Custom token］の［Get started］。名前は「natsu-relay-deploy」。権限は2行だけ: 「Account」「Workers Scripts」「Edit」と、「Account」「D1」「Edit」。「Account Resources」は「Include」「このアカウント」だけ。［Continue to summary］→［Create Token］で出たトークンをコピーし、そのまま 4 へ進みます（この画面でしか見られません）。
4. **GitHub の Environments に入れる:** リポジトリの［Settings］→ 左の［Environments］→ `relay`（無ければ［New environment］で `relay` を作る）。
   - 「Deployment branches and tags」を「Selected branches and tags」にし、`main` だけを足します（main のほかからは秘密が使えなくなります）。
   - 「Environment secrets」の［Add environment secret］で、`CLOUDFLARE_API_TOKEN` に 3 のトークンを、`CLOUDFLARE_ACCOUNT_ID` に Cloudflare の［Workers & Pages］の右側にある「Account ID」を貼ります。
   - リポジトリの［Secrets and variables］→［Actions］の「Repository secrets」には入れません（ほかの枝からも読めるため）。
5. **OpenAI の使いすぎの守り:** 会社の OpenAI の画面で、月の使いすぎの知らせや上限を決められるなら決めておきます（中継の1日の上限とは別に効きます）。

**ログイン（Cloudflare Access）を用意する**

6. **チームのドメインを確かめる:** ［Zero Trust］を開き、チーム（組織）があることを見ます。ブラウザで `https://<チームの名前>.cloudflareaccess.com/cdn-cgi/access/certs` を開くと、RS256 の鍵が並んだ JSON（`"keys": [...]`）が出ます。この `https://<チームの名前>.cloudflareaccess.com` が 12 の `TEAM_DOMAIN` になります。
   - プランは「Zero Trust Free」（席 50・月 0 ドル）で足ります。席は、NaTsu に初めてログインした人が1つずつ使います。
   - 組織は消さないでください（消すとチームの名前は二度と使えません）。「Protect all Workers」（アカウントの全部の Worker を守る）は使わず、`natsu-relay` だけを 8 で守ります。
7. **One-time PIN を足す:** ［Zero Trust］→［Integrations］→［Identity providers］。「Your identity providers」に One-time PIN がもう並んでいれば何もしません。無ければ［Add new identity provider］→［One-time PIN］→ 保存。
8. **natsu-relay を Worker 単位の Access で守る:** ［Workers & Pages］→ `natsu-relay` →［Access］のタブ →［Protect this Worker behind Access］→「All traffic」を選ぶ →「Authentication policy」は「Email domain」にして `<会社のドメイン>` を入れる →［Apply Access］。
   - この後は、ブラウザで中継の住所を開くとログインの画面が出ます。出し方（relay-deploy）の `/health` の確かめは、11 のサービストークンを入れるまで「Access に止められた」で止まります。
9. **決まりとログインの長さを直す:** ［Zero Trust］→［Access controls］→［Applications］→ `natsu-relay` の app の［Configure］。
   - 「Policies」で 8 で作った決まりを開き、Include が「Emails ending in」`@<会社のドメイン>` だけであることを見ます（ほかの Include、たとえば「Cloudflare account」や「Everyone」があれば消す）。
   - 同じ決まりに［Add require］で「Login Methods」→「One-time PIN」を足します。
   - 同じ決まりの「Session duration」が「Same as application session timeout」であることを見ます（違う長さなら、それにする。決まりの長さは app の長さより先に効くので、24 時間のままだと毎日ログインし直しになります）→［Save］。
   - 「Overview」の「Session Duration」を 7 日（1 週間）にします（週に1回ログインし直す）。
   - 「Cookie settings」は既定のまま（Binding Cookie を有効にしない・HttpOnly は有効のまま・Cookie Path Attribute を有効にしない）。
   - 「Additional settings」の「Application Audience (AUD) Tag」（64 字）は、12 で `POLICY_AUD` を入れるときに、この画面をもう一度開いてコピーします（秘密ではなく、いつでも見られます）。
   - アカウントに Access で守るほかの app が無ければ、全体のログインの長さ（［Access controls］→［Access settings］の「global session duration」）も 7 日（1 週間）にします。ほかの app があるときは変えません。
10. **ログインの画面の見た目:** ［Zero Trust］→［Reusable components］→［Custom pages］→「Access login page」の［Manage］。
    - 組織の名前（Your Organization's name）: `NaTsu`
    - 頭の文（header）: `NaTsu（議事録アプリ）のログイン ─ 会社のメールアドレスを入れて［Send login code］を押してください`
    - 足の文（footer）: `メールで届く 6 けたのコードを入れて［Sign in］を押します。コードは 10 分で切れます。届かないときは迷惑メールのフォルダを見てください`
    - ［Save］。画面の英語そのものとコードのメールは変えられません（英語のまま）。この見た目はアカウントの全部の Access の app に効きます（ほかの app があるときは、頭の文を「NaTsu などのログイン」のように広くします）。
    - 会社の PC の Edge の InPrivate の窓で中継の住所の後ろに `/health` を付けて開き、英語のログインの画面 → コードのメール → 中継の答え、まで通るかを見ます。会社のものでないメールアドレスでは、画面は「A code has been emailed to you」と出ますが、メールは届きません（決まりのとおり）。
11. **サービストークンを作り、GitHub に入れる:** ［Zero Trust］→［Access controls］→［Service credentials］→［Service Tokens］→［Create Service Token］→ 名前 `natsu-relay-deploy` → 期限（Service Token Duration）は「1 year」→［Generate token］。
    - 出た Client ID と Client Secret を、そのまま GitHub のリポジトリの［Settings］→［Environments］→ `relay` →［Add environment secret］で、名前 `CF_ACCESS_CLIENT_ID` と `CF_ACCESS_CLIENT_SECRET` に貼ります（Client Secret はこの画面でしか見られません。2つの画面を並べて、片方からもう片方へ直に貼る）。リポジトリの秘密（Repository secrets）には入れません。
    - ［Access controls］→［Applications］→ `natsu-relay` の［Configure］→「Policies」→［Add a policy］→ Action を「Service Auth」、Include を「Service Token」→ `natsu-relay-deploy` →［Save］。
    - ［Access controls］→［Access settings］の「Manage service tokens」に「Strict service token authentication」があり、無効なら有効にします（サービストークンの要求は Service Auth の決まりだけで通り、失敗は 302 でなく 401／403 になります）。
12. **Worker の秘密を入れる:** ［Workers & Pages］→ `natsu-relay` →［Settings］→［Variables and Secrets］→［Add］。どれも種類は「Secret」にします（「Text」にすると次の出し直しで消えます）。鍵はその場で作って、そのまま貼ります。
    - `OPENAI_API_KEY` … 会社の OpenAI の画面で文字起こし用の鍵を作ってコピーし、貼る
    - `ALLOWED_EMAIL_DOMAINS` … `<会社のドメイン>`（会社のメールの `@` より後ろ。2つ以上なら `,` で区切る。Access の決まりとは別の、中継の2つ目の照らし）
    - `TEAM_DOMAIN` … 6 で確かめた `https://<チームの名前>.cloudflareaccess.com`（終わりに `/` と `/cdn-cgi/…` を付けない）
    - `POLICY_AUD` … 9 の画面をもう一度開いてコピーした AUD のタグ（64 字）
    - ［Deploy］を押します。
13. **中継を出す:** GitHub の［Actions］→ 左の［relay-deploy］→［Run workflow］（枝は main）→ 緑になるのを待ちます。最後の行が「ready: db はい・openai はい・access はい・domains はい」なら済んでいます。赤になったら、最後の行の文を写して作り手に送ってください（トークンは記録に出ません）。もう一度［Run workflow］を押しても緑のままです（秘密も Access も消えません）。
14. **コードのメールの送り元を許してもらう（配る前に）:** 情報システムに「`noreply＠notify.cloudflare.com`（＠ は半角の @ にして伝えてください）からのメールを止めない・メールの中の印を先に開かない（メールの検査の除外）」を頼みます。会社の PC でコードが「already been used」になったときは必ず頼みます。

### 取り消しと止め方

- **ある人を今すぐログアウトさせる:** ［Zero Trust］→［Team & Resources］→［Users］→ その人に印 →［Action］→［Revoke］。［Revoke］だけでは、その人はまたログインできます（止めるには次の「使えなくする」）。取り消された人の PC は、次の区間（または音声入力）で「ログインが切れたため…」と［ログインし直す］を出し、PC の中で文字起こしを続けます。
- **ある人を使えなくする:** 9 の決まりに［Add exclude］で「Emails」→ その人のメールを足して［Save］し、続けて上の［Revoke］をします。**中継の止めたメールにも必ず入れます**（Access の Exclude はメールちょうどしか見ないため）:
  1. Cloudflare の画面で［Storage & Databases］→［D1］→ `natsu-relay` →［Console］を開く。
  2. `INSERT INTO blocked_emails (email, at) VALUES ('<メール（小文字）>', CAST(strftime('%s','now') AS INTEGER));` を入れて［Execute］。中継はそのメールを 403 で断ります。
  3. 戻すときは Exclude を消し、`DELETE FROM blocked_emails WHERE email = '<メール>';` を［Execute］。
  - `'<…>'` の所は、引用符を残して、中をその人のメールアドレス（小文字）に替えて入れてください。
  - `+` の付いた別名（`名前+何か@<会社のドメイン>`）は、中継がいつも断ります（Exclude と止めたメールをすり抜けられないため）。
  - いちばん確かなのは、会社のメールのアカウントが止まることです（コードが届かなくなります）。
- **辞めた人の席を空ける（Free は 50 人まで）:** 同じ［Users］で［Action］→［Remove users］→［Remove］。
- **全員を一度ログアウトさせる:** ［Applications］→ `natsu-relay` の［Configure］→［Revoke existing tokens］。
- **Worker 単位の Access は外さない:** 外すと、取り消した人のログインも期限（7 日）まで中継で通ります（中継の止めたメールだけが残る守りになります）。外して止まるのは新しいログインだけで、もう出たログインは期限まで中継で通ります（外すことは止め方になりません）。

### 鍵とトークンが漏れたかもしれないとき

鍵とトークンの差し替えは Cloudflare の画面での書き込みなので、会社の外の回線（自宅の回線・スマートフォンのテザリングなど）で行ってください。

1. 会社の鍵: OpenAI の画面で鍵を消して新しい鍵を作り、Cloudflare の［Workers & Pages］→ `natsu-relay` →［Settings］→［Variables and Secrets］の `OPENAI_API_KEY` を新しい鍵に替えて［Deploy］。
2. Cloudflare のトークン（このトークンで中継のコードを替えられ、会社の鍵を読み出せる）: Cloudflare の［My Profile］→［API Tokens］でそのトークンを［Delete］し、1 と同じく会社の鍵も替える。新しいトークンを作って GitHub の Environments → relay の `CLOUDFLARE_API_TOKEN` を替える。
3. サービストークン: ［Service Tokens］でそのトークンの［Rotate secret］（前の Secret をすぐ使えなくする）か削除をし、新しい Secret を GitHub の Environments → relay の `CF_ACCESS_CLIENT_SECRET` に入れ直す（削除したときは 11 の手順で作り直し、`CF_ACCESS_CLIENT_ID` も替える）。

### サービストークンの期限

- 11 のサービストークンは 1 年で切れます。切れると relay-deploy が「Access に止められた」で止まります（アプリの文字起こしには関係しません）。
- 1 年たつ前に、［Zero Trust］→［Access controls］→［Service credentials］→［Service Tokens］のトークンの［Refresh］で 1 年延ばします（Client ID と Secret は変わらないので、GitHub は直さなくてかまいません）。

### コードのメールが届かないとき

- まず迷惑メールのフォルダを見てもらい、コードは 10 分で切れ、頼み直すと前のコードは使えないことを伝えます。
- 会社のメールの検査で止まる・「already been used」になるときは、14 のとおり情報システムに `noreply＠notify.cloudflare.com`（＠ は半角）を許してもらいます。
- それでも届かないときは、9 の決まりの Include が `@<会社のドメイン>` か、その人を Exclude に入れていないかを見ます。

## ヘルプセンター

NaTsu の使い方の記事を集めた、ログインの要るサイトです（`https://natsu-help.natsu-code.workers.dev/`）。会社のメールアドレスでログインした人だけが読めます（中継と同じ Cloudflare Access の One-time PIN）。アプリにも自動更新の zip にも入りません。

- **記事の元:** `help/articles/<分類>/<名前>.md`。分類と並びは `help/site.json`、見た目（白黒・同梱の Noto Sans JP と Noto Sans Mono の書体。リンクと輪はデジタル庁デザインシステムに寄せた: `DADS-PROTECT.md`）は `help/assets/`。リポジトリは公開なので、記事の元は誰でも読めます。会社の固有の情報（人・社名・会社のドメイン・チームの名前）は記事に書きません。
- **書き方:** 実装計画 `docs/plans/2026-10-20-help.md` の「記事の書き方」。記事の ［…］ は NaTsu の画面の言葉だけで、どれもアプリのコードにちょうどその文字があることを `npm test` が確かめます（ほかの画面のボタンは太字）。
- **作り方:** `npm run help:build` で `help/dist` にサイトができます（git には入りません）。
- **見た目を変えたら:** `node tools/help-shots.js` で写真を撮り直します（作業環境の Playwright と Chromium の場所を `HELP_SHOTS_PLAYWRIGHT`・`HELP_SHOTS_CHROMIUM` で渡す）。ホーム・分類・記事・試験利用の手順・リリースノートを明るい版だけで幅 1280・390 で撮り、全部を目で見てから `help/shots.json` を commit します（CSS を変えたのに撮り直していなければ `npm test` が赤になります）。
- **出し方:** GitHub の［Actions］→［help-deploy］→［Run workflow］（main だけ・環境 `relay`）。main に `help/` などの変更が入ったときも自動で出します。最後に、ログインしていない要求で中身が返らないことを確かめ、返れば赤で止まります。

### 初めて出すとき（利用者の用意）

中継の用意（Cloudflare のアカウント・Zero Trust のチーム・One-time PIN・API トークン・GitHub の環境 `relay`）が済んでいれば、新しいトークンも環境も要りません。会社のドメイン・チームの名前・AUD は Cloudflare の画面にだけ入れます。

0. **1回目を出す:** ［Run workflow］→ 緑で、最後の行が「準備中（Access の app と秘密の欄がまだ。利用者の用意の 1〜5）」。サイトを開くと「NaTsu ヘルプセンターは準備中です。…」だけが出ます（記事は見えません）。
1. **natsu-help を Access で守る:** ［Workers & Pages］→ `natsu-help` →［Access］のタブ → **Protect this Worker behind Access** →「All traffic」→「Authentication policy」は「Email domain」で `<会社のドメイン>` →［Apply Access］。
2. **決まりを中継と同じ形にする:** ［Zero Trust］→［Access controls］→［Applications］→ `natsu-help` の［Configure］。「Policies」の決まりの Include が「Emails ending in」`@<会社のドメイン>` だけであることを見て、［Add require］で「Login Methods」→「One-time PIN」を足す。「Session duration」は「Same as application session timeout」→［Save］。
3. **ログインの長さ:** 同じ app の「Overview」の「Session Duration」を「1 week」（7 日。中継の app も 7 日）。
4. **AUD を見る:** 同じ app の「Additional settings」の「Application Audience (AUD) Tag」。中継（`natsu-relay`）の AUD とは違います。
5. **Worker の秘密を入れる:** ［Workers & Pages］→ `natsu-help` →［Settings］→［Variables and Secrets］。種類はどれも「Secret」（「Text」にすると次の出し直しで消えます）。`TEAM_DOMAIN`（中継と同じ `https://<チームの名前>.cloudflareaccess.com`）・`POLICY_AUD`（4 の natsu-help の AUD）・`ALLOWED_EMAIL_DOMAINS`（中継と同じ）→［Deploy］。
6. **2回目を出す:** ［Run workflow］→ 緑で「Access に守られています」。会社の PC の InPrivate の窓でサイトを開き、ログインの画面が出ること・ログインすると読めること・ログインせずに `…/search-index.json` を開くとログインの画面になることを確かめます。
7. **覚えておくこと:** 人を止める手順は「取り消しと止め方」と同じです。Exclude は app ごとなので、**natsu-relay と natsu-help の両方の決まり**に足します（中継の止めたメールはヘルプにも効きます）。Worker の Access は外しません。

## セットアップ

ソースから動かすには **Node.js 22.12 以上**が要ります（Electron 44 の包みが求める版。https://nodejs.org/ja の LTS 版で足ります）。

社内プロキシ環境では最初に一度: `setx NODE_USE_SYSTEM_CA 1` → PowerShellを開き直す
（Windows の証明書ストアを Node.js に使わせる設定。`NODE_USE_SYSTEM_CA` は Node.js 22.19 以上で効きます）。
プロキシを手で設定している会社では、本体の取り込みに `setx ELECTRON_GET_USE_PROXY true` と
`setx HTTPS_PROXY http://<プロキシ>:<ポート>` も要ります（Electron の包みの取り込み役 `@electron/get` が見る値）。

```powershell
cd <NaTsuを置いたフォルダ>
npm install
node node_modules/electron/install.js
npm start
```

Electron 42 から、`npm install` だけでは Electron の本体（`electron.exe`、150MB ほど）が落ちてきません。
`node node_modules/electron/install.js` が本体を取り込みます（本体があれば何もしません）。
`start-natsu.bat` と `create-shortcut.ps1` は、本体が無いときに `tools/get-electron.js` で同じことをします
（`npx install-electron` は使いません。古い Electron の包みにはこの名前が無く、npm に同じ名前の別の包みがあるため）。

### エンジン（文字起こし）

取り込みは任意です（取り込まなくても、ログインしてつながっていれば会議と音声入力が使えます）。ローカル AI を使うときは、
NaTsu を起動し、［設定］→［ローカル AI］の［ローカル AI を使う（約 0.6GB を取り込む）］（一度押した後は［PC の中の文字起こしを取り込む］）を押すと、文字起こし（whisper.cpp・
large-v3-turbo・VAD のモデル）のエンジンを取り込みます（約 0.6GB）。要約は Claude Code で作るので、要約用の AI は PC に置きません（0.10.0 から。
0.9.x で取り込んだ要約用の AI（約 5GB）は、0.10.0 で初めて起動したときに、アプリが取り込んだものだけを消して1回知らせます）。
置き場所は `%LOCALAPPDATA%\natsu\engine`。版・取得元・SHA-256 はアプリの中（`src/engine-manifest.js`）に
固定してあり、途中で切れても続きから取ります。記録中は止まります。

#### 手で入れる（詳しい人向け）

```powershell
powershell -ExecutionPolicy Bypass -File .\setup-local-engine.ps1
```
表示されたパスを [設定] → [ローカル AI] → [詳細設定] に貼り付け → ［PC の中で試す］（手で入れたパスが優先されます）。
（setup-local-engine.ps1 の `-Model kotoba` で日本語特化の kotoba-whisper も選べますが、NaTsu の 75 秒ずつの文字起こしでは
文の抜け落ちが多く、誤りが large-v3-turbo の約 3 倍でした。速さはほぼ同じです。）
エンジンの Visual C++ ランタイム（14.51 以上）は https://aka.ms/vc14/vc_redist.x64.exe（管理者の権限が要ります）。

※ PC の中の文字起こしのエンジンは、インターネットにつながっていないときと、［オフラインモード］の会議で使います。取り込みにはネット接続が要ります。

## データ保存先

`%APPDATA%\natsu\`
```
settings.json          設定
history.json           音声入力の履歴
update.log             更新の記録（更新確認が失敗した理由もここに残る）
data/                  議事録の保存先
  natsu.db             議事録・要約・文字起こし・メモ（0.7.0 から。この1つのファイルが正本）
  natsu.db-wal         natsu.db の書きかけの分（natsu.db と組で使う。片方だけを消したり写したりしない）
  backup/              natsu.db の確かめた控え（natsu-<時刻>-daily.db.gz など）
  index.json           0.6.0 までの議事録の一覧（元の JSON。0.7.0 は読むだけで書かない）
  pages/<id>.json      0.6.0 までのページ本体（元の JSON）
  transcripts/<id>.json 0.6.0 までの文字起こし（元の JSON）
  draft.json           記録中の議事録（議事録が保存できたら消える）
  segbuf/              記録中の音声の退避（文字起こしが終わり次第消える）
```
設定画面の「データ保存先を開く」からエクスプローラーで開けます。
バックアップはこのフォルダをコピーするだけです（NaTsu を終了してから写してください。動いている間は `natsu.db` と `natsu.db-wal` が組で変わります）。

### 議事録の保存の形（0.7.0 から）

- **natsu.db:** 0.7.0 から、議事録は `%APPDATA%\natsu\data\natsu.db`（SQLite の1つのファイル）に保存します。初めて 0.7.0 を起動したときに、移す議事録の数を窓で見せてから、元の JSON（`pages\`・`transcripts\`・`index.json`）を読んで移します。［今は移さずに終える］も選べます（次の起動でまた聞きます）。
- **元の JSON は残します:** 移した後も、元の JSON は消さず、名前も中身も変えません。1.x の間は NaTsu が自動で消すことはありません。壊れていて移せなかったファイルも、元の場所にそのまま残ります（数は起動のときに知らせます）。
- **控え（data\backup）:** 手が空いているときに1日1回、確かめた控えを `%APPDATA%\natsu\data\backup` に取ります。毎日の控え（`…-daily.db.gz`）は新しい3つ、毎週の控え（`…-weekly.db.gz`）は新しい1つを残し、移した直後の控え（`…-migration.db.gz`）は消しません。`natsu.db` が壊れていたときは、消さずに `natsu.db.broken-<時刻>` へ退けて、確かめ済みの最新の控えから戻し、抜けたかもしれない期間を知らせます。
- **控えに残る期間:** 議事録を［削除］すると一覧から消えますが、中身は `natsu.db` に残ります（ゴミ箱の画面は後の版で足します）。録音中に取り消した会議の文字は `natsu.db` に残しません。ただし控えに入っていた場合は、控えが回って消えるまで、毎日の控えで最長 3 日ほど・毎週の控えで最長 2 週ほど残ります。
- **古い版に戻したとき:** 0.6.0 などの古い版を入れ直すと、古い版は元の JSON を読むので、移した後に録った会議と直しは見えません（`natsu.db` は消さずに残ります）。もう一度 0.7.0 以降にすると、古い版で録った会議と直したページも起動のときに取り込みます（両方で直したページは「（古い版で直したもの）」を題名に付けた別のページになり、どちらも消しません）。
- **保存の仕組みを止めるには:** 保存は「NaTsu DB」という別のプロセスが受け持ちます（タスク マネージャーでは NaTsu の下に「NaTsu DB」として出ます。番号（PID）は `%APPDATA%\natsu\engine.log` の「DB: 起動（番号 …）」の行にあります）。タスク マネージャーで終了しても録音は止まらず、下書きと音声の控えに残り続けます。NaTsu が少し後に起こし直し、10 分に 5 回止まると諦めて知らせます（その間の会議は、次に起動したときに議事録になります）。

窓の大きさと位置・拡大・サイドバー・開いていたタブの覚え書きだけは `%LOCALAPPDATA%\natsu\window-state.json`（Local。プロファイル同期で別の PC へ運ばれない）に置きます。

議事録は `%APPDATA%\natsu`（Roaming）に保存されるため、社内のプロファイル同期で複製されることがあります。

### 困ったとき（保存のファイルの知らせ）

0.4.0 から、保存のファイルが壊れていたり読めなかったりしたときは、画面の左下に知らせが出ます（起動のときに複数あれば1回にまとめて出ます）。
どれも `%APPDATA%\natsu\engine.log` にも1行残ります（キーの名前・理由・ファイルの名前だけで、設定の値や議事録の中身は書きません）。

- **「設定の一部（…）が読めない値だったので、その部分だけ既定に戻しました」**: 書かれた項目だけが既定に戻り、ほかの設定はそのままです。元のファイルは `settings.json.broken-<日時>` として残っています。直した設定はすぐ保存するので、次の起動ではもう出ません。
- **「設定のファイルが壊れていたので、既定の設定で起動しました」**: `settings.json` が JSON として読めませんでした。壊れたファイルは `settings.json.broken-<日時>` として残っています。中身を見て、必要な値を設定の画面で入れ直してください。
- **「設定のファイルの文字の形式（Shift-JIS など）を読めなかったので…」**: メモ帳で開き、「名前を付けて保存」で文字コードを「UTF-8」にして保存し直すと読めます。
- **「設定のファイルをほかのプログラムが使っていて読めませんでした」**: ウイルス対策などが一瞬ファイルを使っていたときに出ます。読めるまでは既定の設定で動き、保存はしません（今の設定を既定で上書きしないため）。少し後と、設定の画面を開いたときに読み直し、読めれば「保存してある設定に切り替えました」と出ます。
- **「設定のファイルが読み取り専用になっているため…」**: 管理者が決めた設定として使います。画面で変えた設定は保存されません。

**`.broken-<日時>` のファイルの扱い:** NaTsu は壊れたファイルを消さずに、同じフォルダに `<元の名前>.broken-<日時>` の名前で残します。中身を確かめて要らなければ消してかまいません（議事録のページ・設定・履歴の控えは、NaTsu が自分では消しません。索引やエンジンの取り込みの記録のような作り直せるファイルの控えだけは、新しい3つを残して古いものを片付けます）。

**試し用の環境変数 `NATSU_TEST_BATCH_MS`:** 録音バーの位置は少しまとめてから保存します（ふだんは 0.35 秒）。シャットダウンの直前の変更が残るかを実機で確かめるときだけ、ユーザーの環境変数 `NATSU_TEST_BATCH_MS` を `60000` にすると、まとめる間隔が 60 秒になります（使ったことは engine.log に残ります）。確かめが終わったら、この環境変数は消してください。

https://github.com/Kishi-Satoshi/natsu/releases/latest

## 更新の配布（アプリ内アップデート）

配布するのは `src/` と `package.json` だけを固めた軽量zip（数百KB）です。
インストーラー丸ごと（120MB ほど）だと、大容量ダウンロードが切れる回線で
更新のたびに失敗しかねないためです。

### リリース手順

1. `package.json` の `version` を上げる
2. `CHANGELOG.md` に `## natsu-v0.1.0 （2026-10-17）` の節（版の後ろに半角の空白、全角の括弧の中に公開する日。空白が無いとリリース本文が取れません）を足して変更点を書く
3. コミットしてタグを push する

```bash
git tag -a natsu-v0.1.0 -m "リリース"
git push origin natsu-v0.1.0
```

`.github/workflows/release.yml` がテストを回し、zipを作り、Releaseを公開します。
その commit で Linux と Windows の CI（`.github/workflows/ci.yml`）が両方緑のときだけ出ます。
`CHANGELOG.md` の該当節がそのままリリース本文になり、アプリの
[設定] → [更新] に表示されます。
タグは `natsu-v<版>` の形にします（古い `v<版>` のタグでは動きません）。
形が違うときと、`natsu-v` を外した版が `package.json` のバージョンと食い違うときは、ワークフローが止まります。

Release はまず **draft** として作られ（zip と ps1 を添付）、Windows ランナーで
`NaTsu-<版>-setup.exe` を添付できてから公開（latest）になります。
exe の添付に失敗すると draft のまま残り、Actions の要約に赤い見出し
「公開されていません（draft のまま）」が出ます。draft の間は `releases/latest` に
出ないので、各PCの更新確認には前の版が出続けます（新しい版が見えないだけで、壊れはしません）。
そのときはワークフローを再実行するか、Releases ページで draft を確かめてください。

タグを push できない環境（プロキシが `refs/tags` を拒否する等）では、
Actions 画面の **Run workflow**、または `release/natsu-v0.1.0` という名前の
ブランチを push しても同じ結果になります（そのブランチは公開後に自動で消えます）。

各PCの NaTsu が起動時、または [設定] → [更新] → [更新を確認] で検出します。

手元でzipだけ作りたい場合（Releaseは手動で作る）:

```powershell
powershell -ExecutionPolicy Bypass -File .\make-release.ps1 -Version 0.1.0
```

適用前に現行の `src/` を `src.backup-*` として退避するので、
展開に失敗しても起動できなくなることはありません（1世代だけ残します）。

更新 zip では exe（Electron 本体）は入れ替わりません。zip の `package.json` の
`engines.electron`（例: `>=44.9.0`）を `src/` を差し替える**前に**確かめ、今の Electron が
満たさなければ「この版はアプリの土台を入れ替えるため、インストーラーで入れ直してください。
議事録・設定・エンジンはそのまま残ります。」で止め（何も書き換えません）、ボタンを［ダウンロード］に替えます。
0.2.x 以前の版は、前の文（「更新 x.y.z には Electron >=… が必要です（今は …）。インストーラーで入れ直してください」）のまま止まります。
Electron を上げる版を出すときは `devDependencies.electron` と `engines.electron` を一緒に上げ、
インストーラーで入れ直してもらう前提で案内してください。

### 入れ直しが要る版の知らせ（0.3.0 から）

- リリースには `natsu-update.json`（版・必要な土台の版〔`engines.electron` の写し〕・zip の SHA-256 と大きさ）が添えられます。
  アプリは［更新を確認］の時点でこれを読み、今の Electron が範囲を満たさない版なら、［設定］→［更新］・
  起動時の知らせ・トレイの［更新を確認］の3か所で、上の「入れ直してください」の文と［ダウンロード］を出します
  （［更新して再起動］は出しません）。［ダウンロード］でリリースのページが開きます。
  当てるときは、落とした zip を `natsu-update.json` の SHA-256 で照らします。
- **公開する前の確かめ:** Actions の［Run workflow］で `publish` を外すと、exe を添付した下書きのまま止まります。
  下書きの `natsu-update.json` を落として置き、`setx NATSU_UPDATE_FEED "%LOCALAPPDATA%\natsu-test\natsu-update.json"`
  （置いた場所）を実行して NaTsu を起動し直すと、その版の知らせが出ます（テスト用の取得先では当てはしません）。
  `NATSU_UPDATE_FEED` には `owner/repo` の形（テスト用のリポジトリの公開したリリース）も入れられます。
  確かめたら［システムのプロパティ］→［環境変数］で `NATSU_UPDATE_FEED` を消して起動し直します
  （`setx` に空の値を渡しても消えないことがあるため。消えたかは新しい窓で `echo %NATSU_UPDATE_FEED%` を見る）。
- 下書きを作った後に commit を足したら、下書きを `gh release delete <タグ> -y` で消してから出し直してください。
  別の commit を指す下書きが残っていると、`release` ジョブが赤で止まります（exe が作り直されず、古い commit にタグが付くのを防ぐため）。

## デグレを止める仕組み

実機でしか見つからない不具合を5件続けて出したため、機械で止める層を入れています。
`npm test` に組み込まれているので、意識せずに毎回走ります。

### 3つの層

| 層 | 何をするか |
|---|---|
| **不変条件**（`test/invariants.js`） | 「この製品では常にこうでなければならない」を26件、表として持つ。HTMLの木・色の対比・透過ウィンドウの禁止事項・復旧の導線・配布物の形式をまとめて検査する |
| **起動ハーネス**（`test/helpers/`） | 画面のスクリプトを素のNodeで実際に実行し、初期化が例外なく完走することを確かめる。存在しない要素への代入は、ここで落ちる |
| **変更危険度ゲート**（`tools/risk.js`） | 前の版と比べ「新たに壊れたもの」だけを報告する。既存の例外に対して誤検知が出ない |

### HTMLの構造を変えるときは必ず `hedit` を使う

**HTMLをテキストで切り貼りしてはいけません。** 過去のデグレ5件のうち3件が、
文字位置で切り出した際の境界ミスです（閉じタグの道連れ、末尾の切り落とし）。

```bash
node tools/hedit.js list  src/renderer/app.html '.card'
node tools/hedit.js order src/renderer/app.html --in '#tabSettings .scroll' --match '.card' --by-h2 "A,B,C"
node tools/hedit.js move  src/renderer/app.html --node '#x' --after '#y'
```

木として動かし、書き出す前に自己検査します。
要素が1つでも消える・増える・枠から出る編集は、**書き込み自体を拒否します**。

### コミット時に自動で止める

```bash
npm run hook     # pre-commit フックを据える（クローン直後に1回）
                 # フックはゲートの後に npm test も走らせる（約15秒。急ぐときは NATSU_SKIP_TESTS=1）
```

危険な変更があると commit が止まります。意図的な場合だけ、理由を残して越えられます。

```bash
NATSU_GATE_OVERRIDE='理由' git commit -m "..."
```

### 実機で1件踏んだら、台帳に1行足す

`tools/lib/mines.js` は、実機で踏んだ地雷の台帳です。
1行足すだけで、全ウィンドウ・全HTMLに一斉に効きます。
個別のテストを後追いで書くより、こちらを育ててください。

### それでも実機でしか分からないもの

- 実際の見た目（色の好み、余白、文字の詰まり）
- Windows 固有の挙動で、台帳にまだ無いもの
- 音声デバイス・ループバック・プロキシなど、環境に依存するもの

リリース時に `npm run checklist` が、変更内容から**実機で見るべき項目だけ**を生成します。

## テスト

```powershell
npm test
```

要約パイプライン（Markdown→ブロック→出典→担当・期限）、出典マッチング、
日付の正規化、アプリ内アップデート、IPCの整合、公開前チェック（個人情報の混入、

## 実装について

オリジナル実装です。Notion・Typeless 等のコードやデザイン資産は含みません。
文字起こしの whisper.cpp（MIT）をローカル実行しています（要約は各自の Claude Code）。
追加のnpm依存はなく、electron と electron-builder のみで動作します。
