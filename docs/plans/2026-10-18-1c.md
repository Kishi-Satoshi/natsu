**目的:** オンラインのときは、
1. **文字起こしをクラウドで行う**（OpenAI と同じ形の口を1つ作り、送り先は「Groq（無料枠）」（既定）・「OpenAI」・「そのほか」から選ぶ）。75 秒の区切りの WAV を1つずつ送り、言語は ja、認識ヒントは今と同じ辞書と直前の発言。鍵は `safeStorage` でしまう。
2. **要約を利用者の Claude Code で行う**（`claude -p`、文字起こしは標準入力、`--output-format json`）。各自の Claude のプランの中で動き、API キーの従量課金で動く設定なら呼ばない。上限・ログイン切れは平易な言葉と［要約を生成］のやり直しで知らせる。
3. **どちらで処理したかを決めて、ページに出す**（文字起こしは区間ごと、要約は1回ごと）。

オフラインのときは今までどおり手元の whisper と llama。録音・下書き・音声の控え（`segbuf/`）・出典の照合（`src/cite.js`）・要約タイプの指示書・ブロックの形は変えない。音声が PC の外へ出るのは、利用者が設定で同意したときだけ。

**Claude Code の資料で確かめたこと（2026-10-18 に読んだ）**
- `-p` は標準入力を読む。**標準入力は 10MB まで**で、越えると分かるエラーと 0 でない終わりの番号で止まる。`--output-format json` は `result`（文）・`session_id`・`total_cost_usd` などを持つ1つの JSON を出す。成功は終わりの番号 0、失敗は 0 でない。**引数の誤りは始まる前に stderr へ、走っている間の失敗（ログインが無いなど）は stdout の結果として出る**（`https://code.claude.com/docs/en/headless`）。
- `--bare` は「OAuth の資格情報やキーチェーンを読まない」ので、`ANTHROPIC_API_KEY` か `apiKeyHelper` が要る（同じページ）。→ この回では使わない。
- `--bare` を付けない `-p` は、「対話のときと同じく、作業フォルダと `~/.claude` にあるフック・スキル・独自のコマンド・サブエージェント・入れたプラグイン・MCP サーバー・自動メモリ・CLAUDE.md を見つけて読み込む」。作業フォルダの `.claude/settings.json` のフックと `.mcp.json` のサーバーも、信頼の確かめなしに動かす（同じページ。`https://code.claude.com/docs/en/permissions` の「What runs before you trust a folder」も同じ）。→ 作業フォルダは NaTsu の空のフォルダにし、さらに `--safe-mode` を付ける（次の項）。利用者のフック（`UserPromptSubmit` など）は頼みの文、つまり文字起こしを受け取りうるので、作業フォルダを空にするだけでは足りない。
- `--safe-mode`: 「CLAUDE.md・スキル・プラグイン・フック・MCP サーバー・独自のコマンドとエージェント・出力の型・自動メモリなどを読み込まずに始める。ログイン・モデルの選び方・組み込みの道具・権限はふつうに動く（`--bare` と違う）。会社の管理の設定（managed settings）の決まりは残る」（`https://code.claude.com/docs/en/cli-reference`）。いつの版からあるかは公式の資料に無い（第三者の記事は v2.1.169）。→ 引数に入れる。知らない古い版は始まる前に stderr へ「unknown option」で止まるので、`old-version` として `claude update` を案内する（S12）。
- 設定ファイルの `env` の欄と `apiKeyHelper` は、`-p` でも使われる（permissions の同じ表）。利用者の `~/.claude/settings.json` の `env` に `ANTHROPIC_API_KEY` があると、子の環境から変数を外しても効く。→ これは `claude auth status` の `authMethod`（`api_key`・`api_key_helper`）で止める（環境を外すのは、環境の変数の分の守り）。
- SIGTERM で止めると終わりの番号は 143（同じページ）。
- 資格情報の選び方の順: クラウドの提供元の変数（`CLAUDE_CODE_USE_BEDROCK`・`_VERTEX`・`_FOUNDRY`）→ `ANTHROPIC_AUTH_TOKEN` → **`ANTHROPIC_API_KEY`（`-p` ではいつも使われる）** → `apiKeyHelper` → `CLAUDE_CODE_OAUTH_TOKEN` → Anthropic のプロファイル（`ANTHROPIC_PROFILE` など）→ `/login` のサブスクリプション。Windows の資格情報は `%USERPROFILE%\.claude\.credentials.json`（`https://code.claude.com/docs/en/authentication`）。
- `claude auth status` は認証の状態を JSON で出し、**ログインしていれば終わりの番号 0、していなければ 1**。JSON の `authMethod` は `none`・`claude.ai`・`oauth_token`・`api_key`・`api_key_helper`・`third_party` のどれか（`https://code.claude.com/docs/en/cli-reference`）。

## 設計書と違えたところ（理由つき。違う答えなら直す）

1. **既定の送り先は Groq の無料枠**（利用者の決定 D3 は「第一の候補は OpenAI の gpt-4o-transcribe」）。まとめ役が 2026-10-18 に伝えた調べで、1人で使う間は Groq の無料枠がよく（OpenAI と同じ形の口・保存なし・学習に使わない）、OpenAI は精度の比べとして選べる形を勧められたため。送り先は問いとして残す（C1）。どちらも同じ口で、設定を変えるだけで切り替わる。
2. **同意と鍵がそろうまでは、オンラインでも手元の whisper で文字起こしする**（D1 は「手元はオフラインのときだけ」）。鍵が無いと送れず、同意の前に音声を送ると RF28 に反するため。案内を1回出す（M2・M3）。問いとして残す（C7）。
3. **429・鍵の誤りでは、オンラインのまま手元へ落とさない**（D1 のとおり）。ただし、送っている途中で通信が切れた区間は、その時点でオフラインなので手元でやり直す（D4 の「区間ごとに決める」）。
