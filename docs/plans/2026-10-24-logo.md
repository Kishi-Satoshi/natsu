## 目的

1. NaTsu のロゴを、持ち主が選んだ「箱の中のリス」（黒い角丸の箱・白いリス・尻尾の中に音の波）にする。今のロゴ D（箱の上を波が突き破る・N・海の色の波）は全部外す。
2. 次の場所で、同じ1つの絵（`assets/icon.svg`）から作った形を出す。
   - アプリのアイコン（exe・インストーラー・ショートカット）
   - 窓
   - トレイ（待機・録音中）
   - サイドバーの頭
   - 録音バー
   - 会議の知らせのパネル
   - MCP のサーバーの情報
3. 写しが食い違わないようにする。絵の元は `assets/icon.svg` だけにし、ほかの写しが同じ形であることをテストで見続ける。

## 絵の作り方（作る人はやり直さない。結果だけを使う）

- 持ち主の画像（1254×1254 の透過の PNG）を、作業環境の外の道具（potrace）でなぞった。次の手順で `docs/plans/2026-10-24-logo-icon.svg` に置いてある。
  1. 箱の中の白い所をリスとする。
  2. 箱の下の端で平らに切る。
  3. 正方形の角丸の箱（半径は一辺の 20%）で切り抜く。
  4. 座標を `viewBox="0 0 64 64"` に直す。
- 中身は2本の path だけ。
  - 1本目: 黒 `#111111` の箱。角丸の箱から「リスを少し太らせた形」を抜いたもの。リスより少し内側で止まる。
  - 2本目: 白 `#ffffff` のリス。尻尾の黒い波2本は穴として持つ。potrace は穴を逆の向きで書くので、nonzero の塗りで穴になる。
  - どちらも3次ベジェ（C）と直線でできている。
- 2本目を1本目の上に重ねて描く。黒い箱はリスの下にほとんど入らない。
- **足元の黒い線（持ち主の指摘。2026-10-24）:** 黒い箱をリスの下まで敷くと、境目のにじみで箱の縁が透け、リスの足元に細い黒い線が出た。そこで黒い箱をリスの下では少し内側で止めた（太らせた分は 1254 の画像で 5 画素、64 の座標で約 0.26）。リスの縁の下に黒が無いので、線は出ない。
  - 拡大して、明るい地と暗い地の両方で線が無いことを確かめた。
  - テスト: 256 の PNG の下から2行で、リスの足の幅の所に暗い画素（明るさ 100 未満）が無いこと（RF-LG6）。

## 方針

- 絵の元は `assets/icon.svg` の1つ。`tools/icon-render.js` を 3次ベジェ（C）が描けるように広げ、そこから全部の ICO・PNG を描き直す。小さい版はやめる（L-3）。
- その場の SVG（app・overlay・nudge）は、`assets/icon.svg` の2本の d をそのまま写し、色だけを場所ごとに決める（問い LG2）。写しの d が元と同じことを、テストで見続ける。
- 録音中のトレイは、尻尾の中の2本の線を赤 `#d93025` にし、少し太くする（LG4 の答え「しっぽの中の線を赤にして」と、太さの「案 1」）。
- 決まったことは設計書の「利用者が決めたこと」に D の番号で書き、R4（ロゴ D）に「この回で差し替えた」と書き足す。

## 決めたこと（理由つき。違う答えなら直す）

1. **3次ベジェは折れ線にして描く。** 分け数は今の2次ベジェ（`Q_STEPS = 32`）に合わせる。理由: 足し引き掛け割りだけで OS が違っても同じ結果になる、という今の道具の約束を守る。
2. **`fill-rule` は今どおり nonzero だけ。** `evenodd` は受けない。理由: potrace の穴は逆向きで書かれ、nonzero で穴になる。受ける形を増やさない。
3. **録音中の赤い線は、白いリスの上に重ねる3本目の path にする。** 線の形は、尻尾の2本の黒い線を 1254 の画像で 10 画素（64 の座標で約 0.7）太らせてなぞったもの（`docs/plans/2026-10-24-logo-tray-rec.svg`。持ち主に見せた「案 1」）。2本は離れたまま。待機のロゴ（`icon.svg`）の線は元の太さ（L-3）。
4. **`icon-small.svg`・`tray-rec-small.svg` は消す。** `SMALL_BELOW` と小さい版の決まりも外す（L-3）。小さい版を見ていたテストは、同じ commit で意図ごと直す（下の「意図して変えるテスト」）。
5. **MCP のロゴ（`src/mcp/icon.js`）も描き直す。** 理由: D36 の答えは「assets/icon.png を 64×64 にした PNG」なので、元が変われば一緒に変わるのが答えのとおり。
6. **ヘルプのサイトは変えない**（問い LG7 の勧め）。

## 持ち主への問い（選択式。おすすめが先頭）

- **LG1 版:**
  - (a) 0.11.0 を出した後の小さな版 **0.11.1** で、ロゴだけを出す（勧め）。理由: 0.11.0 はもう点検の手前で、ロゴを足すと撮る画面の取り直し（ほぼ全部）が 0.11.0 の確かめと混ざる。失うもの: 新しいロゴが届くのが 0.11.0 の後になる。
  - (b) 作っている 0.11.0 に入れる。失うもの: 0.11.0 の点検と取り直しが重くなり、0.11.0 を出すのが遅れる。
  - (c) 0.12.0 と一緒に出す。失うもの: 届くのがもっと遅い。
- **LG2 暗い所の色**（見本: 持ち主に送った「暗い所での見え方」の画像）:
  - (a) 暗い所（暗い画面のサイドバー・録音バーの暗いピル・暗い画面のパネル）では白黒を入れ替えて **白い箱に黒いリス** にする。明るい所とアプリのアイコン・トレイは黒い箱（勧め）。理由: 暗い地に黒い箱だと箱の縁が見えず、白いリスだけが浮いて「箱」の印象が消える。失うもの: 場所によってロゴの見た目が2通りになる。
  - (b) どこでも黒い箱のまま。失うもの: 暗い所で箱が見えない。
- **LG3 海の色 `#0e8cae`:** ロゴから海の色の波が無くなる。残りの使い道は、録音中の点・録音バーの処理中の輪・相手の声の印。
  - (a) この3つは海の色のまま残す（勧め）。理由: 動きの意味（録音中・相手が話している）を色で見分けている。ロゴの差し替えで動きの見え方を変えない。失うもの: 白と黒のロゴの横に、色が1つ残る。
  - (b) この3つも白か灰にして、全部を白と黒にする。失うもの: 相手が話しているかが見分けにくくなる。撮る画面の取り直しも増える。
- **LG4 録音中のトレイ:**
  - (a) 箱の右下に、白い縁つきの赤い点を重ねる（勧め。見本の右端）。理由: 今の録音中の印と同じ考えで、16px でも赤が見える。失うもの: 尻尾の波の一部が点で隠れる。
  - (b) 箱全体を赤くする。失うもの: 白と黒の決まりから外れ、待機と形が離れる。
- **LG5 exe とショートカットのアイコン**（調べた結果 11）:
  - (a) アプリの中の更新で、窓・トレイ・画面の中のロゴは新しくなる。exe・ショートカット・ピン留めは、次にインストーラーで入れ直すとき（次の Electron の入れ替えなど）に変わるのを待つ（勧め）。理由: ロゴのためだけに全員の入れ直しを求めない。失うもの: しばらくの間、タスクバーのピン留めは古いロゴ、開いた窓は新しいロゴ、と混ざる。
  - (b) この版をインストーラーで入れ直す版にする（入れ直しの知らせを出す）。失うもの: 全員が一度入れ直す手間。

  - (b) 録音バーは古いロゴのまま。失うもの: 録音バーだけ見た目が違う。
