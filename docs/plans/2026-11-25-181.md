## 目的

1. **PC 全体が重くならない。** 文字起こしのエンジンが、会議のアプリ（Teams・Zoom など）や画面の操作と CPU を取り合わない。
2. **会議中の遅れを小さくする。** 区切りを短くして字を早く出し、1 回の計算を短くする。会議の後のやり直しが会議の区間の前に割り込まない。
3. **止まって抜けない。** 落ちた NaTsu が残したエンジンがポートを塞ぐのを断つ。
4. **会議の後の文字起こしが必ず終わる。** 時間切れの区間が1つあっても、ほかの区間と要約は進む。何度も時間切れになる区間は音声を残して止める（ヘルプの「3 回まで試して」と同じ形）。
5. **更新すれば直る。** 前の版の既定のままの設定（スレッドの数・間隔）・覚え（`local-pace.json`）・待ち行列（`recovery.json`）を、0.18.1 の初めの起動で直す。利用者は［設定］→［更新］で 0.18.1 にするだけでよい。

## 決めたこと（理由つき）

1. **スレッドの既定を 4 までに（AQ181-1'）。** 既定 = 論理 CPU が 4 より多ければ 4、4 以下なら `max(2, floor(論理 CPU / 2))`（4 → 2、2 → 2）。`settings.js` の `defaultSettings` と `main.js` の `CPU_DEFAULT_THREADS` を1つの関数 `lib.defaultThreads(n)` にする。理由: 持ち主の PC で動いている数にそろえる。GPU 版では計算の大半を GPU がするので 4 で足りる。失うもの: GPU を使えず CPU で計算する PC では遅くなる（2 の優先度と 6 の覚えの直しで、「遅い」と決めつけるのを和らげる）。
2. **起こしたエンジンの優先度を「通常より低い」に（AQ181-1'）。** `spawn` の後に `os.setPriority(p.pid, os.constants.priority.PRIORITY_BELOW_NORMAL)`（Node の公式の部品。Windows では BELOW_NORMAL_PRIORITY_CLASS）。失敗しても起こすのは止めず、`engine.log` に1行。理由: 画面と会議のアプリが先に CPU を取れる。失うもの: ほかの重い仕事と同時のときは文字起こしが遅れる。
3. **前の版の既定のスレッド数を、新しい既定へ移す（AQ181-1'「更新で移す」）。移すのは 0.18.1 の初めの起動の1回だけ（AQ181-14）。** 起動のとき（起動で読めなかった設定は `retrySettingsRead` で読めたとき）、`settings.json` に移した印（`defaultsMigrated`: 1。CR25）が無ければ、`localThreads` が前の既定（`max(4, n − 2)`・`max(4, floor(n / 2))`）のどちらかと同じなら新しい既定にし、移す物が無くても印を付けて、今の設定の書き手（`settingsWriter`。同じ一時ファイルと名前の変更）で `settings.json` を1回書く。画面には知らせない（engine.log に移したキーの名前を1行）。印のある起動では移さない。AQ181-14 の選択肢の字（そのまま）:「0.18.1 で初めて起動したときに1回だけ移し、移したことを設定のファイルに書き残します。その後に自分で 10 や 75 秒を選んだら、その数が残ります。理由: 「更新すれば直る」と「自分で選んだ数は残る」の両方が守れます。失うもの: 0.18.1 の初めての起動で、NaTsu が設定のファイルを1回書きます（今は起動のときに書きません）。」 理由: `settings.json` は既定の数をそのまま書いているので、選んだ数と見分けられない。移した印を残せば、更新で直り、その後に選んだ数は残る（前の第3版の「メモリの中だけ（書き戻し・知らせ無し）」は起動のたびに移したので、後で前の既定と同じ数を選んで保存しても、次の起動でまた移っていた: M15）。失うもの: 0.18.1 の初めての起動で、NaTsu が `settings.json` を1回書く（前は起動のときに書かなかった）。0.18.1 に更新する前に前の既定と同じ数を自分で選んでいた人も、その1回で移る（その後に［設定］で選び直せば残る）。持ち主の PC（論理 CPU 12）の 4 は前の既定（10・6）と違うので移らない（新しい既定と同じ。印だけ書く）。
