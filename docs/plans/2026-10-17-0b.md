**回の名前:** 第0b回（0.2.0）— エンジンの自動取り込み（設計書 :72, :103, :156 の R7）

**目的:** 初めて起動した PC で、利用者が［エンジンを取り込む］を1回押せば、文字起こし（whisper.cpp のエンジン・モデル・VAD のモデル）と要約（llama.cpp のエンジン・要約のモデル）がそろい、起動テストが通る 0.2.0 を、Linux と Windows の CI が緑の commit から `natsu-v0.2.0` で出す。版と SHA-256 はアプリの中に固定し、合わないファイルは使わずに取り込み直す。途中で切れても HTTP の Range で続きから取る。日本語のユーザー名の PC でも動く（RF1）。通信はすべて Electron の `net` で行う（RF2）。取り込んだ exe と DLL は SHA-256 を照らしてから使い、止められたときは案内を出す（RF3）。今のセットアップスクリプトは詳しい人向けに残す。

**方針（アーキテクチャ）:**
- **ピンは1か所:** `src/engine-manifest.js` に、取得元の URL（GitHub はタグ、Hugging Face は 40 桁の commit で固定）・大きさ・SHA-256・置き場所・zip の中で使うファイルごとの SHA-256 を、凍結したデータで持つ。自動更新は `src/` を入れ替えるので（updater.js の apply）、ピンを上げるのも更新で届く（設計書 :158 の R3「src/ に固定した版と SHA-256 を見て、0b の仕組みで取り込み直す」）。
- **実行中に api.github.com を呼ばない。** 今のスクリプトは `releases/latest` を API で引くが（setup-local-engine.ps1:212-215、setup-summarizer.ps1:186-196）、API は1つの IP から1時間に60回までで、会社の出口が1つなら50台で詰まりうる（GitHub の公開の制限。この環境では未検証）。資産の URL を直に固定すれば API は要らない。
- **通信は Electron の `net.request`（ClientRequest）で行う。** `net.fetch` では足りない。Electron 31.7.7 の `lib/browser/api/net-fetch.ts` は redirect と login の受け手を付けないので、手で転送を追えず、プロキシの認証は黙って取り消される（調査者が Electron の元のコードで確認）。`net.request` は `redirect: 'manual'` で転送ごとに `'redirect'` を出し、`followRedirect()` を同じ流れの中で呼べば続く。`'login'` も受けられる。
- **転送のたびに固定の URL から始め直す。** GitHub も Hugging Face も、署名付きの CDN の URL へ 302 で送り、その URL は切れる（Hugging Face は1時間。調査者が `Expires` を確認）。HF の CDN は `If-Range` を無視する（違う ETag でも 206 が返った）。だから中身の同一は「commit で固定した URL」「206 の Content-Range の総量 = ピンの大きさ」「最後の SHA-256」で決める。
- **取り込み先は `%LOCALAPPDATA%\natsu\engine`。** `userData`（`%APPDATA%\natsu`、Roaming）には置かない。数 GB のモデルがプロファイルの同期で運ばれるため。インストール先（`%LOCALAPPDATA%\Programs\NaTsu`）とも別なので、入れ直しや更新で消えない。Electron の `app.getPath` には LocalAppData の名前が無いので、`process.env.LOCALAPPDATA` から作る。
- **RF1 は「相対パス」で避ける。** whisper-server は引数を ANSI（日本語の Windows では CP932）で受け取り、モデルのパスを UTF-8 として読み直す（whisper.cpp v1.9.5 `examples/server/server.cpp:239`, `:261` → `src/whisper.cpp` の `std::wstring_convert<std::codecvt_utf8<wchar_t>>::from_bytes`）。CP932 の日本語は UTF-8 として正しくないので、投げて落ちる。そこでエンジンを **cwd = exe のフォルダ** で起動し、モデルを `..\models\…` の英数字だけの相対パスで渡す。利用者名の部分は引数に出ない。英数字だけの絶対パスは今までどおりそのまま渡す（今動いている PC の挙動を変えない）。これが Windows で本当に効くかは Task 8 の CI で確かめ、効かなければ Task 8b で `C:\ProgramData\natsu` へ逃がす。
- **設定には書かない（設計 B）。** 「詳細設定の実行ファイルとモデルが両方空の側は、取り込んだエンジンを使う」とする。main がパスを設定へ書くと、画面の自動保存が空の欄の値で書き戻す（app.html:1946-1980 の `save()` は5つのパスを毎回 DOM から送る。main から画面へ「設定が変わった」と知らせる道は無い）。設定に書かなければ、この競り合いは起きない。手で入れたパスは、今までどおりそちらが勝つ。
- **切り替えは暇なときだけ。** 取り込みが済んでも、記録中・要約中・復旧中・文字起こし待ちがあるうちは、使うエンジンを替えない（`isBusy()` main.js:1665 と `meeting`）。古い版のフォルダは、記録にあって、動いていないものだけを消す。
- **zip は自前で読む。** `src/zipread.js`（中央ディレクトリ＋`zlib.inflateRaw`）。updater の PowerShell `Expand-Archive`（updater.js:171-189）は使わない。会社の方針で PowerShell が止められうること、パスの `'` で壊れること、必要なファイルだけを選んで SHA-256 を照らせないこと、`execFileSync` で main を止めることが理由。両方の zip の項目は全部 deflate（方式 8）・フラグ 0・ZIP64 なし（調査者が確認）。

**この回で足す決まり**

- **npm test では本物のエンジンを起動しない。** whisper-server.exe と llama-server.exe を実際に動かすのは、Windows の CI の `engine-smoke` だけ。この Linux の作業環境では、落としたバイナリを実行しない。
- **テストの一時フォルダの名前には、日本語と 𠮷（CP932 に無い字）を入れる**（`fs.mkdtempSync(path.join(os.tmpdir(), 'natsu-取込𠮷-'))`）。Linux でも Windows でも、日本語の名前のフォルダで毎回通す（RF1）。
- **新しいモジュールは `require('electron')` をしない。** 通信は `request` を引数でもらう（本番は `net.request`、テストは `test/helpers/fake-net.js`）。素の `fetch(` も書かない（Task 2 のゲートと走査で止まる）。
- **ピンを変えるのは Task 1 のファイルだけ。** ピンを変えた commit は、Windows の CI の `engine-smoke`（本物の取得元に届くか・日本語のフォルダで起動するか）が緑であること。
- **飛ばすテストを増やさない。** CI は Linux で 0 件、Windows で 1 件まで（ci.yml のテストのステップ）。Windows だけで意味のあるテストも、Linux で `path.win32` を使って走るように書く。
- **.ps1 を直すとき:** 読んだ文字の先頭の U+FEFF を外してから `writePs1(file, text)`（tools/write-ps1.js）で書き戻す（0a の決まりのまま）。

### 再開のしかた（HTTP の Range）

1. 取り込み中のファイルは `.download\<SHA-256>.part`。横に `.json` の記録（URL・大きさ・SHA-256・確定した長さ）を置く。名前が SHA-256 なので、ピンが変われば古い `.part` は別物として捨てられる。
2. 32MB ごとにディスクへの書き込みを確定し（`fh.sync()`）、その長さを記録に書く（一時ファイル → 名前の変更）。電源が切れても、次は記録の長さまで切り捨ててから続ける。
3. 続きを取るときは、**毎回ピンの URL から**、`Range: bytes=<持っている長さ>-` を付けて頼む。`206` で、Content-Range の始まりが持っている長さと同じ、総量がピンの大きさと同じときだけ書き足す。`200`（Range を無視された）なら 0 から書き直す。
4. 大きさがピンと同じになったら SHA-256 を照らす。違えば Range を使わずに1回だけ全部取り直し、それでも違えば止める（使わない）。
5. 合えば `.part` を本当の名前に変える。ウイルス対策が掴んでいれば、待って10回まで試す。
6. Node はハッシュの途中の状態を保存できないので、続きから取るときは、持っている分を読み直してハッシュに足す。

    - 206: Content-Range が読めない → retry `bad-range`。総量 ≠ ピンの大きさ → fail `size-changed`。始まり ≠ held → restart `range-start`。`content-encoding` が identity 以外 → restart `encoding`。

    - 401・403・408・429・5xx → retry（`retry-after` を秒で返す）。ほか → fail `http-<status>`。

| --- | --- |

### Task 5（R7-4）: `src/engine-fetch.js` その2 — `fetchFile` の本体（続きから・転送・記録・SHA-256）

**目的:** 1つのファイルを、`net.request` と同じ振る舞いの道具で、切れても続きから、SHA-256 を照らして取る。

**Files**
- 直す: `src/engine-fetch.js`（`fetchFile` を足す）
- 作る: `test/helpers/fake-net.js`、`test/helpers/range-server.js`
- テスト: `test/engine-fetch.test.js` に足す

**Interfaces**
- `fetchFile(pin, opts): Promise<{ file }>`。失敗は `Error`（`code` 付き）で投げる。
  - `pin`: `{ url, size, sha256 }`
  - `opts`: `{ dir, dest, request, sleep, onProgress, signal, requireHttps = true, headerTimeoutMs = 60000, stallMs = 120000, maxFails = 6, maxHops = 10, syncEvery = 32 << 20, rename = fs.promises.rename, userAgent }`
    - `dir` は `.download` のフォルダ、`dest` は置く先の本当のパス。
    - `request` は Electron の `net.request` と同じ形（本番は `(o) => electronNet.request(o)`）。
- 1回の試し:
  - `request({ method: 'GET', url: pin.url, redirect: 'manual', cache: 'no-store' })`。`credentials` は渡さない（プロキシの認証の情報は送り、クッキーは送らない: Electron の url_loader.cc）。
  - 見出し: `Range: bytes=N-`（N > 0 のときだけ）、`Accept-Encoding: identity`、`User-Agent: NaTsu/<版>`。`If-Range` は送らない。
  - `'redirect'(status, method, newUrl, headers)`: 回数が `maxHops` を超えたら `too-many-redirects`。`https:` でなければ `insecure-redirect`。その転送の見出しに `x-linked-etag`（引用符を外す）か `x-linked-size` があって、ピンと違えば `pinned-mismatch`（本体を取る前に止める）。そうでなければ **同じ流れの中で** `req.followRedirect()`。
  - `'login'(info, cb)`: `cb()`（何も渡さない＝取り消す）で `proxy-auth`。
  - `'response'`: `decide()` に従う。書くときは `fh.write(chunk, 0, len, position)` で位置を指定し、ハッシュに足す。
  - 試しのたびに **ピンの URL から** 始める（前の試しの CDN の URL は使わない）。
- 記録（`<dir>/<sha256>.json`）: `{ url, size, sha256, synced }`。始める前に、記録の url・size・sha256 がピンと違えば `.part` を捨てる。`.part` を `synced` まで切り捨てる。`.part` がピンより大きければ捨てる。`syncEvery` ごとに `fh.sync()` してから、記録を一時ファイル → 名前の変更で書く。
- 大きさがピンと同じになったら SHA-256 を照らす。違えば `.part` と記録を消して Range なしで1回だけ全部取り直す。それでも違えば `hash`（最後のファイルも `.part` も残さない）。
- `.part` が初めからピンの大きさと同じなら、要求を出さずに照らす。
- 合えば `rename(.part, dest)`、記録を消す。

**test/helpers/fake-net.js**（Electron 31 の ClientRequest の振る舞いを真似る。node:http と node:https の両方）

## この回でやらないこと（調べて分かったが、別の回）

- **GPU で速くすること。** llama.cpp には公式の Windows の Vulkan 版がある（CPU の DLL も入っている）が、Intel・AMD の内蔵 GPU で、おかしな文を出す・落ちる不具合が報告されている（llama.cpp #17106, #17056）。whisper.cpp には公式の Windows の Vulkan 版が無い（自分で作って配る必要がある）。manifest は版ごとの項目なので、後の回で `variant` を足せる。
- **要約を会議の最中に少しずつ進めること。** 会議の後の待ちは短くなるが、#58 のメモリの判断（要約エンジンを先に起動しない）とぶつかる。
- **スレッドの数の既定を変えること。** 今の `-t max(4, 論理 CPU - 2)` は、SMT の PC で物理コアより多い。物理コアの数のほうが速いという話はあるが、測っていない。
- **プロキシのパスワードの入力の窓。** 0b は案内だけ（Q7）。
- **社内の共有フォルダからの取り込み・予備の取得元（自分のリリースへの写し）。** Q8, Q10。
- **Visual C++ ランタイムの DLL をエンジンのフォルダに同梱すること。** 再配布の権利の判断が要る（Q2）。
- **GitHub の証明（attestation）の確かめ。** GitHub の API が読める機械で `gh attestation verify` を1回回せる。この環境は API が 403 だった（Q10）。
- **更新の確認が起動のたびに api.github.com を呼ぶこと**（updater.js:23, :102、main.js の起動の8秒後）。50台が1つの出口なら、1時間に60回の制限で「更新情報を取得できません (403)」になりうる。0b の範囲の外なので、別の回で直す。
