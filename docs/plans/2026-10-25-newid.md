## 目的

1. 要約からブロックを作るとき（`markdownToBlocks` → `markBlocks`）、同じ要約の中で ID が重ならないようにする。重なると要約が丸ごと保存できない（下の「調べた結果」3）。
2. できれば DB の全体でも重ならないようにする（`blocks.id` は DB の全体で `UNIQUE`）。1つのプロセスの中では必ず重ならず、プロセスをまたいでも乱数で重ならないようにする。
3. ID の形は今と同じ「頭の1字（`b`・`p`・`h`）＋時刻（36 進）＋英数字」のままにし、`ID_RE` を通る。前の版の ID は何も直さずに通る。

## 方針（問い Q1 の勧めの案 A。違う答えなら直す）

新しい純粋な部品 `src/ids.js` に、ID を作る関数を 1 つだけ置く。`store.newId` と `memoTypes` の `newBlockId` は、どちらもこの関数を呼ぶ（写しを 2 つ持たない）。

```
<頭><時刻（ms の 36 進。今は 8 字）><同じミリ秒の中の番号（36 進。0 から）><乱数（crypto。36 進で 5 字）>
例: b mvoh8mib 0 7q2zd   → bmvoh8mib07q2zd（15 字。今は 14 字）
```

- **プロセスの中では必ず重ならない:** 前に使った時刻 `last` と番号 `seq` を覚える。
  - `Date.now()` が `last` より大きければ、`last` をその時刻にし、`seq` を 0 にする。
  - そうでなければ（同じミリ秒、または時計が戻った）、`last` はそのまま、`seq` を 1 つ増やす。
  - ID に入る（`last`, `seq`）の組は、作るたびに大きくなるので、同じ組は 2 度と出ない。
  - 時刻の部分は、1973 年から 2059 年まではいつも 8 字。全体の長さが同じ 2 つの ID は、番号の字数も同じになる。だから番号が違えば、文字列も違う。
- **プロセスをまたいで:** 乱数 5 字を `crypto.randomBytes` から作る。今の `commands.js`・`migrate.js` と同じ源。DB のプロセスの 2 つの作り方は、作り直しで重ならない（調べた結果 4）。
- **形:** 英数字だけ、15〜16 字。`ID_RE`（64 字まで）を通る。前の版の ID（14 字）も、そのまま通る。
- **変えないもの:**
  - `store.newId` の名前と引数。`test/stage2a1.main.test.js` の ST1 が、main から呼んでよい store の関数として名指ししている。
  - `memoTypes` の出す名前。
  - `commands.js` と `migrate.js` の作り方。
  - 照らしの決まり。
