## 目的・方針・使うもの・覆う設計書の項目

## 決めたこと（理由つき。違う答えなら直す）

**A. 木の形（H1・H2・H6）**

1. **木の正本は `parent_id` だけ:** 子のページの行は `parent_id` に親のページの ID、最上位は NULL（今のまま）。親に子の一覧を持たせない（設計書「保存の土台」の「子の並び」。2つの正本が食い違わない）。親になれるのは、一覧に出るページ（議事録でも白紙のページでも。ゴミ箱と録音中の写しは除く）だけ。
2. **並び（BQ5 (a)）:** 最上位は今のまま作った順の新しい順（`created_at desc`。一覧の問い合わせを変えない）。子は兄弟の中の並びの鍵 `ord`（`keys.keyBetween`）の順で、同じ鍵なら作った順。新しく作った子は末尾。最上位のページの `ord` は今の `'i'` のまま（BQ5 (a) では最上位を手で並べないので、全部のページに鍵を書き直す移行は要らない）。
3. **深さに上限は無い（H1）:** DB も画面も段の数で断らない。画面の字下げだけは 8 段で止め、それより深い行は同じ字下げで並べる（`aria-level` は本当の段）。理由: 段の数で断ると、深く作った人のページが動かせなくなる。字下げを止めないと、サイドバーの幅（200〜480）の中で題名が見えなくなる（HR1）。
4. **最上位へ動かす操作の形:** `move` の操作で、ページの行を最上位へ動かすときは `parent: null`（前の親は `oldParent`）と書き、`applyOps` は `Object.hasOwn(o, 'parent')` のときに `parent_id` を書く（`ops.js:287` の条件を直す。ブロックの行の `move` は今どおり文字の親だけを持つので、前の版の `oplog` の当て直しは同じ答え）。後ろへの形（`invertOps`）と照らし（`opsMatch`）は、ページの行を扱わないので変えない（ページの命令は元に戻すに入れない: 決めたこと 15）。
5. **輪を作らない:** `page.move` は、動かすページ自身と、その子孫の下へは `bad-args`（`canMoveUnder`）。読むときも、もし輪や親の無い行があれば（前の版の NaTsu で親だけを消した・壊れた行）、捨てずに最上位に並べ、その数だけを記録に1行書く（`DB: 親をたどれないページ n 件を最上位に並べた`。0.13.1 の要約の行の「組めない行は捨てずに最上位の末尾」と同じ考え: HR2）。
6. **木を歩くのは JS で、同じトランザクションの中:** 子孫を求めるときは、命令の中でページの行を1回読み（`id`・`parent_id`・`trashed_at`）、`src/pageTree.js` の部品で歩く（訪ねた印で、輪があっても止まる）。SQL の再帰の問い合わせは使わない（調べた結果 6: 索引が無く 1,000 段で約 3 秒・索引を足しても計画が変わらない。JS は約 10 ミリ秒。設計書 H5 の「再帰の問い合わせ1つ」と違う: 食い違い M1）。消す・戻すの全部は、今どおり1つのトランザクション・`oplog` の1行。
7. **表の形の版を上げない（H6）:** 索引も欄も足さない。理由: 版を上げると、前の版の NaTsu はその DB を読み取り専用でしか開けない（`core.js:137`〜`:145`）。1.0.0 の前でも、戻した人が書けなくなる道を作らない（RF17）。木を歩く速さは決めたこと 6 で足りる。
8. **前の版の NaTsu に戻したとき（RF17）:** 前の版は `parent_id` を見ないので、子のページも最上位に平らに並んで見える（消えない）。前の版で親だけを消すと、子は親を失い、この版に戻ったときに最上位に出る（決めたこと 5）。前の版の書き戻し（`page.put`）は `parent_id` を書かない（調べた結果 5）ので、木は壊れない。白紙のページは前の版では議事録の形で開く（本文は［AI 要約］の欄に見える）。

**B. 会議と録音（BQ4 (a)）**

9. **録音中のページは木に入れない:** 録音中の写しと録音の前のページは、一覧に出ないので木にも出ない。`page.move` は録音中の写しを動かせず（`bad-args`）、`page.create`・`page.move` は録音中の写しを親にできない。理由: 録音の正本は main のメモリと `draft.json` で、DB は写し。締め・復旧・取り消しは同じ ID を上書きするか消すので、録音中に親を付けると取り消し（`meeting.discard`）で子が迷子になる。
10. **新しい議事録はいつも最上位に作る（BQ4 (a)）:** ［＋ 新しい議事録］・Ctrl+Shift+N の［議事録］・会議の検出のパネル・Alt+M のどれで始めても、締めた議事録は最上位（今のまま）。保存した後は好きな所へ動かせる。
11. **取り消しで子を迷子にしない:** `meeting.discard` は、もし消すページを親に持つ行があれば（普通の流れでは起きない: 決めたこと 9）、同じトランザクションでその行を最上位へ出してから消す（`purge` の前に `move` の操作）。
12. **書き戻し・締め・復旧は親を変えない:** `diffPage` はページの行の `parent_id`・`ord` を書かない（調べた結果 5）ので、要約の書き戻し・種類の変更・メモの直しは動かしたページの置き場を残す。ページを動かすとそのページの `rev` が上がるので、要約を作っている間に動かすと書き戻しは `conflict` になり、`saveIfExists` が読み直して書く（今の決まりのまま。PH-2 で場面を固定する）。

**C. 命令（PH-2）**

13. **新しい命令（どれも役 `app` だけ。main と後の MCP は呼べない: SEC3）:** `page.create`（白紙のページを作る）・`page.move`（親と兄弟の中の置き場を替える）・`page.restore`（ゴミ箱から戻す）・`pages.trash`（ゴミ箱の頭の行。読む）・`page.setIcon`・`page.setLook`（PL-2）。`page.delete` は子孫も入れる形に直す（答えは今どおり一覧）。形は「受け渡す名前と形」。
14. **新しいページの ID は DB が作る:** `p`＋時刻の36進＋5字の小文字の英数（`store.newId` と同じ形。タブの鍵 `^page:p[a-z0-9]{1,40}$` に合う）。同じ ID が無いかを確かめて作り、送り直し（dup）の答えは `oplog` の1行の `add` の操作から同じ ID を返す（`block.insert` と同じ）。
15. **ページの命令は元に戻すに入れない（HR3）:** `page.create`・`page.move`・`page.delete`・`page.restore`・`page.setIcon`・`page.setLook` は `UNDO_CMDS` に入れない（0.14.0 の元に戻すは、開いているページの要約とメモの欄の歩み）。動かしたら動かし直す、消したらゴミ箱から戻す。
16. **何も変えない命令は書かない:** 同じ所への `page.move`・同じアイコン・同じ見た目は、操作の空の行だけ（(役, tx) の送り直しのため）で、ページの `rev` も更新の時刻も変えない。
17. **一覧の行に木の欄を足す:** `pages.list`（問いが空のときと、検索の答え）の1行に `parentId`（最上位は `null`）・`ord`・`kind`（白紙のページだけ `'blank'`）・`icon`（あるときだけ）を足す。覚えた1行（`LIST_CACHE`）の外で、読んだ行から添える（`HOT_QUERIES.list` に `parent_id`・`ord` を足す）。`page.get` の答えの形は変えない（`icon`・`look`・`kind` は `attrs` なので、ページに今どおり入って来る）。json-backend の `pages.list` は `parentId: null`・`ord: 'i'` を添え、答えの形を比べるテストを同じにする。

**D. サイドバーの木（H2。PH-3）**

**H. 全幅・文字の大きさと書体（U5・U6。PL-3）**

## 実機で利用者に見てもらうこと（出した後。Windows x64・JIS のキーボードと Microsoft IME・拡大 100／150／200%）

1. **木:** サイドバーの行の［＋］で子・孫を作る。▸ の開け閉めが起動し直しても残る。↑↓←→ で歩ける。引っ張って中へ・前後へ。自分の子の中へは落ちない。
2. **白紙のページ:** 題名と本文だけ。本文で `/`・Ctrl+B・貼り付け・Ctrl+Z が要約と同じに動く。「目的」の見出しが勝手に並べ替わらない。
3. **議事録と木:** 保存した議事録を白紙のページの中へ動かす。要約を作っている間に動かしても、要約が書き戻される。録音中のページはサイドバーの木に出ない。新しい議事録はいちばん上にできる（BQ4 (a)）。
4. **パンくず・子ページの行・［移動先…］:** 深い段で「…」。親の本文の下の子ページの行。［移動先…］で探して動かす。Ctrl+Shift+U。
5. **Ctrl+Shift+N:** 日本語入力のままでも、変換中は開かない。［白紙のページ］［議事録］。録音中は［議事録］が押せない。
6. **ゴミ箱:** 親を消すと中のページも消える（確かめに数）。［ゴミ箱］から戻すと、一緒に消した子も戻る。先に消した子は戻らない。
7. **Claude（BQ8 (a)）:** Claude デスクトップで「白紙のページの○○を読んで」。子ページの答えに場所。ゴミ箱のページは出ない。
8. **（0.15.1）アイコン・見た目:** よみで絵文字を探す。サイドバー・タブ・パンくずにアイコン。全幅・小さい文字・明朝・等幅を拡大 200% で。ページを替えると見た目が替わる。

**BQ1 0.15.0 を分けますか？（大きさ: 13 タスク・変異 76・新しい画面 17 枚・取り直しはタブの写る画面の全部（約 40〜70 枚）を含む）**
- **(a) 2つに分ける（おすすめ）。** 0.15.0 は「ページの階層」（白紙のページ・木・パンくず・子ごとのゴミ箱と戻す・Ctrl+Shift+N。PH-1〜PH-8）、0.15.1 は「ページのアイコンと絵文字・全幅・文字の大きさと書体」（PL-1〜PL-3）。理由: 階層は DB の削除と移動（議事録を壊さない約束）に手が入るので、先に出して実機で確かめてから見た目を載せる方が、壊れたときの切り分けが易しくなります。アイコンをタブに出すとページのタブが写る画面を全部取り直すので、その見比べを階層の確かめと分けられます。0.13.0／0.13.1 と同じ分け方で、後の版の番号はずれません。失うもの: アイコン・全幅・書体が1回分遅れて届き、リリースの手間が1回増えます。「···」の画面は2回取り直します。
- **(b) 0.15.0 にまとめて出す。** 失うもの: 1回のリリースで DB の木と大きな取り直しを一緒に確かめることになり、点検と実機の確かめが重くなります。
- **(c) 見た目を先に（0.15.0 がアイコンと見た目、0.15.1 が階層）。** 失うもの: アイコンを出すサイドバーとパンくずを、階層で作り直すときにもう一度取り直します。

**BQ2 白紙のページは、どんな形にしますか？（H4）**
- **(a) 題名と本文だけ（おすすめ）。** 本文は要約と同じ書き方（太字・`/`・⠿・貼り付け・Ctrl+Z）で、［AI 要約］［メモ］［文字起こし］のタブ・会議の種類・要約の生成・出典の札は出しません。理由: 録音しないページに、使わないタブと「要約を生成」が並ぶと迷います。本文は 0.13.0〜0.14.0 で作った行の部品をそのまま使えます。失うもの: 白紙のページから録音は始められません（会議は［＋ 新しい議事録］から。保存した後で白紙のページの中へ動かせます）。
- **(b) 議事録と同じ形（3つのタブを出し、空のまま）。** 失うもの: 使わないタブが並び、［要約を生成］を押しても断られます。
- **(c) 白紙のページに［このページで録音を始める］を置き、録ると議事録に変わる。** 失うもの: 録音・下書き・復旧・締めに「今あるページに書く」道を足す大きな作業で、0.15.0 がかなり大きくなります。録音の守りの確かめもやり直します。

**BQ3 子ページは、親のページのどこに並べますか？（H1）**
- **(a) 親の本文の下に「このページの中のページ」の一覧で並べる（おすすめ）。** 白紙のページは本文の最後、議事録は［AI 要約］の欄の最後に、「📄 ページ名」の行（押すと開く・並びはサイドバーと同じ）。理由: 議事録の本文は AI の要約で、［要約を再生成］で行が全部作り直されます。子ページを本文の行にすると作り直しで消え、子が迷子になります。出典の照合・［コピー］・Claude に渡す要約も今と1文字も同じで済みます。失うもの: 本文の途中の好きな所に子ページの行を置けません（Notion とはそこが違います）。
- **(b) 白紙のページだけは本文の行として好きな所に置き、議事録は本文の下の一覧。** 失うもの: 2つの形を作り、行の命令（貼り付け・まとめて消す・元に戻す・複製）が子ページの行を消したり写したりしたときの決まりを全部決めることになり、0.15.0 がかなり大きくなります。
- **(c) 本文には出さない（サイドバーとパンくずだけ）。** 失うもの: 設計書 H1 の「親の本文に並ぶ」を満たしません。

**BQ4 新しい議事録はどこにでき、録音中のページは木でどう扱いますか？**
- **(a) 新しい議事録はいつもいちばん上にでき、録音中と録音の前のページは木に出さず、動かせず、中にページを作れない（おすすめ）。** 保存した後は好きな所へ動かせます。理由: 録音の正本は PC のメモリと下書きのファイルで、保存の DB は写しです。締め・落ちたときの戻し・取り消しは同じページを上書きか消すので、録音の途中で置き場を変える道を作ると、取り消したときに中のページが迷子になります。失うもの: プロジェクトのページを開いて会議を始めても、議事録はいちばん上にでき、後で動かす1手が要ります。
- **(b) 開いているページの中に作る（［＋ 新しい議事録］を押したときに開いていたページの中。親は録音を始めたときに決めて下書きに書く）。** 失うもの: 下書き・戻し・締めに親を足し、録音の途中で親が消されたときの決まりも要ります。0.15.0 が大きくなります。
- **(c) 締めた後に「どこに置きますか」と聞く。** 失うもの: 会議のたびに問いが1つ増えます。

**BQ5 サイドバーの並び順は？**
- **(a) いちばん上の段は今のまま新しい順、中のページは自分で並べた順（新しく作った子は末尾。引っ張って並べ替え）（おすすめ）。** 理由: 50 人の議事録は毎日増え、いちばん上の段を手で並べると新しい議事録を探しにくくなります。今の全部のページに並びの鍵を書き直す移行も要りません。失うもの: いちばん上の段は並べ替えられません（引っ張ると中へ入れる・いちばん上へ出すだけ）。
- **(b) 全部自分で並べた順（Notion と同じ。新しいページは上に足す）。** 失うもの: 今の全部のページに並びの鍵を書く移行が要り、前の版に戻したときと食い違わないかの確かめが増えます。議事録が増えるほど、新しい議事録が埋もれます。
- **(c) 全部新しい順。** 失うもの: 中のページの順番を決められません（アジェンダの順などに並べられない）。

**BQ6 消したページを戻す入口は？（H5）**
- **(a) ゴミ箱に何かあるときだけ、サイドバーの［設定］の上に［🗑️ ゴミ箱］を出し、押すと消したページの一覧と［戻す］（中のページも一緒に戻る）（おすすめ）。** 完全に消す・30 日で消すは第17回のまま。理由: 親を消すと中のページも全部消えるので、間違えたときの被害が大きくなります。今は戻す道がありません。空のときは出さないので、今の画面と写真は変わりません。失うもの: ゴミ箱が空のときは入口が見えません（空なので困りません）。
- **(b) 消した直後に左下の知らせに［元に戻す］を 10 秒出すだけ。** 失うもの: 知らせを見逃すと戻せません。
- **(c) 戻す道は作らない（DB の命令だけ作り、画面は第17回）。** 失うもの: 第17回まで、間違えて消した親と中のページを戻せません。

**BQ7 Ctrl+Shift+N と、新しいページの入口は？（0.14.0 の BQ8 の申し送り。持ち主の言葉「Notionのように新しいページを追加＞白紙のページ or データベースという感じ」）**
- **(a) Ctrl+Shift+N で「新しいページ」の小さな選び（［白紙のページ］［議事録（録音の前のページ）］。データベースは 0.17.0 で足す）を開く。サイドバーは［＋ 新しい議事録］をそのまま残し、見出し「議事録」の行に乗せる・フォーカスすると出る［＋］で白紙のページを作る（おすすめ）。** 理由: 持ち主の言葉の形で、設計書 U3 のキーです。サイドバーの見た目が今と同じなので、写真とヘルプの［＋ 新しい議事録］を直さずに済みます。録音は今どおり［文字起こしを始める］を押すまで始まりません。失うもの: 見出しの［＋］は乗せないと見えません（キーボードは Tab で届きます）。白紙のページも「議事録」の見出しの下に並びます。
- **(b) サイドバーの［＋ 新しい議事録］を［＋ 新しいページ］に替え、押すと同じ選び。見出しも「ページ」に。Ctrl+Shift+N も同じ選び。** 失うもの: サイドバーの写る画面を全部（約 90 枚）取り直し、ヘルプの記事と写真の［＋ 新しい議事録］を全部直します。議事録を録るのに1手増えます。
- **(c) Ctrl+N（Notion の近道）で同じ選びを開き、Ctrl+Shift+N は使わない。** 失うもの: 設計書 U3 の文と違うキーになります。
- **(d) 近道は作らない（もう一度後回し）。** 失うもの: 窓の中のキーだけで白紙のページを作れません。

**BQ8 白紙のページを、Claude（MCP）から読めるようにしますか？**
- **(a) 読めるようにする（おすすめ）。** 今の道具（一覧・箇所の検索・読む・ToDo）で議事録と一緒に読め、答えに「白紙のページ」と、中のページなら「場所: 親 / …」が付きます。理由: D57（見せない会議は無い）と同じ考えで、自分のメモやプロジェクトのページも Claude から探せます。失うもの: 道具の名前は「議事録（meetings）」のままです。答えの形が少し増えます（議事録だけの答えは今と同じ）。
- **(b) 0.15.0 では読めないようにする（議事録だけ。0.16.0 の Claude の書く道具の回で改めて決める）。** 失うもの: 白紙のページの中身を Claude から探せません。

**BQ9 アイコンの絵文字の辞書は、どのくらいにしますか？（U2。0.15.1）**
- **(a) よく使う絵文字 約 500 を、分類ごとに日本語の名前とよみ（ひらがな）で探せる自作の辞書にする（旗は入れない）（おすすめ）。** 理由: 名前とよみは NaTsu が自分で書くので、数が多いほど手間とテストが増えます。Windows の絵文字の書体で描けるものだけに絞れます。失うもの: 辞書に無い絵文字はアイコンにできません（文の中に打つことは Win+. でできます）。
- **(b) Unicode の絵文字の全部（約 1,900）を入れる。** 失うもの: 全部に日本語の名前とよみを書くのに時間がかかり、Windows で描けないものが混じります。
- **(c) 絵文字でなく、自作の SVG のアイコン（30 ほど）。** 失うもの: 絵文字で選びたい人に合いません。設計書の「絵文字の選択画面」と違います。
