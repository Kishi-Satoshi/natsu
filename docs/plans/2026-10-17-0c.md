**回の名前:** 第0c回（0c-1 = 0.3.0、0c-2 = 0.4.0）— 土台の入れ替え（設計書「第0c回 — 土台の入れ替え（Electron 31 → 44）」の EL0〜EL10）

**目的:** 議事録の DB（第2a1回）が使う `node:sqlite`・FTS5 trigram・`backup()` を、警告なしで使える Electron 44.9.0（Node 24.22.0・SQLite 3.53.4・Chromium 152）に入れ替える。そのために、
1. まず 0.3.0 を Electron 31 のまま自動更新で配る。クリップボード・画面の取り込み・ファイルの選択を 31 と 44 の両方で正しく動く形に直し、「入れ直しが要る版」をアプリが確かめた時点で見分けて「インストーラーで入れ直してください」と出せるようにする（EL0〜EL5）。
2. 次に 0.4.0 を Electron 44.9.0 と electron-builder 26.17.0 で作り、インストーラーで配る。CI の Node を 24 にし、配る exe で `node:sqlite`・trigram・`backup()` が動くことと、`utilityProcess`・口・sandbox の窓が動くことを、Windows の CI とリリースの流れで毎回確かめる。第0b回の取り込みを 44 で確かめ直す（EL6〜EL10）。
議事録・設定・エンジンとモデルは、入れ直しても残る（`%APPDATA%\natsu`・`%LOCALAPPDATA%\natsu\engine` はインストール先 `%LOCALAPPDATA%\Programs\NaTsu` と別）。

**方針（アーキテクチャ）:**
- **自動更新で入れ替わるのは `src/` だけ**（`updater.js` の `apply()`、updater.js:262-264）。だから Electron の版が変わる 0.4.0 は、自動更新では当てられない。今の門（`apply()` の `engines.electron` の確かめ、updater.js:250-259）は、**落としてから**断り、文に「Electron」と出る。0c-1 で、確かめた時点（`check()`）で見分ける道を足す。
  - `release.yml` がリリースに小さな `natsu-update.json`（`{ schema, version, electron, zip, sha256, size }`。`electron` は `package.json` の `engines.electron` の写し）を添える。
  - `check()` はリリースの資産からそれを読み、今の Electron（`process.versions.electron`）が `electron` の範囲を満たさなければ `reinstall: true` を返す。
  - 文を作るのは `updater.updateNotice(r, target)` の1か所だけにし、設定の画面・起動時の知らせ（左下の告知）・トレイの3か所が同じ文とボタン（［ダウンロード］）を出す。
  - `apply()` の門は「これより古い版のための最後の守り」として残し、文を同じ「入れ直してください」に替え、`reinstall: true` を返して、画面のボタンを［ダウンロード］に替えられるようにする。`natsu-update.json` の SHA-256 で、落とした zip も照らす。
- **0.2.0 のまま 0.4.0 を見た人も壊れない。** 0.2.0 の `check()` は `natsu-update.json` を知らないので「更新して再起動」を出すが、0.2.0 の `apply()` の門（#34）が `>=44.9.0` を満たさない zip を、`src/` を触る前に断る（今のテスト updater.test.js:324-397 が固定している）。だから 0.3.0 を先に行き渡らせるのは「分かりやすい案内」のためで、壊れないための唯一の守りではない。
- **実機の確かめ用の取得先（環境変数 `NATSU_UPDATE_FEED`）。** 今の `check()` は決まったリポジトリの `releases/latest` しか見ないので、0.4.0 を公開する前に知らせを確かめられない。下書き（draft）のリリースは、ログインしていない API からは見えない。そこで `NATSU_UPDATE_FEED` に次のどちらかを入れられるようにする。
  - 手元の `natsu-update.json` のパス（下書きのリリースのページから利用者が落としたもの、または手で書いたもの）。
  - `owner/repo` の形（テスト用のリポジトリの公開したリリース）。
  - この取得先のときは知らせを出すだけで、`apply()` は動かさない（取り違えた zip を当てないため）。`apply()` 自身も、`NATSU_UPDATE_FEED` があれば断る（二重の守り）。
- **クリップボードは mainlib へ移し、外から渡す。** Electron 44 では main でも `clipboard.readText()`／`writeText()` が Promise を返す（下の「調べた結果」の 2）。今の `copyPrivate` の読み返し（main.js:1272 `clipEquals(readClipboardText(), t)`）はいつも外れて Electron で書き直し、口述の文字が Win+V の履歴に残る。`deliverText` は `prev` に Promise を入れ、2秒後に `[object Promise]` を書き戻す（`restoreAfterPaste` は `String(prev)` を見る、mainlib.js:274-279）。`copyPrivate`・`deliverText` を `mainlib` の純粋な関数にし、`clipboard` と常駐 PowerShell と時計を引数でもらう。全部の読み書きを `await` する（31 では文字列を待っても害がない）。Promise を返す偽物と、文字列を返す偽物の両方で実行テストする。
- **画面の取り込みを断るときは `null`。** `callback({})` は 31 でも 44 でも main で `TypeError: Video was requested, but no video stream was provided` を投げる。`null` なら黙って断る（下の「調べた結果」の 3。作業環境で両方の版を本当に動かして確かめた）。
- **ファイルの選択は、今のファイルのフォルダ → この起動で前に選んだフォルダ → エンジンの置き場所、の順に開く。** Electron 43 から `defaultPath` が無いと「ダウンロード」が開き、OS が前のフォルダを覚えなくなる（「調べた結果」の 4）。画面からはパスを受け取らず、設定のキーの名前だけを受け取る（決まった5つのキーだけ）。
- **本体の取り込みは `node node_modules/electron/install.js` で行う（設計書の `npx install-electron --no` から意図して変えた）。** Electron 42 から `npm install` で本体が落ちてこない。`install-electron` という名前は 44 の包みの `bin` が `install.js` を指すだけで、中身は同じ（「調べた結果」の 5）。ところが 31 の包みにはこの `bin` が無く、npm の登録簿には **同じ名前の別の包み `install-electron@1.0.0` がある**（作業環境で 200 を確かめた）。0c-1 の起動の助けは 31 の上で動くので、`npx install-electron` だと、その別の包みを落として走らせるおそれがある。`node node_modules/electron/install.js` なら 31 でも 44 でも同じ道で、登録簿を見ない。CI とリリースも同じ書き方にそろえる。
- **起動の助けは `tools/get-electron.js` に寄せる。** `start-natsu.bat` と `create-shortcut.ps1` は、`electron.exe` が無いときだけ `node tools/get-electron.js` を呼ぶ。Node の版の確かめ（22.12 以上）と案内の文と本体の取り込みは、この1つの JS にあり、Linux の `npm test` で実行して確かめられる。JS は古い Node でも構文で落ちない書き方（`var`・`function`）にする。
- **`npm test` は外へつながない（0c-2 で守りを足す）。** Electron 44 の npm の包みの `index.js` は、Node から `require('electron')` されると、本体が無ければその場で落とす（`downloadElectron()`。「調べた結果」の 5）。今の `updater.js` の `httpFetch` は Electron の外でも `require('electron')` を試すので（updater.js:39-46）、`npm install` だけした開発の機械で `npm test` が 150MB を落としにいく。`process.type === 'browser'`（Electron の main）のときだけ `require('electron')` するように直す（Task 12）。
- **CI の Node は 24、出力は TAP に固定する。** Node 23 からテストの既定の出力が spec（`ℹ skipped 0`）になり、`ci.yml` の `^# skipped` の確かめが落ちる（作業環境の Node 24.22.0 で確かめた）。`npm test` に `--test-reporter=tap` を付ける（Node 22 でも同じ出力）。
- **配る exe を毎回確かめる。** `tools/sqlite-probe.js` を `ELECTRON_RUN_AS_NODE=1` で、`node_modules` の Electron と、electron-builder が詰めた `dist/win-unpacked/NaTsu.exe` の両方で走らせる。`tools/electron-smoke/`（小さなアプリ）で `utilityProcess`・`MessageChannelMain`・sandbox の隠れた窓・preload との往復・落として立ち直る・クリップボード・画面の取り込みを断る、を本物の 44 で動かす。Windows の CI では、テスト全部を Electron 44 の Node（`ELECTRON_RUN_AS_NODE=1`）でも回す（RF15。設計書では DB のテストを第2a1回から Electron で回すとしている。その土台を先に作る）。
- **`asar: false` は保つ**（自動更新が `src/` を入れ替えるため。repo.test.js の「パッケージ版でもアプリ内更新ができる設定」が固定している）。

2. **クリップボード（44）**（`https://github.com/electron/electron/blob/44-x-y/docs/breaking-changes.md` の「API Changed: `clipboard` module rearchitected to align with the W3C Clipboard API」と「Removed: `clipboard` module is no longer available in the renderer process」）
   - `clipboard.readText()` は `Promise<string>`、`writeText(text)` は `Promise<void>`。型の定義も同じ（44.9.0 の `electron.d.ts` の `readText(): Promise<string>;`。31.7.7 は `readText(type?): string;`）。
   - **作業環境で本物を動かした（Linux・xvfb）:** 44.9.0 では `writeText` が Promise、`readText` が Promise で `String(r)` は `[object Promise]`、待つと `abc`。31.7.7 では `writeText` が `undefined`、`readText` が文字列。
   - 画面（renderer）からの `clipboard` は 44 で無くなったが、NaTsu の画面と preload は `clipboard` を使わない（`window.koeApp.copy` → main の `clipboard:copy`、app.html:1111, :1730, :2111）。
3. **画面の取り込みを断るとき**（Electron の元のコード `shell/browser/electron_browser_context.cc` の `DisplayMediaDeviceChosen`。`https://github.com/electron/electron/blob/31-x-y/shell/browser/electron_browser_context.cc` と `.../44-x-y/...`）
   - `null` か `undefined` なら、例外を出さずに失敗で返す。`{}`（`video` が無い）は「Video was requested, but no video stream was provided」の `TypeError` を投げる。どちらの版も同じ。
   - 44 では、渡した `WebFrameMain` が壊れていると「video refers to a frame that has been destroyed」も投げる（44.9.0 の `electron.d.ts` の注釈「the callback throws if the frame has been destroyed」）。Electron 33 から `request.frame` が `null` のこともある（breaking-changes の「frame properties may retrieve detached WebFrameMain instances or none at all」）。
   - **作業環境で本物を動かした:** 31.7.7 と 44.9.0 の両方で、`callback({})` は main で上の `TypeError`、`callback(null)` は例外なし。画面の `getDisplayMedia` はどちらも `AbortError` で失敗する。
   - 45 からは画面の取り込みが `setPermissionRequestHandler` に `display-capture` として届く（breaking-changes の 45.0）。NaTsu はまだ許可の受け口を置いていない（第1a回の SEC1 で見込む。EL10）。
4. **ファイルの選択（43）**（breaking-changes の 43.0「Dialog methods default to Downloads directory」）: `defaultPath` が無いと「ダウンロード」（無ければホーム）で開き、OS が前のフォルダを覚えなくなる。前のフォルダは自分で覚えて渡すよう書いてある。
5. **本体の取り込み（42）**（breaking-changes の 42.0「`electron` no longer downloads itself via `postinstall` script」と、44.9.0 の包みの `install.js`・`index.js`・`cli.js`）
   - `npm install` では本体が落ちてこない。作業環境で `npm install electron@44.9.0` を実行し、`node_modules/electron/dist` が無いことを確かめた。`node node_modules/electron/install.js` で本体（`dist/`・`path.txt`）が置かれた。
   - `index.js` は `require` されると `path.txt` を読み、本体が無ければ `install.js` を `spawnSync` で走らせる（落とす）。`cli.js`（`npm start` の `electron .`）も同じ道を通るので、`npm start` は初回に自分で落とす。`start-natsu.bat` と `create-shortcut.ps1` は `dist\electron.exe` を直に指すので、無ければ動かない。
   - `install.js` は、`dist/version` が同じ版で本体があれば何もせず 0 で終わる（`isInstalled()`）。31.7.7 の `install.js` も同じ形（`postinstall` が済んでいれば何もしない）。
   - npm の登録簿の `https://registry.npmjs.org/install-electron` は 200（`latest: 1.0.0`。Electron の包みとは別物）。
6. **`node:sqlite`**（Node の文書 `https://github.com/nodejs/node/blob/v24.x/doc/api/sqlite.md`）
   - 22.13 から旗なしで使え、24.15.0 で「Release candidate」（Stability 1.2）。`backup()` は 23.8.0 で足された。24.14.0 から `defensive` が既定で有効。
