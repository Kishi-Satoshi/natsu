# ヘルプセンター 実装計画 — NaTsu のヘルプセンター（ログインの要る別のサイト。2026-10-20 の D22）

> **実装する人へ:** 1タスクずつ「落ちるテストを書く → 落ちるのを見る → 実装 → 通るのを見る → commit」の5手で進める。タスクごとに新しいエージェントが作り、別のエージェントが「計画どおりか」と「質」の2つを点検する（設計書「作り方」の 5）。
> **この計画は4つのレーンで作る**（下の「レーンと順番」）。B（作る道具）・C（記事）・W（門と出し方）・A（アプリの入口）。G（守りの仕上げ）は B・C・W の後。
> **前提と待つもの:**
> - B と C は今すぐ作れる（`help/`・`tools/help-build.js`・`tools/lib/help-*.js`・`test/help-*.test.js` は、アプリにも自動更新の zip にも入らない）。
> - W（H-9・H-10）は **0.8.0 の統合を待つ。** 門は第1d回の `relay/access.mjs`（Access の JWT の確かめ）をそのまま使い、写さない。`relay/access.mjs` は作業ブランチ `claude/new-session-wy0ks5` の先頭 `c3e1b6f`（第1d回 G-3 の点検の直し）に入っている。このレーン（`lane/help`）は `de033ce` から作ったので、H-9 の前に作業ブランチの先頭へ載せ直す。H-9 を始める前に、下の「受け渡す名前と形」の `requireAccess`・`readConfig` の形が作業ブランチと同じかを確かめ、違えばこの計画を先に直す。

> - 設計書（`docs/plans/natsu-design.md`）は行番号では指さず、見出しと記号（D22・HC0・RF45 など）で指す。

**回の名前:** ヘルプセンター（記号 H。設計書「回の一覧」の段階A の H・「利用者が決めたこと（ヘルプセンター。2026-10-20）」の D22・「回をまたぐ決まり」の「ヘルプセンター」の HC0・HC2）

**目的:**
1. **NaTsu の使い方を、50人が自分で調べられるようにする。** Notion のヘルプセンターに寄せた並び（大きな検索・分類のカード・記事の左の目次・パンくず・このページの内容）で、見た目はシンプルにする（利用者の決定: 「Notionのヘルプには寄せたいですが、分かりやすさを重視してシンプル設計にはしたいです。」）。
2. **ログインした会社の人だけが読める。** 出したサイトは Cloudflare Access（中継と同じ Zero Trust の組織・同じ One-time PIN）の後ろに置き、Worker も Access の札（JWT）を自分で確かめてから中身を返す。ログインしていない人には、記事の文字を1字も返さない。
3. **記事がアプリと食い違わない。** 記事に書いた NaTsu の画面の言葉（［…］）がアプリのコードにちょうどあるかを、テストで毎回確かめる。記事ごとに「確かめた元」（ファイルの名前）を持たせる。
4. **記事の中の文字で画面を壊さない・人をだまさない。** 記事は小さな決まった Markdown だけを受け、生の HTML・`javascript:` のリンクは出し方の前に止める。
5. **アプリから1回で開ける。** サイドバーのいちばん下に［ヘルプ］を置き、既定のブラウザで開く（0.8.0 を出した後）。

**方針（アーキテクチャ）:**
1. **記事の元はこのリポジトリの `help/`**（`src/` の外。インストーラー（`build.files` は `src/**/*`・アイコン・`package.json`）にも自動更新の zip（`src` と `package.json`）にも入らない）。記事は `help/articles/<分類>/<名前>.md`、分類と並びは `help/site.json`、見た目は `help/assets/`。**リポジトリは公開なので、記事の元は誰でも読める**（ログインで守るのは出したサイトだけ。記事に会社の固有の情報を書かない: 問い Q1）。
2. **サイトを作る道具は Node だけで、npm の依存を足さない**（`tools/help-build.js` と `tools/lib/help-md.js`・`tools/lib/help-page.js`）。Markdown は小さな決まった形だけを受ける（下の「記事の書き方」）。出力は `help/dist/`（`.gitignore` の `dist/` がもう外している）。同じ元からは何度作っても同じバイトになる（日付は記事の `updated` だけ）。
3. **見た目は NaTsu の N1 の色と文字**（設計書の「N1 の色の値」と N1 の書体の並び）。明暗は `prefers-color-scheme` だけ。本文の幅は約 720px。スマホの幅（390px）でも横にはみ出さない。キーボードの輪が見える。文字と地の濃さの差は 4.5:1 以上。Notion の CSS・アイコン・画像・文は使わない（並び方の考え方だけ）。アイコンは自作の SVG、ロゴは `assets/icon.svg` を写す。
4. **検索は PC の中（ブラウザの中）だけ。** 作るときに `search-index.json` を書き、`help/assets/search.js`（別のファイル。インラインの script は使わない）が NFKC と小文字にそろえた部分一致で、題名 > 見出し > 本文の順に並べる。
5. **置き場所は Cloudflare Workers の静的な資産（static assets）。** Worker `natsu-help` を、今の workers.dev のサブドメインに出す（`https://natsu-help.natsu-code.workers.dev`）。Worker を先に走らせ（`run_worker_first: true`）、Access の JWT を `relay/access.mjs` の `requireAccess` で確かめてから資産を返す（`relay/help-gate.mjs`）。設定がそろっていなければ 503 の「準備中」（記事の文字なし）。だから、利用者が Access を有効にする前の1回目の出し方でも中身は漏れない。
6. **出し方は wrangler を使わず、Cloudflare の REST API**（`tools/help-deploy.js`。`tools/relay-deploy.js` と同じ形・同じ出力の守り。共通の部品は `tools/lib/cf-api.js` に出す）。最後に、**ログインしていない GET で中身が返らないこと**を確かめ、返れば赤で止める。GitHub Actions の `help-deploy.yml`（手で押すか、main に `help/**` などの変更が入ったとき。main だけ。環境 `relay`）。
7. **アプリの入口は固定の URL だけ。** 画面は URL を渡さず、main が決まった `HELP_URL` を `shell.openExternal` で開く（今の［リリースを開く］と同じ形）。

**使うもの:**
- Cloudflare Workers の静的な資産（資産の上げの session・バケットの上げ・Worker のスクリプトの `assets` の設定と `ASSETS` のバインド。https://developers.cloudflare.com/workers/static-assets/direct-upload/ ・https://developers.cloudflare.com/workers/static-assets/binding/ を 2026-10-20 に読んだ）・workers.dev・Workers の秘密の欄・D1（中継の D1 を読むだけ）。
- Cloudflare Access（Worker 単位の Access・One-time PIN・決まり。第1d回の「調べた結果（2026-10-20）」のとおり）。
- Node 24（CI）と Node 22（手元）: `node --test`・`node:crypto`（資産の指紋）・`node:http`（偽の Cloudflare の API・テストの台）・グローバルの `fetch`／`FormData`／`Blob`（出す台本とテストだけ）。
- 画面の写真: 作業環境に入っている Chromium（`/opt/pw-browsers/chromium-1194`）と、作業環境に入っている Playwright（リポジトリの依存ではない。`tools/help-shots.js` が場所を環境変数で受ける）。
- npm の依存は足さない（道具にも門にも出す台本にも）。

**設計書:** `docs/plans/natsu-design.md`
- 「全体を通して守ること」（下にそのまま写した）。
- 「目的」の「1.0.0 の問い合わせ」（この計画と同じ commit で改めた）と、「利用者が決めたこと（ヘルプセンター。2026-10-20）」の D22。
- 「利用者が決めたこと（ログインと画面の言葉。2026-10-20）」の D18（Access の One-time PIN・決まりの形・会社のドメインはリポジトリに書かない）。

**全体の決まり（設計書「全体を通して守ること」からそのまま写す。この計画に効くもの）:**
- **録音バー:** `overlay.html` は触らない。例外は第0回の `<title>Listener Overlay</title>` の文字の置き換え1か所だけ。
- **Notion の資産:** デザイン資産・ロゴ・コードは使わない。フォントは OS 標準、アイコンは絵文字か自作の SVG。
- **Notion の考え方の扱い:** 考え方だけを参考にし、名前と実装は NaTsu のものにする。参考にしてよいのは、公開されている資料（ヘルプセンター・公式 API・公式ブログ）と、画面の外から見て分かる動きだけ。利用者が自分の PC で調べて作った試作（PoC）からは、Notion 以外の公開資料（Electron・SQLite・Node の公式資料）に同じ形が書いてある仕組みか、今の NaTsu のコードにすでにある形だけを採る。公開資料で説明できない形・名前・値（例: 間引きの秒数、会議の区画や状態の名前）は採らない。アプリの中を調べて分かった名前（モジュールの名前・設定の名前・内部の値）は、コードにも文書にも書かない。コードのコメントに「Notion は〜」と書かない。利用者の試作（PoC）のコードは、許しがあっても貼らず、落ちるテストから書き直す。
- **アプリの依存:** npm の依存を足さない。サーバー（`server/`）だけは Bedrock 用 SDK を使ってよい。
- **公開前の確認:** 個人名・社名・会社のドメイン・個人のパスをコードに残さない。会社のドメインはサーバーの環境変数にだけ置く。
- **テストデータ:** 実在の人名を使わない。出典リンクを LLM に作らせない。日付を推測で埋めない。

この計画で足す決まり: 記事にも上の3つ（公開前の確認・テストデータ・日付）を守る。記事の `updated` は、書いた人がその日の本当の日付を書く（推測で埋めない）。チームの名前・AUD のタグ・会社のドメインは記事にも書かない（`<チームの名前>` のように書く）。

## 記事の書き方（H-2 が受ける形。C のタスクはこの形で書く）

````markdown
---
title: 録音を一時停止する
description: 会議の途中で録音を止めて、また始める方法
updated: 2026-10-21
sources: src/renderer/app.html, README.md
related: record/start-stop, record/status-line
---

録音中のページの ［⏸ 一時停止］ を押すと……（段落。行をまたいだ文はつなぐ）

## ホットキーで止める {#hotkey}

[[Ctrl+Shift+P]] でも一時停止できます。**もう一度押すと再開**します。

- 箇条書き
  - 1段だけ入れ子にできる
1. 番号の付いた手順

> [!NOTE]
> メモの枠（NOTE＝メモ・TIP＝ヒント・WARNING＝注意）

| 表の見出し | 見出し |
| --- | --- |
| セル | `コード` |

![代わりの文](assets/img/example.png)

[ログインする](start/login.md)・[同じページの見出しへ](#hotkey)・[外のページ](https://example.com/)

```
コードの塊（SQL など。色付けはしない）
```
````

- **前置き（front matter）:** `title`（60 字まで）・`description`（100 字まで）・`updated`（`YYYY-MM-DD`。書いた日の本当の日付）・`sources`（確かめた元。リポジトリの中のファイルの名前を `,` で区切る。1つ以上）は必ず。`related`（`分類/名前` を `,` で区切る。3つまで）はあってもなくてもよい。ほかの鍵は止める。
- **見出し:** `##` と `###` だけ（`#` は題名が担う。`####` から下は止める）。`{#id}`（`[a-z0-9-]{1,40}`）を付けた見出しだけに、リンクで飛べる。付けない見出しの `id` は `s1`・`s2`… の順（飛び先にしない）。
- **段落:** 空の行で区切る。行をまたいだ文は、つなぎ目の前後のどちらかが ASCII でなければそのまま、両方 ASCII なら空白1つでつなぐ。
- **文中:** `**太字**`・`` `コード` ``・`[[キー+キー]]`（`<kbd>` に分ける）・`［画面の言葉］`（NaTsu の画面の言葉だけ。R9）。`*` 1つ・`_` は飾りにしない（そのまま文字）。
- **リスト:** `- ` と `1. `。入れ子は1段まで（2つより多い空白の字下げ）。2段目の下はさらに入れ子にできない（止める）。
- **注意の枠:** `> [!NOTE]`・`> [!TIP]`・`> [!WARNING]` の行から始まる `>` の続きだけ。印の無い `>` は止める。
- **表:** 頭の行・`---` の行・本文の行。セルの中は文中の形だけ。
- **画像:** `assets/` で始まり、`help/assets/` の中に本当にある `.png`・`.svg` だけ。代わりの文は必ず。初めの版では使わない（Q2）。
- **リンク:** 記事は `分類/名前.md`（と `#id`）、同じページは `#id`、外は `https://` だけ（新しいタブにしない・`rel="noreferrer"`）。リンクの文は空にしない。
- **止めるもの（作るのを止め、ファイルの名前・行・符号を出す）:** 生の HTML（コードの外の `<` の後に英字・`/`・`!`・`?`）・`javascript:`／`data:`／`http:`／`mailto:`／`//` のリンク・無い記事や `#id` へのリンク・形の違う前置き・上の形の外の書き方（`#`・`####`・3段のリスト・印の無い `>`・閉じていない `**` やコードの塊）。
- 改行は CRLF でも LF でも同じに読む（Windows の CI の取り出しは CRLF になりうる）。BOM は外して読む。

## 利用者の用意（Cloudflare の画面で。上から順に）

第1d回の利用者の用意（Cloudflare のアカウント・Zero Trust の組織とチーム・One-time PIN・API トークン・GitHub の環境 `relay`）は済んだものとして続ける。新しいトークンも新しい環境も要らない（R5）。鍵やトークンは、メモ帳・チャット・メールに貼らず、作った画面からそのまま次の画面へ貼る。会社のドメイン・チームの名前・AUD は Cloudflare の画面にだけ入れる。

**待つもの:** H-1〜H-11 が main に入り、写真の OK をもらった後（下の「レーンと順番」の 10）。

0. **1回目を出す:** GitHub の［Actions］→［help-deploy］→［Run workflow］（main を選ぶ）→ 緑で、最後の行が「準備中（Access の app と秘密の欄がまだ。利用者の用意の 1〜5）」。ブラウザで `https://natsu-help.natsu-code.workers.dev/` を開くと「NaTsu ヘルプセンターは準備中です。…」だけが出る（記事は見えない）。
1. **natsu-help を Worker 単位の Access で守る:** ［Workers & Pages］→ `natsu-help` →［Access］のタブ →［Protect this Worker behind Access］→「All traffic」→「Authentication policy」は「Email domain」にして会社のドメイン（`@` の後ろ）を入れる →［Apply Access］。
2. **決まりを中継と同じ形にする:** ［Zero Trust］→［Access controls］→［Applications］→ `natsu-help` の app の［Configure］。
   - 「Policies」で 1 で作った決まりを開き、Include が「Emails ending in」`@<会社のドメイン>` だけであることを見る（ほかの Include があれば消す）。

   - 同じ決まりの「Session duration」が「Same as application session timeout」であることを見る →［Save］。
3. **ログインの長さ:** 同じ app の「Overview」の「Session Duration」を「1 week」（7 日）にする（R6）。「Cookie settings」は既定のまま（Binding Cookie を有効にしない）。
4. **AUD のタグを見る:** 同じ app の「Additional settings」の「Application Audience (AUD) Tag」（64 字）。**中継（`natsu-relay`）の AUD とは違う**。5 のときに、この画面をもう一度開いてコピーする。
5. **Worker の秘密を入れる:** ［Workers & Pages］→ `natsu-help` →［Settings］→［Variables and Secrets］。どれも種類は「Secret」（「Text」にすると次の出し直しで消える）。

   - ［Deploy］を押す。
6. **2回目を出す:** ［Run workflow］→ 緑で「Access に守られています」。続けて下の「実機で利用者に見てもらうこと」の 1。

## 実機で利用者に見てもらうこと

**1. 出した後（利用者の用意の 6 の後）— 会社の PC から**
1. 会社の PC の Edge の InPrivate の窓で `https://natsu-help.natsu-code.workers.dev/` を開く → 英語のログインの画面（中継と同じ頭と足の日本語）。住所の欄が `<チームの名前>.cloudflareaccess.com`。

3. 検索の箱に「一時停止」→ 結果の一番上が「一時停止と再開」。↓ と Enter で開ける。Esc で閉じる。
