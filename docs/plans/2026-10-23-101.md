## 目的

1. NaTsu の設定のカードは「登録済み」と出たのに、Microsoft Store 版（MSIX）の今の Claude デスクトップに natsu が出なかった。
2. Claude デスクトップの［設定］→［開発者］→［設定を編集］が開いたのは `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc\claude_desktop_config.json`（`claude_` は小文字。後ろはパッケージの符号）。

## 方針

1. **直すのは場所の探し方（と、その確かめと記録）だけ。** 状態の決め方（全部の悪い方）・断り方・控え・知らせ・画面の文は 0.10.0 のまま（D80）。
2. **場所は main だけが決め、画面にも記録にもパスを出さない**（0.10.0 の方針 7・決めたこと 26 のまま）。記録には場所の種類の数だけを足す。
3. **Claude デスクトップがどのファイルを読むかを NaTsu は確かめられない。** 当て推量の1つに決め打ちせず、Claude が読みうる場所の全部を見て、全部にそろえる（問い Q1 の勧め）。だから「どれを読むか」が外れても、「登録済み」と言うのは、どの場所にも NaTsu の項目があるときだけになる。
4. **他のアプリのファイルは、NaTsu の1項目のほかを1つも変えない**（RF61）。

## 決めたこと（理由つき。違う答えなら直す）

1. **探す場所は3つの種類**（勧めの問い Q1 の (a) で）:

2. 前の場所の印のファイル（`.user-data-left.*`・`.user-data-back.*`）の名前と意味は第三者の読み解き。持ち主の PC の前の場所に何という名前のファイルがあるかを見ていない（問い Q4）。
3. `Claude-Data` の下に `claude_*` が2つ以上できるか（入れ直し・ベータ版・別の発行元）は分からない。2つあれば両方に書く。
4. Store 版の Claude の実行ファイルが `claude.exe` か（0.10.0 からの分からないこと。実機 5）。
5. 新しい場所の記録のフォルダ（実機 7）。
6. `userDataOutsidePackageAnswer` の意味（「パッケージの外にデータを置くか」の答えと読めるが、資料が無い）。`false` の PC では前の場所を読むのかもしれない。全部に書く形なら、どちらでも効く。
7. Claude デスクトップが動いている間に新しい場所のファイルを書き戻して natsu を消すか（Review Focus 1・実機 6）。
8. 持ち主が渡した新しい場所の写しに natsu が無かった理由（手で足す前か、後で外したか）。
9. Claude デスクトップが、将来また場所を変えるか（`Claude-Data` の名前の形が変わる・`%APPDATA%` に戻る）。変われば、また「登録済みなのに出ない」になりうる。そのときに気づける道は、持ち主の目と［設定を編集］だけ（NaTsu は Claude の読む場所を知らない）。
10. 直のインストーラー版と Store 版の両方が入った PC で、どちらがどこを読むか。全部に書くので、どちらでも効く見込み。

## 持ち主に確かめること（ソクラテス式の問い。勧めを先に。答えが来るまでは作らない）

**Q1. NaTsu はどの場所に書き、どう「登録済み」を決めますか。**
- **(a)【勧め】見つけた全部（新しい場所・前の場所・%APPDATA%\Claude）に書き、全部にそろったときだけ「登録済み」。** 理由: Claude がどれを読むかを NaTsu は確かめられません。全部に書けば、当て推量が外れても、Claude が読むファイルに登録があります。「登録済み」と出るのは、どの場所にも登録があるときだけなので、今回のように「登録済みなのに出ない」は起きにくくなります。0.10.0 の「見つけた Store 版の場所にも書く」の考えを伸ばすだけで、コードの変わる所が小さいです。失うもの: Claude が読まない古いファイルにも書きます。古いファイルが壊れていると、新しい場所にも書けず「設定ファイルを読めません」と出ます（［設定を編集］で開くファイルは正しいので迷います）。
- **(b) Claude が今読む1つを、前の場所に残る印のファイルで決め、そこにだけ書き、そこだけで「登録済み」を決める。** 理由: Claude が読まないファイルに触れません。古いファイルが壊れていても登録できます。失うもの: 印の名前と意味は第三者の読み解きで、外れると 0.10.0 と同じ「登録済みなのに出ない」がまた起きます。印を読むコードとテストが増えます。
- **(c) 新しい場所があれば新しい場所だけ、無ければ今の場所。** 理由: 一番簡単です。失うもの: Claude が前の場所に戻ったとき（報告にある印 `.user-data-back`）や、新しい場所のフォルダだけがあって Claude がまだ移っていないときに外れます。

**Q2. 0.10.0 で前の場所にだけ登録した人（持ち主のほかの PC・これから入れる人）に、何と出しますか。**
- **(a)【勧め】今の「Claude デスクトップへの登録が消えています。［設定を開く］で［登録し直す］を押してください。」と、カードの［登録し直す］のまま。** 理由: 画面の文を変えない（D80）ので、取り直しの画像も要りません。押せば新しい場所にも入ります。失うもの: 本当は「消えた」のではなく「Claude が読む場所が変わった」ので、文が少しずれます。
- **(b) 新しい状態「Claude デスクトップの設定の場所が変わりました」と新しい知らせを足す。** 理由: 何が起きたかが正しく伝わります。失うもの: 画面の文が増え（D80 の「直しだけ」から外れる）、どの場所が「新しい」かを NaTsu が決めることになり（Q1 の (b) に近づく）、テストと取り直しが増えます。
- **(c) 起動のときに黙って新しい場所にも書く。** 理由: 押さなくて済みます。失うもの: 0.10.0 の決まり「ほかのアプリの設定を黙って変えない」（決めたこと 151）を破り、Claude が動いている間に書いてしまうことがあります。

**Q3. Claude デスクトップが動いているときに［Claude デスクトップに登録］を押したら、どうしますか。**
- **(a)【勧め】0.10.0 のまま、カードの頭に「Claude デスクトップが動いています…」と出し、登録はする。** 理由: 0.10.1 は場所の直しだけ（D80）。書いた後の読み直しで、書く間に Claude が書き換えたら「今は読めませんでした…もう一度押してください」と断るようにします（決めたこと 9）。失うもの: 書いた後に Claude が古い中身で書き戻すと、次の起動の「登録が消えています」まで気づけません。
- **(b) 動いていれば書かずに断る。** 理由: 新しい場所のファイルは Claude が使うたびに書くので、書き戻しの心配が減ります。失うもの: 動いているかが「分からない」PC（Store 版の実行ファイルの名前が違うなど）の扱いを決め直すことになり、画面の文も変わります（D80 から外れる）。

**Q4. 作る前に、持ち主の PC の3つのフォルダの中のファイルの名前を見せてもらえますか（中身は要りません）。**
