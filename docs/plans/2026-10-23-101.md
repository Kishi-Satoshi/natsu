## 目的

持ち主が 0.10.0 を自分の PC で試した（2026-10-23）。

1. NaTsu の設定のカードは「登録済み」と出たのに、Microsoft Store 版（MSIX）の今の Claude デスクトップに natsu が出なかった。
2. Claude デスクトップの［設定］→［開発者］→［設定を編集］が開いたのは `%LOCALAPPDATA%\Claude-Data\claude_pzs8sxrjxfjjc\claude_desktop_config.json`（`claude_` は小文字。後ろはパッケージの符号）。
3. その PC には `%APPDATA%\Claude` が無い。NaTsu 0.10.0 は前の Store 版の場所 `%LOCALAPPDATA%\Packages\Claude_pzs8sxrjxfjjc\LocalCache\Roaming\Claude\claude_desktop_config.json` にだけ書いていて、今の Claude デスクトップはそこを読まない。
4. 新しい場所のファイルには `preferences.userDataOutsidePackageAnswer: true`（場所を移したときの印と見られる）と、ほかの多くの鍵がある。全部を残さなくてはならない。
5. 持ち主が新しい場所のファイルへ手で natsu の項目を写すと、natsu は動いた。手で貼り損ねたときは、Claude デスクトップにサーバーが1つも出なかった（**壊れた JSON は全部のサーバーを隠す**）。

この版で:

- **A. 場所:** NaTsu は新しい場所（`%LOCALAPPDATA%\Claude-Data\claude_<符号>\`）にも登録し、見つけたどの場所にも NaTsu の項目がそろっているときだけ「登録済み」と言う（D82）。
- **B. 動いている間は書かない:** Claude デスクトップが動いているときは、登録・外す・登録し直すのどれも書かずに断り、「終了してから、もう一度押してください」と出す（D84）。動いているかを確かめられないときは、1回目は断り、続けて2回目に押したら書く（D85）。
- **C. 起動のときに黙って登録し直す:** 前に登録した人で、登録が欠けた・古くなった場所があれば、Claude デスクトップが終了していて、どのファイルも書ける形のときだけ、NaTsu の起動のときに黙って登録し直す（D83）。Claude デスクトップが動いている（か分からない）ためにできないときは、新しい知らせ「…Claude デスクトップを終了してから［登録し直す］を押してください…」（RN4。D86）。ほかの理由でできないときは今の知らせ。0.10.0 で前の場所にだけ登録した人は、これで新しい場所にも入る。

## 方針

1. **直すのは場所の探し方と、書いてよいときの決まり（D84）と、起動のときの書き直し（D83）。** 状態の決め方（全部の悪い方）・壊れたファイルの断り方・控えは 0.10.0 のまま。
2. **場所と、書く・書かないは main だけが決め、画面にも記録にもパスを出さない**（0.10.0 の方針 7・決めたこと 26 のまま）。記録には場所の種類の数だけを足す。
3. **Claude デスクトップがどのファイルを読むかを NaTsu は確かめられない。** 当て推量の1つに決め打ちせず、Claude が読みうる場所の全部を見て、全部にそろえる（D82）。
4. **他のアプリのファイルは、NaTsu の1項目のほかを1つも変えない**（RF61）。Claude が動いている間は、Claude のファイルに書かない（D84）。

## 決めたこと（理由つき。違う答えなら直す）

1. **探す場所は3つの種類**（D82）:
   - **Roaming:** `%APPDATA%\Claude` があれば、そこの `claude_desktop_config.json`（0.10.0 のまま）。
   - **Claude-Data（新）:** `%LOCALAPPDATA%\Claude-Data` の直の子のうち、**フォルダ**で、名前を小文字にすると `^(anthropic\.)?claude_[a-z0-9]+$` に合うもの全部の `claude_desktop_config.json`（`README.txt` などのファイルは場所にしない）。
   - **Packages:** `%LOCALAPPDATA%\Packages` の子のうち、名前を小文字にすると `claude_`・`anthropic.claude_` で始まり、`LocalCache\Roaming\Claude` があるもの（0.10.0 のまま。照らしだけ大文字と小文字を区別しなくする）。
   理由: 新しい場所は持ち主の PC と公開の報告の両方で確かめた。前の場所と Roaming は、まだ移っていない Store 版・直のインストーラーの Claude が読む。
2. **書くのは見つけた全部**（D82）。外すときも全部から NaTsu の印のある項目だけを外す。理由: Claude がどれを読むかを確かめられない（方針 3）。全部に書けば、当て推量が外れても Claude が読むファイルに項目がある。前の場所の natsu は Claude が読まなくても、同じ中身なら害が無く、Claude が前の場所へ戻ったとき（`.user-data-back` の印）にもそのまま効く。失うもの: Claude が読まない古いファイルにも書く。古いファイルが壊れていると、新しい場所に書けない（決めたこと 11）。困りごとが出たら、印で選ぶ形へ切り替える（「持ち主の PC のフォルダーの名前」の 1）。
3. **状態は全部のファイルの悪い方**（0.10.0 のまま: 調べた結果の 3）。「新しい場所に無い・前の場所にある」は `none`（前に登録した印があれば `gone`）で、「登録済み」とは言わない。
4. **起動のときに黙って登録し直す**（D83。**0.10.0 の決めたこと 151 を意図して変える**。条件はコーディネーターの案。持ち主は問い Q8 で「案に足して RN4 を出す」(b) を選んだので、条件は案のまま決まった: D86）。`checkMcpRegistration()`（起動の後に1回だけ。だから試すのは起動ごとに1回）で:
   1. ファイルごとの状態を読む（書かない）。
   2. 書き直すのは、次の全部がそろうときだけ:
      - (i) 前に登録した印 `settings.mcpRegisteredFor` がある（登録したことの無い人・外した人には書かない）。
      - (ii) どれかのファイルが `none`（項目が無い）か `stale`（印のある古い項目）で、ほかのファイルは `same`・`none`・`stale` のどれか（`broken`・`busy`・`other`・`readonly` が1つも無い。`other` の項目には決して触れない）。
      - (iii) Claude デスクトップが動いていない（`tasklist` の答えが `false`。「分からない」（`null`）は動いているとみなす）。`tasklist` を見るのは (i)・(ii) がそろったときだけ（ふだんの起動で `tasklist` を起こさない）。
   3. そろえば、［Claude デスクトップに登録］と同じ書き方（`mcpApply(true)`。控えを取る・全部の中身を読み直して確かめる・登録の印を書き直す）で書く。記録は今の数だけの行と、場所の1行（頭に「起動のとき」を付ける: 決めたこと 13）。**できたら知らせを出さない。**
   4. そろわない・書けなかったら知らせる（どれも［設定を開く］で項目「要約」。カードは今どおり［登録し直す］）:

   理由: 持ち主の答え。0.10.0 で前の場所にだけ登録した人は、押さずに新しい場所にも入る。失うもの: ほかのアプリの設定を、利用者が押さずに書く（控えは残る）。Claude デスクトップはログオンで自動で起動することが多いので、NaTsu の起動のときに Claude が動いていて、書き直せずに知らせに戻ることが多い見込み（Review Focus 7）。

   - 動いている（`true`）→ 書かずに `{ ok: false, state: <今の状態>, code: 'running', running: true }`。

   - 見つけた場所が無いとき（`noclaude`）は `tasklist` を見ずに今どおり `noclaude` で断る。
   - 記録は `MCP の登録: 断った（running）（ファイル N・控え 0）`・`断った（unknown）`（今の形。符号は小文字の英字）。2回目で書いたときは、今の数だけの行の前に `Claude デスクトップの確かめ: 動いているか分からないまま、2回目の押しで書きます` の1行（頭を「MCP」にしない）。
   理由: 持ち主の答え。Claude が動いている間に書くと、Claude が古い中身で書き戻して natsu を消しうる（試作から参考にしたことの4行目）。`tasklist` がいつも失敗する PC（会社の決まりで止められているなど）でも、2回押せば登録も外すこともできる（D85）。失うもの: 2回目の押しでは、本当に動いていても書く（RN2 で「終了してから」と頼んだ後なので、利用者が終了した見込みに頼る）。Store 版の実行ファイルの名前が `claude.exe` でなければ、動いていても「動いていない」と見えて1回目で書いてしまう（実機 5）。
9. **書いた後の確かめを広げる:** 書いた全部のファイルを読み直し、**読んだ中身が書いた中身とちょうど同じ**（`isDeepStrictEqual`。natsu の項目もほかの鍵も）かを見る。違えば `busy` で、登録の印を書き換えない。登録でも外すときでも起動のときの書き直しでも確かめる。理由: 書く直前に `tasklist` を見ても、その後に Claude が起動して書くことはありうる。natsu 以外の鍵の違いで見つけられる。控えは書く前に取ってあるので戻せる。
