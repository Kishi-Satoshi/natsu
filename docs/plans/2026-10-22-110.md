## 目的

1. **会議の種類を選ぶと、メモの型も決まる**（D42）。欄は「会議の種類」の1つ。「一般・その他」は無くなり、決まらない会議は「自動」のまま会議の要点の型でまとめる（P12）。並びは 自動（文字起こしから判定）→ ─ 社内の会議 ─ 朝会・内部定例会／部会・報告会／ブレスト・意見交換 → ─ 人と話す ─ 1on1／採用面接・事前面談 → ─ 社外と話す ─ 商談／プレゼン形式（`<optgroup>`。D43・D44）。横に灰色の小さな字で「メモの型: {型の名前}」。
2. **見出しはメモが空のときだけ入れる。** 種類を選んだとき、メモが空か手を付けていない雛形ならその型の見出しを入れ、人の文があれば1文字も変えない。見出しごとのヒントはメモ欄の上の灰色の手引きに出し、本文に入れない。
3. **録音中のページでも種類を選べる**（D50）。初めは「自動」のまま。選ぶとメモのタブに切り替わり、入った見出しが見える（P17）。メモが空の間は一言「会議の種類を選ぶと、メモに見出しが入ります」。選んだ種類は締めにも、落ちた後の戻しにも残る。
4. **要約が型の見出しで埋まる。** 見出しごとに文字起こしの根拠へ飛べる出典（今の `cite.js` の流れ）。根拠の無い見出しは本文に出さず、抜け・重なりチェックに「未確認: {見出し}」とまとめる（D39）。メモにだけある話は「（メモより）」。
5. **どの要約も締めは同じ:** 決定事項・持ち越し（無ければ省く: D46）・ToDo（誰が・何を・いつまでに。分からなければ画面で「要確認」）・抜け・重なりチェック（未確認の1行と、3件まで）。その後に「次に気をつけること」（1〜2 行の助言。D49。人を評価しない）。
6. **打ち合わせの質を 25 点で出す**（D33）。5 つの軸のうち 3 つを AI が、2 つを NaTsu が数える（P8）。1on1 と採用面接・事前面談にも既定で付ける（P11。設定で「1on1 と採用面接・事前面談を除いて付ける」「付けない」を選べる）。点はページの欄に持ち、読み取りだけのカード。
7. **画面は読む人の順**（D48）。決定事項・持ち越し・ToDo → 型の見出し → 抜け・重なりチェック → 次に気をつけること → 打ち合わせの質。［コピー］も同じ順。保存の順と AI に書かせる順は変えない。
8. **要約・点・助言は Claude Code だけ**（D59）。オフラインモードの会議も、つながったときに同じに作る（D62）。
9. **Claude から読める**（0.10.0 の MCP の道具に、メモの型・点・助言・種類の経過を足す: T-6）。点の流れは Claude に頼んで読む（D47）。

## 決めたこと（0.11.0。理由つき。違う答えなら直す）

**A. 会議の種類とメモの型**

1. **型は会議の種類から決まる（D42）:** `memoTypeOf(meetingType)`（`DEFAULT_MEMO = { standup: 'report', review: 'report', brainstorm: 'points', oneonone: 'grow', interview: 'star', sales: 'bantc', present: 'present' }`。決まらない（`''`）・前の版の `general`・知らない種類は `points`）。型を別に選ぶ欄・`memoTypeAuto`・`page.setMemoType` は作らない。ページは型を欄に持たず、種類から毎回決める（種類と型がずれることが無い）。

3. **欄の名前は「会議の種類」**（D42 の言葉。今は「要約タイプ」）。ページの行の名前・`aria-label`・知らせの文・ヘルプの記事も「会議の種類」にする。替えたときの知らせは MQ2 か MQ3 の1つだけ（今の「要約タイプを変更しました…」は MQ3 に入る）。

6. **「メモの型: {名前}」**（D42）: 種類の欄の横の灰色の小さな字。種類が決まっていれば `memoTypeOf` の名前、決まらなかったときは「メモの型: 会議の要点（論点整理）」、「自動」で要約の前は「メモの型: 要約のときに決まります」。
7. **「手を付けていないメモ」の決め方（`isUntouchedMemo(memo, legacy)`）:** メモが空白だけか、どれかの型の雛形か今のアジェンダの雛形（`TYPES[*].agenda`）と、行ごとに `trim` して空の行を除いて完全一致なら手を付けていないとみなす。人の文が1文字でもあれば変えない。画面は手引きと一言を出すかを決めるためだけに同じ決まりの写し（`app.html` の `untouchedView`）を持ち、`repo` が同じ表で照らす（当て直し 15）。

17. **未確認（D39）:** 型の見出しで根拠の無いものは本文に見出しごと出さない。抜け・重なりチェックの頭に1行「未確認: {見出し}、{見出し}」（`mark: 'check'`・`unconfirmed: true`）。チェックの残りは 3 件まで（`CHECK_MAX = 3`。未確認の1行は数えない。4 件目からは捨て、`engine.log` には数だけ）。決まりの文で「未確認」などの語を「」で囲まず、行の終わりを（…）にしない（`dropTemplateEcho` の鍵（`templateKeys`: `src/minutes.js:203`）は「」の中と行末の（…）を外した形なので、その語だけの本物の行が要約から落ちる）。BANTC は行の頭に 確定・見込み。
18. **AI が根拠の無い見出しを書いてきたときの畳み（新しい。D39 を守る）:** AI が型の見出しを書き、その下の行が全部「未確認」「言及なし」「特になし」「会議内で言及なし」だけ（行頭の `-`・`**`・「見出しの名前:」と行末の（…）を外して完全一致）なら、`markBlocks` がその見出しと行を本文から外し、見出しの名前を未確認の1行に足す（1行が無ければ作る）。人の文らしい行（「未確認の不具合が3件ある」）が1行でもあれば畳まない。

**D. 打ち合わせの質**

29. **点の軸（P8 の勧め (a)）:** `AXES` の 5 つ（上の「物差し」）。軸 1〜3 は AI が点と理由を書き、軸 4・5 は NaTsu が要約から数える。誰が付けるかは `AXES` の各軸の `by`（`'ai'`・`'app'`）の1か所で決め、AI に渡す採点の節・読む軸・数える軸・理由の出典を付ける軸は、どれも `by` から組む（答えが「AI が 5 つ全部」なら `by` とテスト1つの期待を直すだけ）。
30. **AI の答えの読み方（`splitScore`・`parseScore`）:** 要約の最後に「## 打ち合わせの質（採点）」の節を1つ。中は「目的と結論: 4 | 理由」「抜け・重なり: 3 | 理由」「決定事項: 4 | 理由」の3行だけ（D49 でヒントの行は無い）。行を NFKC で畳んでから照らす（理由の文は元のまま残す）。軸の行はちょうど1回ずつ、点は 1〜5 の整数（「4」「4 / 5」「4点」だけ）。点と理由は最初の `|` で分ける。行頭の `-`・`・`・`*` と軸の名前の前後の `**` と末尾の（…）を外して見る。**足りない・2回ある・読めない点が1つでもあれば点を出さない**（当て推量で埋めない・3 で埋めない）。ほかの行（合計・人ごとの点・名前の行）は読まずに捨てる。理由は 300 文字まで（越えたら切る）、空なら読めない。**採点の節の見出し**は、`#`〜`####`・`■`・`**…**` のどれかの形で、文が「打ち合わせの質」だけか、後ろが（…）か「: N / 25」だけのもの（「## 打ち合わせの質を上げる施策」は本物の節として残す）。**採点の節が2つ以上なら、どれも本文から外し、点は出さない。**
