利用者の 0.8.0 の実際の会議の記録（クラウドの文字起こし。中継 → OpenAI）で、次の2つが起きた（利用者の決定 D29。2026-10-21）。

## 方針

1. **無音の判定は「一番大きい 0.5 秒」で見る。** 区間全体の RMS で見ると、15 秒の区間の中の短い小さな発言（0.5 秒）は 10 dB 以上薄まって無音に見える。0.5 秒の窓を 0.25 秒ずつずらし、一番大きい窓の RMS がしきい値（-55 dBFS）より小さいときだけ無音にする（決めたこと 1）。WAV として読めない（16bit PCM の data が無い）音声は無音にしない（今どおり送る）。
2. **判定と除き方は1か所（`transcribeAuto`）に置く。** 会議の区間・［もう一度］・残した区間の並べ直し・会議の後の待ち行列・音声入力・残した音声入力の6つの道は、どれも `transcribeAuto` を通る（調べた結果の 5）。その頭で無音を見て送らずに `{ text: '', silent: true }` を返し、答えの後で認識ヒントの繰り返しを見て `{ text: '', echo: true }` を返す。呼び手はどれも今の「空の答え」の扱いで区間を除く（会議の区間だけは、止まりの見張りに数えない・自動で止める見張りに「話し声なし」と教える）。
3. **認識ヒントの繰り返しの判定は純粋な関数（`mainlib.hintEcho`）。** 答えを句読点と空白で切った各片が、認識ヒントの単位（文例の文・業務の言葉・辞書の語。2字以上）だけでつながっている（区切りが無くても）か、4字以上でヒントの尻尾の一部なら、その片は「ヒントの材料」。全部の片がそうなら除く。材料は main が `promptParts` と同じ設定（言語・辞書・業務の言葉のオンオフ）から作る（`hintOf`）。
4. **自動で止める見張りは録音の時間で数える。** 区間の長さ（録音バーが録った時間。一時停止で区間を締めるので一時停止の時間を含まない: 調べた結果の 9）を足した会議の時計で、話し声の無い区間が続いた長さを見る。判定は区間の文字起こしが済むたびに、純粋な関数（`mainlib.quietStep`）で決める。壁の時計（`Date.now()`）は使わない（一時停止とスリープを数えない）。
5. **止めるのは今の `stopMeeting()` だけを通す。** 手で止めたのと同じ道で、止める途中（`stopping`）・作成中・破棄の後は何もしない。聞いている間に止めたら（自動でも手でも）、話し声の無い終わりの部分を所要時間から外す。
6. **録音バーは変えない。** 聞いている間は、今ある `overlay:phase`（`{ phase: 'recording', message }`。録音バーは 4 秒の赤い短い文として出す: 調べた結果の 11）を 3 秒ごとに送り直して出し続ける。
7. **画面は文を作らない（今の決まり）。** 帯の文は main（`meetingStatus().quiet.text`）、ボタンの名前（［続ける］［終了して作成］）は画面。

**使うもの:** Node 24 の `node:test`・今のテストの台（`test/helpers/mainrun.js`・`relay-local.js`・`fake-stt.js`・`fake-whisper.js`・`simrun`）・`tools/mutate.js`・`tools/risk.js`・`tools/shots`。npm の依存は足さない。中継（`relay/`）は変えない。

## 決めたこと（理由つき。違う答えなら直す）

1. **無音のしきい値は「一番大きい 0.5 秒の窓（0.25 秒ずつずらす）の RMS が -55 dBFS より小さい」（`SILENT_DBFS = -55`・`QUIET_WIN_MS = 500`・`QUIET_HOP_MS = 250`）。** 理由: (a) 録音バーは今 RMS 約 -44.6 dBFS より小さい音を「音が入っていません」としている（調べた結果の 8）。それより 10 dB 小さい所に置き、録音バーが「音がある」と見る音は必ず送る。(b) 話し声はふつう -40 dBFS より大きい（`STALL_MIN_DBFS` の考え）。小さな声・遠い人の声を -45〜-50 dBFS と見ても、5〜10 dB の余裕がある。(c) 0.3 秒の短い語（-45 dBFS）が窓に入れば、窓の RMS は -45 + 10·log10(0.3/0.5) ≈ -47 dBFS で、しきい値より 8 dB 大きい。窓を半分ずつ重ねるので、語が窓の境にまたがっても半分より多くが1つの窓に入る（-3 dB まで）。(d) 区間全体の RMS で見ると、15 秒の区間の中の 0.6 秒の -45 dBFS の発言は -59 dBFS に薄まって無音に見える（場面 `blip15` で固定。決めたこと 1 の芯）。(e) マイクは雑音を抑える処理を通してあり（調べた結果の 8）、静かな部屋の無音はふつうずっと小さい。ループバックの無音はデジタルの 0。(f) しきい値より大きい雑音の区間は送るが、作り話は下の 2 で除く（2 段で守る）。WAV として読めない音声は無音にしない。
2. **認識ヒントの繰り返しの判定（`hintEcho`）:** 答えを NFKC にして「、。，．,.!?！？」と空白で切り、各片を検索と同じ畳み方（`hintFold`: NFKC・句読点と記号と空白を外す・小文字）で畳む。片は「ヒントの単位（文例を同じく切った文・業務の言葉・辞書の語。畳んで2字以上）だけでつなげられる（区切りが無くても: 動的計画）」か「4字以上で、畳んだ尻尾の一部」なら材料。全部の片が材料なら除く（会議）。1字の辞書の語は単位にしない（何でもつなげてしまう）。尻尾は4字より短い片を材料にしない（「はい」が尻尾にあるだけで本物の「はい」を落とさない）。
3. **会議では、ヒントの材料だけの答えはいつも除く**（本物の「お疲れさまです。よろしくお願いします。」が会議の頭で1回落ちても、議事録の中身は減らない。利用者の記録は 0:00 も作り話の見込み）。**音声入力では、録った音の一番大きい窓が -40 dBFS（話し声の大きさ）より小さいときだけ除く**（理由: 音声入力は人が話すつもりで押す。メールの頭の「お疲れさまです。」や辞書の語1つを口述するのはふつうで、いつも除くと本物の口述を落とす。作り話は話し声の無い録音で起きる）。問い Q1。
4. **繰り返しの除き方:** 今の「直前と同じ文（7字以上）」はそのまま。話し声の大きさより小さな区間（一番大きい窓が -40 dBFS より小さい: 作り話の疑いがある区間）だけ「直前の2つの済んだ区間のどちらかと同じ文（7字以上）」に広げる（交互の作り話 A・B・A・B を3つ目から除く）。大きな音の区間まで広げると、本物の同じ文（あいさつ・PC の中とクラウドの区間で同じ文になる試験の台）を落とす（作るときに `stage090.banner` の BN2 と `stage1d.seg` の D16 の場面が赤になって見つけた）。さらに、その会議でヒントの繰り返しとして除いた答え（畳んだ形。メモリの中だけ・20 まで）と同じ答えは、ヒントが変わった後（辞書を直した・尻尾が替わった）でも除く。
5. **除いたときの記録:** 文字は書かず、数を書く。無音: `音の無い区間: 区間 s12 を送らずに除きました（-63 dBFS・起動から 41 回目）`。ヒント: `認識ヒントの繰り返し: 区間 s12 の答えを除きました（起動から 5 回目）`（区間の名前は `what`。音声入力は「音声入力」、復旧は「復旧 s3」）。会議の区間は今の1行（`区間 s12（音声 15 秒）: …のため除きました`）も書く（理由の文に「認識ヒントの繰り返しのため」を足す）。行の頭は「文字起こし:」「文字起こしの経路:」にしない（`transcribe.e2e` がその頭で数える）。
6. **無音・作り話・繰り返しで除いた区間は、止まりの見張りに数えない**（`noteEmptySegment` を通さない）。全部が空だったときの知らせ（「マイクを確かめて」）の数（`emptySegs`）には無音と作り話も数える（全部が無音なら、マイクを確かめるのが正しい行動）。
7. **「話し声あり」と「話し声なし」の分け方（自動で止める見張り。会議の区間ごと）:** 文字を書いた → あり。無音・作り話・繰り返しで除いた → なし。空の答えは、区間全体の RMS が -40 dBFS より大きければ（止まりの見張りの「音のある空」と同じ）あり、ほかはなし。失敗の区間と残した区間（文字起こしできていない）は、無音でない（無音は送る前に除くので、ここへ来るのは -55 dBFS より大きい区間だけ）のであり（分からないときは止めない側）。
8. **聞く・止める（`quietStep`）:** 話し声の無い長さ（最後の「あり」の区間の終わりから、最後に分けた区間の終わりまで。会議の時計）が N 分（設定。既定 10）に達したら聞く（`ask`）。聞いた時の会議の時計から 5 分（`QUIET_GRACE_MS`）の間「あり」が来なければ止める（`stop`）。つまり既定で 10 分で聞き、15 分で止める。間に「あり」が来たら聞くのをやめる（`withdraw`: 帯・録音バーの文・Windows の知らせを下げる）。［続ける］は数えを、その時までに届いた音声の終わり（`m.offsetMs`）からにし直す。設定をオフにしたら、次の区間で聞くのをやめる。
9. **止めてよいのは:** 会議を録音中（`state === 'meeting'`）で止める途中でなく、ほかに文字起こしを待つ区間が無い（`pendingSegs <= 1`。今の区間だけ）とき。待ちがあれば、その区間が分けられた時に決め直す（遅い PC で文字起こしが録音に追いつかないとき、まだ聞いていない話し声で止めない）。録っている途中の区間（クラウドで最大 15 秒）は分かっていないが、止めると最後の区間として文字起こしして議事録に入る（失わない）。問い Q3。
10. **聞き方:** (a) 録音中のページの頭（文字起こしの帯の上。文字起こしの帯は今どおり記録の行のすぐ上: `stage1d.app` の D17）に、帯 `#liveQuietAsk`（文は main の `quietAskText(N)`、ボタン［続ける］［終了して作成］。問いなので注意の赤にしない）。(b) 録音バーに「会議は終わりましたか？」（今の `overlay:phase` の口。3 秒ごとに送り直す。一時停止中は送らない。下げるときは `message: ''`。止める途中・作成中は送らない）。× で隠していれば出し直す（O-4 のエラーと同じ）。(c) 録音中のページが見えないときだけ Windows の知らせ（D17 と同じ。押すと録音中のページを開く）。下げるときは閉じる。文: `10 分ほど話し声がありません。会議は終わりましたか？ このままなら 5 分後に録音を止めて議事録を作ります。`（帯と知らせで同じ）。
11. **止めた後:** 聞いている間に止めたら（自動・帯の［終了して作成］・ホットキー・録音バー・トレイのどれでも）、所要時間を「残った区間の一番遅い終わり」（会議の時計）までにし、それより後の一時停止の印を外す（会議の時計は区間を録った時間の和で、壁の時計から一時停止を引いた長さより長くならない）。区間が1つも残っていなければ外さない。自動で止めたときは、議事録を保存できた後に、知らせ（`app:notice`）と、本体の窓が前にないときの Windows の知らせで `話し声が無かったので録音を止め、議事録を作りました（最後の発言 51:28）。`（時刻は議事録の最後の区間の時刻。文字起こしの行の頭と同じ書き方 `m:ss`／`h:mm:ss`）。区間が1つも無ければ `（話し声はありませんでした）`。押すと本体の窓とそのページを開く。
12. **設定:** `autoStopQuiet`（真偽。既定 true。「話し声が無いときに自動で止める」）と `autoStopMin`（5・10・15・20・30・60 のどれか。既定 10。違えば 10。「知らせるまでの時間」）。画面は［設定］→［録音］に新しいカード「話し声が無いとき」（「マイクと相手の声」の後）を足し、チェックと選ぶ欄（`<select>`。打ち間違いを起こさない）を置く。検索の名前（`data-row`）は「話し声が無いときに自動で止める」「知らせるまでの時間」。
13. **ログインや中継に触らない:** 無音の判定・作り話の判定・見張りはどれも PC の中だけで決め、中継・`/health` へ何も送らない。無音の区間は経路を決める前に除く（`sttRoute` を呼ばない）ので、PC の中だけの会議でも、ログインしていなくても同じ。
14. **一時停止とスリープ:** 一時停止の間は数えない（会議の時計が進まない）。スリープは一時停止にするので同じ。一時停止の間に分けた区間（一時停止で締めた区間の文字起こしが一時停止の後に済む）で聞く長さ・止める長さに達しても、聞かず止めない（聞いた印も付けない）。**再開は［続ける］と同じに数え直す**（人が録音を続けると答えた。聞いていれば聞くのをやめる）。一時停止の間は録音バーへ送り直さない。
