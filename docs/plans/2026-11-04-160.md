## 決めたこと（理由つき。違う答えなら直す）

**A. 書き込みの口（Q1・SEC3 の第15b回・P10）**

1. **口を開くのは DB のプロセス:** DB のプロセス（utilityProcess `NaTsu DB`）が名前付きパイプの受け口を1つ開き、つながった口に役 `mcp` を付ける。main は口を作らず、頼みを中継しない。理由: 設計書「保存の土台」の採るもの 6（「MCP の口（第15回）には DB のプロセスが `mcp` の役を付ける」）と 2（「main は口を作って渡すだけで、問い合わせは中継しない」）。main を通すと、録音とホットキーを受け持つ main が Claude の書き込みで止まる。
2. **パイプの名前と合い言葉は起動ごとに作り直す:** パイプの名前は `\\.\pipe\natsu-<24 字の16進>`（Windows。テストの Linux では一時フォルダの `natsu-<24 字>.sock`）、合い言葉は 32 バイトの乱数の16進。DB のプロセスは、用意ができて（`ready` の `state: 'ok'`）から、DB のフォルダの「扉の紙」`natsu.door`（文字の3行「pipe <名前>」「token <合い言葉>」「pid <番号>」。JSON にしない）を一時ファイル → `fsync` → 名前の変更で書き、閉じるとき（`close`）に消す。起動の頭で前の起動の扉の紙を消す（`natsu.db.lock` と同じ: 残っているのは落ちた跡）。`state` が `newer`（新しい版の DB）・`failed` のときは口を開かず紙も書かない（書けない DB に頼ませない）。理由: 紙を読めるのは、`%APPDATA%` を読める同じ利用者のプログラムだけで、そのプログラムは今でも `natsu.db` を直に読み書きできる（RF75 と同じ考え: 書ける人は増えない）。ほかの利用者・ブラウザのページ・ほかの PC は合い言葉を知らない。
3. **握手と上限:** つないだ最初の1行は `{"hello":"<合い言葉>","v":1}` だけ。合わなければ（比べは `crypto.timingSafeEqual`）答えずに切る。2 秒以内に握手が無い・握手の前に頼みが来た・1行が 1MB を越えた（今の口の決まりと同じ）ときも切る。同時の口は 4 つまで（5 つ目はすぐ切る）。60 秒なにも来なければ切る。1行に1つの JSON（MCP の標準入出力と同じ）。頼みと答えの形は今の口と同じ `{ id, cmd, args, tx }` → `{ id, ok, result | code, retry }`。記録には「DB: 書き込みの口 つないだ・断った（合い言葉・形・数）」の数と符号だけ（合い言葉・パイプの名前・頼みの中身は書かない）。
4. **役 `mcp` と actor `claude`:** `core.js` と `server.js` の役の表に `mcp` を足す。役 `mcp` の口からの頼みは、`actor` がいつも `claude`（引数で名乗れない。`args.actor` があれば `bad-args`）。役 `mcp` が呼べるのは、新しい5つの命令（`mcp.writeSummary`・`mcp.fixNames`・`mcp.updateAction`・`mcp.createPage`・`mcp.appendPage`）だけで、今の命令（読む命令も、`page.delete`・`block.*`・`meeting.*`・`snapshot.*` も）は `forbidden`。新しい5つの命令は役 `app`・`main` からは `forbidden`（画面と main が Claude を名乗れない）。理由: 道具1つに命令1つにすると、照らす引数と書く範囲が道具の約束とちょうど同じになる（試作の「決まった一覧だけ」）。
5. **NaTsu が閉じている・DB が使えないとき（P10）:** MCP の書く道具は、扉の紙が無い・読めない・パイプにつながらない・握手が切られたとき、書かずに「NaTsu が起動していないので、書けません。NaTsu を起動してから、もう一度試してください（読むことは今もできます）。」と答える（道具の誤り `isError`・符号 `closed`）。MCP のプロセスは `natsu.db` を書ける形で開かない（`reader.withReader` の `readOnly`・`query_only` は変えない）。DB が `failed`・`newer` で紙が無いときも同じ文（NaTsu の窓には今どおり DB の知らせが出ている: CR3）。
6. **読む道具は今どおり直に読む:** NaTsu が動いていても、6つの読む道具は扉を使わず、今の読み取りだけの接続で答える（Q1 は「動いているときは口で頼む」と書くが、読む道具を口に替えると、閉じているときと動いているときで2つの読み方を持つことになり、0.10.0 からのテスト（RF62・RF64・RF78）を全部やり直す。読み手は WAL の読み手で書き手を止めない: 設計書「壊さないための注意」の「読み手と WAL」）。書く道具は、書いた後の答えに要る題名などを、書く前に今の読み取りの接続で読む（ページが無い・白紙のページに要約を書こうとした、を DB に頼む前に平易に断る。DB の命令も同じ照らしで断る）。
7. **送り直し:** MCP の書く道具は、道具の呼び出しごとに `tx` を1つ作り（`mcp:<時刻の36進>:<8字>`。`TX_RE` に合う）、パイプが答えの前に切れたら、つなぎ直して**同じ `tx` で1回だけ**送り直す（DB の (役, tx) の表引きで2回目は効かず、1回目の答えを今の中身から作り直して返す: `dupResult`）。待つのは 1 回につき 10 秒まで。だめなら「NaTsu に書けたかどうか分かりませんでした。get_meeting で確かめてから、もう一度頼んでください。」（符号 `unknown`）。理由: 設計書「保存の土台」の「送り直し」・試作で実際に起きた「書けたのに返事が届かない」。

36. **能力 `prompts` を足す:** 2つの版（2026-07-28 の `server/discover`・要求ごとの `_meta` と、前の `initialize` の握手）のどちらでも `capabilities` に `prompts: {}` を足し、`prompts/list`・`prompts/get` に答える。指示書は 10 個: 要約タイプ 7 つの「<種類>の型で要約して書き戻す」（引数 `meeting`: ID か NaTsu で写したリンク。必須）と、よく使う頼み3つ（「指した会議から資料を作る」（引数 `meetings`）・「話題で過去の会議を横断する」（引数 `topic`）・「ToDo と決定事項をまとめる」（引数 `from`・`to`。任意））。要約タイプの指示書の本文は、`memoTypes.buildTemplate({ meetingType, score, labeled: true })`（Claude Code に渡すのと同じ書式の1か所）と、「get_meeting を include_transcript で読み、この書式で書き、write_summary に meeting_type を付けて書き戻す」手順だけ。**指示書の中に議事録の文を入れない**（会議の中身は Claude が道具で読む。指示書は DB を開かない）。引数の値は照らし（ID・日付の形・語の長さ 200 字）、指示書の本文には照らした ID と日付だけを差し込む（`topic` は1行にして 200 字まで）。

**H. 画面（知らせ・印・Claude の変更を戻す。CU-1）**

37. **main が知らせを窓へ渡す:** main の DB の客の `onEvent` が `{ type: 'changed', actor: 'claude' }` を受けたら、窓に `claude:wrote { pageIds, what }` と `pages:updated`（一覧）を送る（`what` は DB の知らせに足す、命令の名前から決めた道具の印。題名は送らない: 画面が一覧から引く）。ほかの `actor` の知らせは今どおり読み捨てる（今の画面の動きを変えない）。
38. **画面:** `claude:wrote` を受けたら、開いているページがその中にあれば、打ちかけの文を送ってから（`flushEdits`）読み直して描き直す（打ちかけの文が、Claude が作り直した行を指していて書けなければ、左下に「Claude が書き換えたので、打ちかけの文は入りませんでした」）。左下に「Claude が「題名」を書き換えました（要約を書き戻した）」と［戻す］を一度（［戻す］はそのページの一番新しい控えで、決めたこと 14 の確かめを通す）。白紙のページを作ったときは「Claude が「題名」を作りました」と［開く］。Windows の知らせ・音は出さない。
39. **「···」の［Claude の変更を戻す］:** そのページに控えがあるときだけ、「···」の［削除］の前に出す（控えの無いページの「···」は今と1画素も同じ）。押すと小さな窓 `#claudePop`（見出し「Claude の変更を戻す」）に、新しい順で「11/04 10:20 要約を書き戻した」の行（時刻・道具の言葉。直した数があれば「名前を直した（12 か所）」）と、行ごとの［この前に戻す］。↑↓・Enter・Esc（閉じてフォーカスを「···」へ戻す）。押すと確かめ（決めたこと 14）→ `pageClaudeRevert` → 読み直して描き直し、左下に「戻しました」。
40. **印:** ページのプロパティの行に「🤖 要約: Claude（本人）」（`routeLabel`。Claude が要約を書き戻したページ）。白紙のページ・名前の直し・ToDo の更新には札を足さない（控えがあれば「···」に出る）。
41. **設定のカードと案内:** カード「Claude との連携（MCP）」の頭の1行を「Claude デスクトップから議事録を読み、頼んだときは書き戻せるようにします。」に、吹き出しの「Claude は議事録を読むだけで、書き換えません。」を2行「Claude は、頼んだときだけ、要約の書き戻し・名前の直し・ToDo の更新・白紙のページへの書き込みをします（消すことはしません）。書き換えは、ページの「···」の［Claude の変更を戻す］で戻せます。」「NaTsu を閉じている間は、Claude は読むだけで、書けません。」に替える。行の名前「Claude デスクトップから読む」とボタンは変えない（登録は同じ: CR8）。

**I. そのほか**

42. **見せない会議は無い（D57）:** 書けないのは `listedRows` の外（ゴミ箱・録音中の写し）と、DB に無い録音の前のページだけ。オフラインモード（［この会議は PC の中だけ］）の会議にも、ほかと同じに書ける（D62: 守秘の機能ではない）。
43. **意味の近さの検索は入れない（CQ6 (a)）:** 第7回の RAG の申し送り 6 のまま（共有の保存ができた後に、サーバーの側で考える）。PC の中に埋め込みのモデルを置かない（D59 で要約の手元のモデルをやめたのと同じ考え）、文を外へ送る新しい道も作らない（D110 の「新しい送り先を作らない」と同じ考え）。
44. **記録:** MCP の標準エラーは今どおり「道具 <名前>: <符号>・<件数> 件・<ms>ms」だけ（書く道具も同じ。直した語・題名・合い言葉・パイプの名前は書かない: RF67）。engine.log は「Claude の書き込み: <道具の印>・<符号>」と、DB のプロセスの扉の記録（決めたこと 3）の数と符号だけ。
45. **何も変えない命令:** 名前の直しで当たりが無い・ToDo を同じ値にした・空の Markdown（行が0）は、操作の空の行だけ（(役, tx) の送り直しのため）で、ページの `rev`・更新の時刻・控えを変えない（0.15.0 の決めたこと 16 と同じ）。

**CQ1 0.16.0 に、どの書く道具を入れますか？（大きさ: (a) で 11 タスク・変異 67・新しい画面 4 枚・取り直し 2〜3 枚）**

- **(b) 要約の書き戻し・名前の直し・Claude の変更を戻すだけ（ToDo の更新・白紙のページ・指示書は後の版）。** 理由: 設計書の 15b の行で名指しされている3つに絞り、Claude の書き込みが議事録を壊さないかを先に実機で確かめられます。失うもの: ToDo を Claude から済みにできず、Claude にまとめのページを作らせられません。指示書が無いので、要約の型は利用者が頼み方で伝えます。後の版でもう一度リリースの手間が要ります。
- **(c) 2つに分ける（0.16.0 は扉・控え・要約の書き戻し・戻す、0.16.1 は名前の直し・ToDo・白紙のページ・指示書）。** 理由: 新しい入口（扉）と版 2 を先に出し、壊れたときの切り分けを易しくします。失うもの: リリースと取り直しの見比べが2回になり、後の版の番号の付け方（0.16.1）を版の表に足します。

**CQ2 Claude が書く前に、NaTsu でも確かめを出しますか？**
- **(a) NaTsu では確かめを出さず、すぐ書く（おすすめ）。** Claude デスクトップが道具ごとに「NaTsu の書く道具を使ってよいか」を利用者に聞きます。書いた後に NaTsu の左下に知らせと［戻す］が出て、「···」から 10 回分まで戻せます。理由: 設計書の第14回 F2（「確かめを出さずに反映する」）と同じで、Claude の画面で頼んで許したのに、NaTsu の窓でもう一度押す手間を作りません。NaTsu が後ろに隠れていても待たせません。失うもの: Claude デスクトップで「いつも許す」にしていると、Claude が頼み違いで書いたときに、書いた後で気づくことになります（戻せます）。
- **(b) NaTsu の窓に「Claude が「題名」の要約を書き換えようとしています［書く］［断る］」を出し、押すまで待つ。** 理由: 何が書かれるかを NaTsu の側でも必ず見られます。失うもの: NaTsu の窓が隠れていると Claude が待ち続け、時間切れで断られます。名前の直しを何回も頼むと毎回押します。扉に「待つ」答えの形と、窓の部品と画面が増えます。
- **(c) 要約の書き戻しだけ NaTsu で確かめ、ほかはすぐ書く。** 理由: 一番大きく変わる書き込みだけを止めます。失うもの: (b) と同じ手間と部品が、要約の書き戻しにだけ要ります。道具ごとに動きが違うので覚えることが増えます。

**CQ3 「Claude の変更を戻す」は、どう出しますか？**
- **(a) ページの「···」に［Claude の変更を戻す］（Claude が書いたページだけ）を出し、10 回分の一覧から選んで戻す。書いた直後の左下の知らせにも［戻す］。後で自分が直した所があれば、戻す前に確かめる（おすすめ）。** 理由: 設計書の「…」→「Claude の変更を戻す」の形で、何回か前に戻したいときも選べます。後の直しを黙って消しません。失うもの: 小さな窓が1つ増え、撮る画面が 3 枚増えます。
- **(b) 「···」の［Claude の変更を戻す］で、一番新しい1回だけ戻す（一覧は出さない）。** 理由: 画面が小さく、迷いません。失うもの: 2回前の書き込みだけを戻すことはできず（新しい方から1回ずつ戻す）、控えが 10 回分あっても選べません。
- **(c) 左下の知らせの［戻す］だけ（「···」には出さない）。** 理由: 一番小さい形です。失うもの: 知らせが消えた後や、NaTsu を起動し直した後は戻せません。設計書の「…」→「Claude の変更を戻す」を満たしません。

**CQ4 Claude の変更の控えを、どこに持ちますか？（議事録の保存の形に関わります）**
- **(a) 設計書のとおり、保存の DB に控えの表（`page_snapshot`）を足し、保存の形の版を 2 に上げる。上げる前に自動で控えを取る（おすすめ）。** 理由: 設計書と今のコードの注（「page_snapshot は版 2 の表として足す」）のとおりで、ページごとに 10 回分を、いつまでも（消すまで）残せます。後の変更履歴（第10回）もこの表から作れます。取り消した会議の文字も同じ形で消せます（RF16）。失うもの: 0.16.0 を入れた後に 0.15.x 以前の NaTsu に戻すと、議事録は読むことだけできて、書けなくなります（入れ直せば戻ります）。控えの取れない PC（空きが無いなど）では、空けるまで議事録を開けません。
- **(b) 保存の形を変えず、操作の記録（`oplog`。前の値を持つ）から、Claude の書き込みだけを逆に当てて戻す。** 理由: 前の版の NaTsu に戻しても書けます。後で利用者が同じ所を直していたら戻さない（直しを消さない）形にできます。失うもの: 操作の記録は控えを回すと消えるので、戻せるのはおよそ 2 週間です。設計書の 10 回分・いつまでもと違い、後の変更履歴の回で作り直します。
- **(c) 保存の形を変えず、設定などの小さな欄の表（`meta`）に控えを入れる。** 理由: 前の版の NaTsu に戻しても書け、10 回分を残せます。失うもの: 小さな欄のための表に大きな写しを入れることになり、設計書の表の形から外れます。前の版の NaTsu は控えを知らないので、前の版で会議を取り消すと控えの文字が残りえます（RF16）。後の変更履歴の回で作り直します。

**CQ5 Claude デスクトップの「＋」のメニューに出す指示書（MCP のプロンプト）は、どれにしますか？**
- **(a) 要約タイプ 7 つの「この型で要約して書き戻す」と、よく使う頼み3つ（指した会議から資料を作る・話題で過去の会議を横断する・ToDo と決定事項をまとめる）の 10 個（おすすめ）。** 理由: 要約タイプの書式は Claude Code に渡しているものと同じ1か所から作るので、Claude デスクトップでも NaTsu と同じ型の要約になります。3つの頼みは、持ち主が 0.10.0 で決めた RAG の使い方（D65・D73）そのものです。失うもの: メニューの項目が 10 個になり、少し長くなります。
- **(b) 要約タイプの 7 つだけ。** 理由: 設計書の「要約タイプごとの指示書」の文のとおりで、書き戻しに絞ります。失うもの: 資料作り・横断・ToDo のまとめは、今までどおり利用者が言葉で頼みます。
- **(c) 作らない（`instructions` の文だけ）。** 理由: Claude デスクトップの画面を変えません。失うもの: 設計書の 15b の「要約タイプごとの指示書」を満たさず、Claude が NaTsu の型の見出しで要約するとは限りません。

**CQ6 意味の近さの検索（ベクトル）を 0.16.0 に入れますか？（D51 で「後の候補（第7回の申し送りと第15b回）」とした分）**
- **(a) 入れない。第7回の申し送りのまま、共有の保存ができた後に、サーバーの側で考える（おすすめ）。** 理由: PC の中で作るには埋め込みのモデル（数百 MB）を同梱するか取り込む必要があり、要約の手元のモデルをやめた D59 と逆向きです。外の埋め込みを使うには、会議の文を外へ送る新しい道が要ります（0.14.0 の D110 の「新しい送り先を作らない」と逆向き）。今の箇所の検索（語の当たり・2〜4回の言い換えを Claude に頼む instructions）で、0.10.0 からの使い方は足りています。失うもの: 言い換えを Claude が思いつかないと、意味だけが近い箇所は見つかりません。
- **(b) 0.16.0 で、文字起こしの中継を通して外の埋め込みを作り、PC の中に索引を持つ。** 理由: 「同じ意味の違う言い方」でも見つかります。失うもの: 会議の文を外へ送る新しい道と同意の画面が要り、中継・費用・1日の上限の設計がやり直しになります。保存の形にも欄か表が増えます。0.16.0 がかなり大きくなります。
- **(c) 0.16.0 で、PC の中の小さな埋め込みのモデルを取り込みで入れる。** 理由: 文を外へ送りません。失うもの: 取り込み（数百 MB）と、遅い PC での索引作りの時間がかかります。D59 で手元のモデルをやめた考えと逆向きで、0.16.0 がかなり大きくなります。

**CQ7 議事録のメモ（利用者が書く欄）に、Claude が書けるようにしますか？**
- **(a) 書かせない。議事録に Claude が書くのは、要約の書き戻し・名前の直し・ToDo の更新だけ。書き足しと新しいページは白紙のページで（おすすめ）。** 理由: メモは利用者が会議中に書く欄で、Claude の文が混ざると、どこまでが自分のメモか分からなくなります。Claude の文は白紙のページに置けば、子ページとして議事録の中にも置けます（0.15.0）。失うもの: 「この議事録のメモに次回の議題を足して」は頼めません（白紙のページを議事録の中に作らせます）。
- **(b) メモの最後に書き足せる（今のメモの行は変えない）。** 理由: 議事録1つの中で完結します。失うもの: メモに Claude の文が混ざり、Claude にメモを渡す要約（Claude Code）が、Claude の書いた文も「メモ」として読みます。
- **(c) 要約の最後に書き足せる。** 理由: 要約の欄に答えが並びます。失うもの: ［要約を再生成］で消え、出典の照合と要約の型の決まり（並べ替え・印）の外の行が要約に混ざります。
