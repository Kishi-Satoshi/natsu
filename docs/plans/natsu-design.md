# NaTsu — Notion に寄せた議事録とチームのワークスペース

## Context

最初の依頼: 「UI含めて、Notionに限りなく近くに寄せて欲しいです。」
壁打ちで広がった依頼:
- 名前を NaTsu に変え、保存先まで含めて改める。ロゴは箱型にする。
- 要約をクラウドで行う（AWS のサーバーレス構成＋Bedrock の Claude）。
- プライベートとチームスペースを分け、ページごとに共有する。タスクも共有する。
- データベース、話者分離、AI による名前の修正を入れる。
- 個人の Claude と MCP で連携する。
- Teams で知らせる。ヘルプセンターを置く。

今の画面（調査結果）:
- **見た目:** ガラス風（ぼかし玉・`backdrop-filter`・グラデーション・ピル型・青い影）。Notion の平らな白地とは正反対。
- **画面の切り替え:** 上のタブ（議事録・音声入力・設定）は画面を切り替えるだけ。左の一覧は議事録タブの中にしかない。
- **ブロック:** 4種（見出し・箇条書き・ToDo・段落）。
  - Enter は空の行を足すだけ、Backspace は空の行を消すだけ。
  - `/` メニュー・Markdown 記法・型の変換がない。
  - 挿入や削除のたびに、ページ全体を描き直す。
- **一時停止:** 録音バーにすでにある（`overlay:pause`、`meeting.paused`／`pausedMs`）。

**全体を通して守ること**
- **出典の照合:** `src/cite.js` は変えない。照合の対象は箇条書きと ToDo だけ。`markdownToBlocks` が作る型も変えない（見出しの段数 `level` を足すだけ）。
- **録音バー:** `overlay.html` は触らない。例外は第0回の `<title>Listener Overlay</title>` の文字の置き換え1か所だけ。
- **Notion の資産:** デザイン資産・ロゴ・コードは使わない。フォントは OS 標準、アイコンは絵文字か自作の SVG。
- **アプリの依存:** npm の依存を足さない。サーバー（`server/`）だけは Bedrock 用 SDK を使ってよい。
- **IME:** 確定の Enter は、どの新しい入力経路でも `imeEnter(ev)` で先に抜ける。
- **公開前の確認:** 個人名・社名・会社のドメイン・個人のパスをコードに残さない。会社のドメインはサーバーの環境変数にだけ置く。
- **テストデータ:** 実在の人名を使わない。出典リンクを LLM に作らせない。日付を推測で埋めない。
- **PowerShell:** BOM 付き UTF-8 と CRLF で保存する。`switch` と `[ValidateSet]` は使わない。
- **Listener の利用者:** 一切考えない。データの移行も、自動更新の橋渡しも作らない。

## 目的（ソクラテス式の問答で分かったこと）

- **本当の目的:** 会社が50人に Notion を入れる予定を、NaTsu に置き換えること。理由は **Notion の料金**。今 Notion を使っているのは利用者本人だけで、導入を決めるのも本人。
- **最優先:** **50人が個人で使えること**。共有（チームスペース・同時編集・コメント）は後回しでよい。
- **1.0.0 の範囲:** 個人で使える版を **1.0.0** として50人に配る。共有などは 1.x で足していく。
- **1.0.0 の約束:** 配った後は、50人の議事録を壊さないことが最も重い約束になる。だから、保存の形の作り替え（T4b）は 1.0.0 の前の第2a回で済ませる。
- **配る前に要らないもの:** PC が壊れて議事録が消えることは、配る時点では許せる（クラウド保存は配った後）。計算式とロールアップも、配った後でよい。
- **要約（50人全員が Claude の個人プランを契約している前提）:**
  - **自動の要約:** 録音が終わったら、今どおり**手元の llama** で自動で入れる。前に決めた「llama をやめる」は**取り消す**。
  - **質の高い要約:** 本人が Claude デスクトップで頼み、Claude が NaTsu の MCP で文字起こしを読んで要約を書き戻す。各自のサブスクリプションの利用枠で行い、**API の従量課金はかからない**。NaTsu は Claude を一度も呼ばない。
  - **AI による名前の修正:** これも各自の Claude で MCP 越しに行う。
- **1.0.0 に AWS は要らない:** ログインも要らない。AWS・ログイン・管理画面は、共有を作る段階B へ移す。
- **決め手:** 50人が Notion でなくてよいと思う決め手は「見た目と書き心地が Notion と同じ」こと。そのため、画面と編集（第1b〜3回）は削らない。
- **Claude デスクトップ:** 50人の PC に入れられる。PC の中の MCP で足り、1.0.0 に AWS は要らない。
- **タスク:** 1.0.0 では自分の中だけで管理する。他の人への依頼は今までどおり Teams で行う。
- **NaTsu でいくことは決定済み:** 配った後の声は、段階B の順番を決めるのに使う。
- **1.0.0 の問い合わせ:** Teams の NaTsu 用チャンネルで受ける。アプリの「?」には、同梱した使い方の記事と、「状態を写して Teams に貼る」ボタンを置く。写すのは版の番号と動作の記録だけで、議事録の本文は含めない。サーバーは要らない（第3回で入れる）。ヘルプセンターと「その場で質問」は段階B。
- **Claude の書き込みの戻し（1.0.0）:** Claude が MCP で書き換える直前のページを、PC の中に控える（ページごとに直近10回分）。「…」→「Claude の変更を戻す」で戻せる。本物の変更履歴は段階B の第10回のまま（第15回で入れる）。
- **50人への案内:** 個人向けのプランでは、会話を学習に使うかの設定を本人が決める。1on1・面談を扱う前に、学習への利用を切るよう案内する（ヘルプの記事と、MCP の登録画面に書く）。

## 利用者に確かめたこと

- **コード署名:** 会社の PC は署名なしのアプリも入れられる（今の Listener もそれで動いている）。署名は今回しない。後から落とす exe は SHA-256 で照らす（RF3）。
- **会社のプロキシと日本語のユーザー名:** あるとは聞いていない。それでも、通信は Electron の `net` を使い（RF2）、日本語の名前のフォルダでのテストを CI に持つ（RF1）。どちらも作る量は小さく、外れたときの被害が大きいため。

**作業ごとに別のエージェント**で作る。各回の実装計画の作業1つごとに、新しいエージェントが作り、そのたびに別のエージェントが点検する。回の最後に、回全体をもう一度点検してからリリースする。

**保存の形（ここで決め、あとで作り直さない）**:
- **ブロックは木:** `children` を持つ木にする。第8回の同時編集も、第16回の段組み・同期ブロックも、この形を前提にする。
- **文字は2つの欄で持つ:** 今までどおりの素の文字 `text`（文字列）と、飾り付きの区切りの列 `rich`（例 `[{t:"今日は",m:[]},{t:"大事",m:["b"]}]`）。保存のたびに `rich` から `text` を作り直し、両方が食い違わないことをテストで固定する。
- **素の文字の使い道:** `cite.js` は `b.text` を文字列として読んでいるので、そのまま `text` を読ませる。だから `cite.js` は変えない。検索・要約・コピーも `text` を使う。
- **見出しの段数:** 今の `markdownToBlocks` は `#`〜`####` を区別せず `heading` にしている。`#`→1、`##`→2、`###` 以下→3 とし、読み取りのテストを足す。
- **既存のページ:** 「子のない木」として読む。
- **出典チップ:** 箇条書きと ToDo 以外の型に変えると、その行の出典チップは消える（許容する）。要約の有無の判定（`heading` があるか）は変わらない。

## 壊さないための注意（調査で分かった罠）
- **保存先の変更:** `userData` が替わり、Listener の議事録は見えなくなる（意図どおり）。
- **ダーク定義のテスト:** `test/repo.test.js` の「ダーク定義は最後」は、旧い地色の文字列を目印にしている。新しい地色を目印にするよう直す。
- **設定の `<h2>`:** 区画の見出し専用で、並びはテストで固定している。第0回と第6回で区画が変わるので、テストの意図ごと直す。エディタの見出しには `<h2>` を使わない。
- **色のトークン:** 明暗の両方を定義し（COLOR-02/03）、状態クラスには CSS を付ける（COLOR-04）。CSS の入れ子は使わない（COLOR-05）。
- **偽 DOM の制約:** 画面テストの偽 DOM には `getSelection` / `Range` がない。分割・結合・飾りは純粋な関数に切り出してテストする。
- **行の差し替え:** フォーカス中の要素を消しても blur は飛ばない。差し替えの前に保存する（`flushEdits` / `_commit`）。
- **サイドバーの移動:** 外へ出すとゲートが「枠からの離脱」で止める。`hedit.js move --allow-reparent` を使い、理由を添えて通す。
- **テストが固定している見た目:** `.pitem .t` の nowrap、つまみの `⠿`、ToDo の四角いチェック（`appearance:none` は設定のトグルだけ）。変えるときはテストの意図ごと直す。
