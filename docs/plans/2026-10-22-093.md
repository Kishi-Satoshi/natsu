## 目的

利用者の依頼（2026-10-22。「Notion に近づけて」）:

1. **Web 会議（Teams・Zoom・Google Meet など）が始まったら、小さなパネルを自動で出す。** Notion の会議の検出の知らせのように、画面の右上に丸いパネルで、NaTsu のロゴ・「AI 議事録を始める」・下の行（「文字起こしで NaTsu を開く」）・青い［文字起こしを始める］と ⌄ のメニュー（オフラインモードで始める・このアプリでは出さない・設定）。パネルの明暗は Windows の明暗に合わせる（Q3）。
2. **録音を始めたら、音を拾っていることが見える波を出す。** Notion の会議のブロックのように、「文字起こし」の横に、音の大きさに合わせて高さの変わる小さな点の列（流れる）。Notion がまだ決まっていない文字を灰色で出すのに当たるものも考える。

この版で:

- **A. 会議の検出の通知。** Windows が持っている「どのアプリがマイクを使っているか」の記録（下の「外の資料で調べたこと」の 1）を 2 秒ごとに読み、決まった会議のアプリ（Teams・Zoom・Webex・Slack・ブラウザ（Chrome・Edge・Firefox））がマイクを使い始めたら、録音していないときだけ、右上にパネルを出す。フォーカスを取らない・画面の共有に写らない・30 秒で引っ込む（カーソルが乗っている間は引っ込まない）・そのアプリがマイクを離したらすぐ引っ込む・同じ会議では2度出さない。［文字起こしを始める］で今の［新しい議事録］と同じに録音を始め、NaTsu の本体の窓を前に出して録音中のページを見せる（会議の種類をそこで選べる。トレイに隠していても出す: Q5）。音は聞かない・何も外へ送らない・窓の題名を読まない。［設定］→［録音］の「会議の検出の通知」（既定オン）で切れる。アプリごとに出さないこともできる。

## 方針

1. **「会議が始まった」は「会議のアプリがマイクを使い始めた」で見る。** Notion も「マイクを使っているプロセスがあるか」で見ている（外の資料の 4）。プロセスが動いているだけ（Teams は1日中動いている）・窓の題名・カレンダーでは見ない。音そのものは聞かない（NaTsu の録音の外で音を開かない）。
2. **読むのは Windows の利用者ごとの記録（HKCU）だけ。** 管理者の権限・ドライバー・新しい npm の依存は要らない。読み手は、会議の検出のためだけの常駐の PowerShell（「見張り」）。今の常駐の PowerShell（貼り付けとクリップボードの係。調べた結果の 9）には混ぜない（K1）。
3. **見張りは決まった一覧（`MEET_APPS`）に当たるものだけを外へ出す。** 一覧に無いアプリの名前・パス（利用者の名前が入る）は PowerShell の外へ出ない。NaTsu 自身（音声入力・議事録）は除く。
4. **出す・引っ込める・2度出さないの判断は純粋な関数（`mainlib.nudgeStep`）。** main は見張りの1行と自分の状態（録音中か）を渡し、答えのとおりに窓を出し入れするだけ。
5. **パネルは録音バーと同じ作りの小さな透過の窓（`nudge.html`）。** `focusable: false`・`showInactive()`（会議のアプリの入力を奪わない）・いつも前・タスクバーに出ない・影を付けない。大きさは画面が測って送り（`reportSize`。録音バーの O-2 と同じ）、置き場所は main が純粋な関数（`lib.nudgeBounds`）で決める。
6. **音の波の大きさは、録音バーの画面に main が聞く（10 回／秒）。** 録音中のページが見えている間だけ聞き、見えていなければ聞かない。録音バーを × で隠していても答えられるように、録音バーの毎フレームの描き（`requestAnimationFrame`。隠れた窓では止まる）ではなく、IPC の受け口で答える。
7. **画面は文を作らない（今の決まり）。** 「音が入っていません」は録音バーと同じ文を main 経由で受けて出す。パネルの文は決まった文（「AI 議事録を始める」「文字起こしで NaTsu を開く」: Q4）で、⌄ のメニューの「<アプリ> では出さない」のアプリの名前だけを main が一覧から渡す。パネルの明暗も main が決めて渡す（Q3）。

**使うもの:** Node の `node:test`・今のテストの台（`test/helpers/simrun.js`・`simdom.js`・`simcss.js`・`mainrun.js`）・`tools/mutate.js`・`tools/risk.js`・`tools/shots`。npm の依存は足さない。中継（`relay/`）は変えない。

## 外の資料で調べたこと（出典つき。2026-10-22 に読んだ）

1. **Windows の「マイクを使っているアプリ」の記録（Capability Access Manager）。** `HKCU\Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone` の下に、ストアのアプリ（パッケージ。キーの名前はパッケージファミリー名。例 `MSTeams_8wekyb3d8bbwe`）ごとのキーと、`NonPackaged` の下にデスクトップのアプリごとのキー（キーの名前は実行ファイルのパスの `\` を `#` にしたもの。例 `C:#Users#…#Zoom#bin#Zoom.exe`）があり、それぞれ `LastUsedTimeStart`・`LastUsedTimeStop`（QWORD の FILETIME）を持つ。**`LastUsedTimeStop == 0` かつ `LastUsedTimeStart != 0` なら「今使っている」。** これは Windows の［設定］→［プライバシーとセキュリティ］→［マイク］の「最近のアクティビティ」（7 日分・「現在使用中」の表示）と同じ記録。**Microsoft はこの意味を公式に文書にしていない**が、フォレンジックの道具とマイクの印の小道具で広く使われている。開いた問い: アプリが落ちたとき `Stop == 0` のまま残るか（だから「その実行ファイルのプロセスが今あるか」でも確かめる）。出典: GitHub `llexa97/trigo-whispr` issue #9・PR #21（https://github.com/llexa97/trigo-whispr/issues/9 ・ https://github.com/llexa97/trigo-whispr/pull/21。2 秒ごとに読み、1 回 1ms 未満を目標・NonPackaged は同じ名前のプロセスがあるかで古い値を除く・自分の実行ファイルを除く）、GitHub `WinIslandProject/WinIsland` issue #162（https://github.com/WinIslandProject/WinIsland/issues/162。`LastUsedTimeStop` が 0 の行を拾う PowerShell の1行）、Cyberengage「Tracking Microphone and Camera Usage in Windows」（https://www.cyberengage.org/post/registry-system-configiuration-tracking-microphone-and-camera-usage-in-windows-program-execution）、TheWindowsClub（https://www.thewindowsclub.com/delete-last-accessed-timestamp-for-location-camera-microphone）、Geek Rewind・ElevenForum（https://geekrewind.com/how-to-see-which-apps-have-accessed-your-microphone-in-windows-11/ ・ https://www.elevenforum.com/t/see-which-apps-have-accessed-your-microphone-in-windows-11.48684/latest）。Sigma のルール（https://sigma.controlassurance.com/rules/win_security_camera_microphone_access/）は、監査を入れた PC でこのキーへのアクセスを記録する例（会社の監視の道具が見ることがある: 問い Q13）。
2. **読む費用。** キーの数はふつう数十〜百数十。.NET の `Microsoft.Win32.Registry` で常駐のプロセスの中から読めば、1 回は 1ms 前後（上の issue の目標。M-2 で Windows の CI で測る）。`reg.exe` を 2 秒ごとに起こすと 1 時間に 1,800 回プロセスを作り、会社の監視の道具に目立つ（やめる: K1）。キーの変わりを待つ `RegNotifyChangeKeyValue` もあるが、2 秒の見回りで足りる（上の issue と同じ考え）。
3. **Windows の音のセッションの API（`IAudioSessionManager2`）。** 録音の機器ごとに「今そこから録っているセッションと、そのプロセスの ID」を数えられる、Microsoft の文書のある API（https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-getsessionenumerator ・ Q&A https://learn.microsoft.com/en-us/answers/questions/214055/is-it-possible-to-get-status-or-event-when-device ）。ただし (a) 機器ごとに数える（マイクが複数あれば全部）、(b) 文書が「数えるだけでは新しいセッションを見落とすことがある。知らせ（`IAudioSessionNotification`）で自分で一覧を持て」と書く、(c) PowerShell から使うには C# の COM の型を `Add-Type` でその場で組む（100 行を越える）。0.9.3 では使わない（Capability Access Manager が実機で外れたときの次の手。問い Q13）。

## 決めたこと（理由つき。違う答えなら直す）

### A. 会議の検出の通知

1. **「今使っている」の判定:** Capability Access Manager の `microphone` の下（パッケージのキーと `NonPackaged` の下のキー）で、`LastUsedTimeStop` が 0・`LastUsedTimeStart` が 0 でない・どちらも QWORD で読めるもの。読めない値は「使っていない」（上の issue と同じ。古い値で出しっぱなしにしない）。
2. **一覧（`MEET_APPS`。mainlib・凍らせる）:** `{ id, label, exe: [...], pkg: [...], proc: [...] }`。`teams`（「Teams」。pkg `MSTeams_8wekyb3d8bbwe`・exe `ms-teams.exe`・`teams.exe`）・`zoom`（「Zoom」。`zoom.exe`）・`webex`（「Webex」。`webex.exe`・`ciscocollabhost.exe`・`atmgr.exe`）・`slack`（「Slack」。`slack.exe`）・`chrome`（「Chrome（ブラウザ）」）・`edge`（「Edge（ブラウザ）」。`msedge.exe`）・`firefox`（「Firefox（ブラウザ）」）。比べるのは実行ファイルの名前（パスの最後）を小文字にしたもの。`proc` は古い値を除くときに見るプロセスの名前（`.exe` を外した形）。ブラウザも入れる（持ち主の答え Q6）。**Notion（`notion.exe`・ストアの Notion）と NaTsu（`natsu.exe`・`electron.exe`）は入れない**（持ち主の実機の記録: 外の資料の 6。Notion は会議のアプリではなく別のメモ取りの道具。NaTsu は自分。一覧に無いアプリは見張りの外へ出ないので、Notion だけ・NaTsu だけがマイクを使っていても何も出ない）。
3. **見張り（`mainlib.micWatchScript({ root, self, apps, everyMs })` → PowerShell の1つの文字列）:** `-NoProfile -NonInteractive` の常駐。`everyMs`（2000）ごとに HKCU の `root` の下を読み、一覧に当たるもの（NonPackaged は名前、パッケージはファミリー名）だけを、`self`（`process.execPath` を小文字にしたもの）と同じパスを除いて、`proc` のプロセスが今あるもの（`[System.Diagnostics.Process]::GetProcessesByName`）だけ残す。**前と変わったときだけ** `mic <id>:<start>,<id>:<start>`（無ければ `mic -`）を1行書く。読めない・例外は `err <符号>` の1行（`read`・`proc`）。パス・一覧に無い名前・題名は書かない。`root` は既定 `Software\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone`（Windows の CI のテストは自分の作った HKCU の下の偽のキーを渡す）。
4. **見張りの生き死に（main）:** 起こすのは `process.platform === 'win32'`・設定 `meetingDetect` がオン・`state === 'idle'` のとき。録音（音声入力・議事録・作成中）が始まったら止める（読み続けない）。設定を切ったら止める。落ちたら 30 秒・2 分・10 分の後に起こし直し、それでも落ちたら次の起動か設定のオンオフまで起こさない（記録に1行）。終了のときは止める。標準出力の読み方は貼り付け係と同じ（1行ずつ）だが、別のプロセス・別の受け口（K1）。
5. **出すかの判断（`mainlib.nudgeStep(st, ev)` → `{ st, show, hide }`。純粋）:** 出来事は `sample`（見張りの1行を読んだ形 `[{ id, start }]`）・`busy`（録音を始めた・止めて idle に戻った）・`shown`・`closed`・`setting`（オンオフと出さないアプリ）。**出すのは次の全部のとき:** (a) idle、(b) 設定がオンでそのアプリを出さないにしていない、(c) 同じ `(id, start)` が2回続けて見えた（2〜4 秒。マイクの試しの一瞬や、開き直しを拾わない）、(d) その `(id, start)` で出したことが無い、(e) 同じアプリの前の使い（出した・閉じたもの）が終わってから 60 秒たっている（つなぎ直し・機器の切り替えで同じ会議に2度出さない）、(f) 今パネルが出ていない。2つのアプリが同時なら一覧の順の先のもの。**音声入力・作成中（idle でない・議事録の録音中でない）に始まった使いは覚えておき、idle に戻ったときにまだ使っていて出していなければ出す**（音声入力の後・前の議事録の作成の後）。**議事録の録音中に見えていた使いは「録った会議」として、idle に戻っても出さない**（M-1 で作ったときに足した: ホットキーで録音を始めて止めた後、まだ会議のアプリがマイクを使っていてもパネルを出さない。出来事 `busy` に `meeting` の印）。NaTsu を起動した時にもう会議中なら出す（問い Q14）。
6. **引っ込めるのは:** そのアプリがマイクを離した（次の `sample` に無い）・出してから `NUDGE_SHOW_MS`（30 秒。問い Q2）たった・カーソルが乗っている間は数えず、離れてから 5 秒で引っ込む・× を押した・どの道でも録音が始まった・設定を切った／そのアプリを出さないにした・画面が外れた。**無視したとき:** 30 秒で引っ込み、何も残らない（記録もしない）。同じ会議ではもう出さない。
7. **パネルの窓（`nudgeWin`。初めて出すときに作り、使い回す）:** `frame: false, transparent: true, resizable: false, movable: false, minimizable: false, maximizable: false, focusable: false, alwaysOnTop: true, skipTaskbar: true, show: false, hasShadow: false`・webPreferences は録音バーと同じ（preload・sandbox・contextIsolation）。`setAlwaysOnTop(true, 'screen-saver')`（全画面の会議の上にも出す）・`setVisibleOnAllWorkspaces`・**`setContentProtection(true)`**（画面を共有していても参加者に見えない: K4）。出すのは `showInactive()` だけ（`show()`・`focus()` を呼ばない）。
8. **置き場所:** 出す時のカーソルのある画面の作業領域の右上、端から 12px（録音バーの置き場所と同じ余白）。`lib.nudgeBounds({ size, workArea })` → `{ x, y, width, height }`（右と上を作業領域の内側 12px に、幅と高さを作業領域 − 24px まで）。出している間はその画面のまま（カーソルを動かしても飛ばない）。画面の拡大率（DPI）は Electron の DIP のまま。画面の配置が変わった（`display-metrics-changed`）ら置き直し、画面が外れた（`display-removed`）ら引っ込める。録音バーとは同時に出ない（パネルは録音していないときだけ）ので、置き場所は取り合わない（問い Q8）。
9. **パネルの中（`nudge.html`。持ち主の決定 D50: 会議の種類を選ぶ欄は置かない）:** 左にロゴ（`overlay.html:173` と同じ3本の path）、太字の「AI 議事録を始める」、下の行「文字起こしで NaTsu を開く」（アプリの名前を入れない決まった文。持ち主の答え Q4）、青い［文字起こしを始める］と ⌄、× 。⌄ を押すとパネルの下にメニュー（「オフラインモードで始める」（下の小さな文は付けない: D54）・「<label> では出さない」・線・「会議の検出の通知の設定…」）。メニューを開くと画面が大きさを送り直し、main が窓を広げる（閉じると戻す）。**明暗は Windows に合わせる（持ち主の答え Q3）:** main が `nativeTheme.shouldUseDarkColors`（NaTsu の外観が「システムに合わせる」（既定）なら Windows のアプリの明暗。外観で明るい・暗いを選んでいればその明暗）で `theme: 'light' | 'dark'` を決めて `nudge:show` に入れ、出している間に `nativeTheme` の `updated` が来たら送り直す。暗いパネルは録音バーと同じ地（`#262626`・縁と内側の明かり）。明るいパネルは白い地・細い縁（`rgba(28,19,1,.16)`）と、はっきりした影（モック `v4-light.png`）。**影は `box-shadow` で描かない**（透過の窓の地雷: 地雷の台帳の css の box-shadow。窓の矩形いっぱいに灰色が出る）。代わりにカードの外に半透明の輪を2つ重ねた疑似要素（`::before`・`::after`。ふつうの `background` の半透明の色で、角の丸めの外側を薄くする）で影に見せ、窓はその輪の分（四方 6px）だけ広く取る（K9）。キーボードは使えない（`focusable: false`。録音バーと同じ。代わりは議事録ホットキー: K5）。
10. **押したとき（main。画面からは id も文も受けない）:** ［文字起こしを始める］→ `nudge:start`（`{ pcOnly: false }`）・「オフラインモードで始める」→ `nudge:start`（`{ pcOnly: true }`）: パネルが出ていて idle のときだけ、引っ込めてから `startMeeting()`、`pcOnly` が真で始められたら `setMeetingLocalOnly(true)`。始められなければ `toggleMeetingByHotkey` と同じに本体の窓を出して文を知らせる。**始められたときは、本体の窓を前に出して録音中のページを見せる**（持ち主の答え Q5。会議の種類をそこで選べる: D50 と合う。Notion の「文字起こしで Notion を開く」と同じ）。出し方は Windows の知らせを押したときの `showLiveFromNotice` と同じ（窓が無ければ作る・最小化なら戻す・`show()` と `focus()`・読み込み中なら読み終えてから `meeting:show-live`）。**トレイに隠した窓（`stayInTray` で × を押した窓。`isVisible()` が偽）でも出す**（隠れた窓の画面は動いているので、録音は窓と関わりなく始まる。録音を始めてから窓を出すので、窓を出せなくても録音は始まっている）。会議のアプリの入力は奪われるが、持ち主がそれでよいと答えた（パネルを出すとき（`showInactive`）は今までどおり奪わない）。「<label> では出さない」→ `nudge:mute`（引数なし。main が今出しているアプリの id を `meetingDetectMute` に足して保存し、`settings:patched` で画面へ）。「会議の検出の通知の設定…」→ `nudge:settings`（引っ込めて本体の窓を出し、`app:open-settings` で［設定］→［録音］の「会議の検出」のカードへ）。× → `nudge:close`。
11. **設定（キー 33 → 35）:** `meetingDetect`（「会議の検出の通知」・bool・`notFalse`・既定オン。名前は Notion の「Desktop meeting detection notifications」に合わせた）・`meetingDetectMute`（「通知を出さないアプリ」・新しい kind `apps`: `MEET_APPS` の id の並び。一覧に無いもの・重なり・文字でないものは落とす）。画面は［設定］→［録音］の頭に新しいカード「会議の検出」（録音の始め → 録音バー → マイクと相手の声 → 話し声が無いとき、の順）。行は2つ: トグル「会議の検出の通知」（見える1行「会議のアプリがマイクを使い始めたら、録音するか聞きます。」・ⓘ）と「通知を出さないアプリ」（出さないにしたアプリの札と ×。無ければ「ありません」）。0.9.2 の決まり（1行・ⓘ・検索が吹き出しの文も見る）に入れる。場所は問い Q7。
12. **人に関わる情報の扱い（K2・K3）:** 外へは何も送らない（見張りもパネルも通信しない）。見張りが PowerShell の外へ出すのは一覧の id と FILETIME の数だけ。設定に残すのは出さないアプリの id だけ。engine.log には見張りの「始めた・止めた・読めない（符号）・起こし直し」だけ書き、**アプリの名前も id も書かない**（いつどの会議のアプリを使ったかを残さない）。窓の題名・URL・音は読まない。
13. **費用:** 見張りの PowerShell は1つ（数十 MB のメモリ。M-2 で Windows の CI で測って「作ったときに合わせたこと」に書く）。CPU は 2 秒に1回の読み（1 回 数 ms まで）。設定を切っている間と録音中は 0。パネルの窓は初めて出すまで作らない。

### B. 録音中のページの音の波

14. **大きさの道（聞く形）:** main の `levelWanted()` が真の間だけ、`LEVEL_ASK_MS`（100）ごとに `overlay:level-ask` を録音バーの画面へ送る。真は「議事録の録音中（`state === 'meeting'`・止めている途中でない）・一時停止でない・本体の窓が見えていて最小化していない・`liveShownByUi`」（前にあることは求めない: 横に会議のアプリを並べて見ている人にも出す）。録音バーの画面は受けたら `{ mic, sys, warn }`（`rmsOf` の値。`analyser` が無ければ 0。`warn` は `shownLabel`）を `overlay:level` で返す。main は `lib.levelMsg` で照らし（数は 0〜1 に収めて小数 2 けた、`warn` は決まった3つ（`''`・「音が入っていません」・「マイクの音が入っていません」）のほかは `''`）、`meeting:level` で本体の画面へ送る。理由: 録音バーの毎フレームから送ると、録音バーを隠したとき止まり（調べた結果の 2）、誰も見ていなくても 60 回／秒送る。
15. **`overlay.html` の直し（問い Q1）:** 受け口 `window.koeOverlay.onLevelAsk(() => window.koeOverlay.reportLevel(…))` の数行だけ。点・文・大きさ・区切り・無音の見張りは変えない（撮った録音バーの画面は全部そのまま: 取り直し待ちに入れない）。preload に `onLevelAsk`・`reportLevel` を足す。
16. **形（`#liveWave`）:** 丸いタブ「文字起こし」（`#paneBtnScript`）のすぐ右に、20 本の棒（幅 3px・間 2px・高さ 3〜16px・角丸 1.5px）。`#liveWaveNote`（12px）を続ける。左のタブ（AI 要約・メモ）を選んでいても出す（メモを書きながら音を拾っているのが分かる）。録音中のタブで会議の録音中だけ（保存したページ・作成中には出さない）。棒の列は飾り（`aria-hidden="true"`）で、意味は文で出す（`#liveWaveNote` は `role="status"`。文が替わったときだけ書く）。
17. **高さ（`waveHeights(levels)`。画面の中の純粋な関数）:** 1つの値は `max(mic, sys)`（録音バーの点と同じ: 問い Q9）。`SILENT_LEVEL`（0.02）以下は 3px の点、ほかは `round(3 + 13 · min(1, l · 1.25))`。届くたびに右に足して左を落とす（20 本で 2 秒）。1 秒届かなければ平らにする（止まった波を「音がある」と読ませない）。
18. **色と文:** 音のある棒は `--level`（夏の差し色。録音中の点と同じ）。全部が点（無音）なら `--muted` の点。`warn` があれば `#liveWaveNote` に同じ文（`--danger`）。一時停止中は列を空にして `--line` の点と「一時停止中」（`--muted`）。明暗はトークンだけ（生の色を書かない）。
19. **動きを減らす設定（`prefers-reduced-motion: reduce`）:** 流さない。20 本のうち真ん中の5本だけを、録音バーの `levelDots` と同じ重み（左右対称）で今の大きさに合わせる（場所は動かない）。CSS の transition は今の全体の決まり（`app.html:681`）で無い。
20. **一番下の「聞き取り中」の行（`#liveTail`）:** 録音中（一時停止でない）の文字起こしの一番下に、灰色（`--muted`）の行「聞き取り中…（約 <segSec> 秒ごとに文字になります）」（`segSec` が無いときは「聞き取り中…」だけ）。時刻の欄は空。`.seg` でない（区間の数・出典の飛び先・編集・コピーに入らない。止めていた時間の印 `.pausemark` と同じ扱い）。動く点は付けない（読み上げも毎秒しない）。Notion の灰色の「まだ決まっていない文字」に当たるのは、今の「（文字起こし中…）」の行（`.seg.pending`）と、この行。
21. **NaTsu にできないこと（ヘルプと問いに書く）:** 話している途中の文字を灰色で流すこと（本当の途中の文字）。理由: 音は区間（クラウド 15 秒・PC の中 75 秒）ごとに1つの WAV として中継へ送り、OpenAI のファイルの文字起こしが区間ごとに文字を返す（調べた結果の 6・7）。途中の文字には、中継を WebSocket の Realtime の道に作り直し（ログイン・上限・費用・認識ヒントと 0.9.1 の作り話の除き方も作り直し）、PC の中の文字起こしも別の作りが要る。0.9.3 の大きさを越える（この回でやらない）。区切りを短くすると速く出るが、送る回数が増え、区切りの所の言葉が切れて精度が落ちる（変えない）。
22. **費用:** 10 回／秒 × 3 つの IPC と、20 本の高さの書き換え（変わったものだけ）。ページが見えていないとき・一時停止中は 0。

### C. 名前の付け直し（持ち主の答え D54）

### D. オフラインモードの札（持ち主の答え D55）

27. **オフラインモードの会議であることが一目で分かる形:** オフラインモードの会議（［オフラインモード］を押した後・パネルの「オフラインモードで始める」・ほかの道で `localOnly` になった会議。画面は `mtLocalOnly || st.localOnly` で決め、押したかどうかだけで決めない）では、記録の行のボタン［オフラインモード］のあった所（すぐ後ろの `#meetingLocalOnlyState`）に、押せない札「オフラインモード中」を出す。札はボタンでない `span`（`role="status"`・`aria-describedby` で灰色の説明の行を指す・Tab で届かない）で、印はローカル AI の設定（`#setNavOffline`）と同じノート PC の線の絵（`aria-hidden`）。色は安全の色 `--ok` の文字と 1px の枠で地を持たない（明 `#1a6e42`・暗 `#4cc98a`。明暗のすべての地の上で 4.5:1 を `stage1b.look` が計っている組）。押せる形にしない: 高さはボタンの 28px より低い 24px・角丸 6px（部品の決まり）・`cursor: default`・`user-select: none`・`:hover`・`:active`・`:focus` の規則を持たない。札の文は同じなら書き直さない（読み上げを繰り返さない）。記録の行（`#liveTitle`）の括弧の中に「・オフライン」を足す: 「議事録を記録中（相手の声も・オフライン）」・相手の声が無ければ「議事録を記録中（オフライン）」・区間の待ちは後ろの括弧のまま「…（オフライン）（2区間を文字起こし中）」・一時停止「一時停止中（録音していません・オフライン）」・作成中「議事録を作成しています…（オフライン）」（オフラインモードの会議の要約は PC の中で作るので、作成中も同じ印）。灰色の説明の行（準備の無い PC の文も）は今のまま。戻すボタンは今どおり置かない（押し間違いでクラウドへ送る側に戻らない）。クラウドで処理しない PC（ボタンを出さない PC）でも、印があれば札を出す。main は印を付けたらいつも `meeting:update` を送る（前は準備の無い PC のときだけで、パネルの「オフラインモードで始める」の会議は次の区間（オフラインモードは長い区間）まで札と「オフライン」が出なかった）。

## 実機で利用者に見てもらうこと（0.9.3 を出した後）

1. NaTsu を起こしたまま Teams（か Zoom）の会議に入ると、2〜4 秒で右上に「AI 議事録を始める」のパネルが出る。パネルが出ただけでは会議のアプリの文字の入力が奪われない（チャットに打ち続けられる）。Windows の明るい・暗いで、パネルも白・暗い色になる（明るいパネルの影が灰色の四角にならない）。
2. 画面の共有をしている間、共有の相手の画面にパネルが写らない。
3. 何もしないと 30 秒で消える。カーソルを乗せている間は消えない。会議を抜けるとすぐ消える。同じ会議でもう一度は出ない。
4. ［文字起こしを始める］で録音バーが出て録音が始まり、NaTsu の窓が前に出て録音中のページが見える（窓をトレイに隠していても・最小化していても）。⌄ の「オフラインモードで始める」でオフラインモードの会議になる。「Zoom では出さない」の後は Zoom では出ない（［設定］→［録音］で戻せる）。
8. Notion の AI ミーティングノート（Notion もマイクを使う）や、NaTsu だけを使っているときは出ない。
9. 録音中のページのボタンが［オフラインモード］、設定の左の列が「ローカル AI の設定」になっていて、1行に収まっている。
10. Webex・Slack で会議に入ったとき、［設定］→［プライバシーとセキュリティ］→［マイク］の「最近のアクティビティ」に出る名前（実行ファイルの名前）を教えてもらう（一覧の `webex.exe`・`ciscocollabhost.exe`・`atmgr.exe`・`slack.exe` が合うか）。
5. 音声入力（ホットキー）を使っても出ない。録音中は出ない。
6. 録音中のページで、話すと「文字起こし」の右の点が動く。黙ると平らな点になり、8 秒で「音が入っていません」。一時停止で薄い点と「一時停止中」。録音バーを × で隠しても点は動く。
7. Google Meet（Chrome）でも出る（ブラウザを出さないにしたときは出ない）。YouTube を見ているだけでは出ない。
11. 録音中に［オフラインモード］を押すと、ボタンの所に緑の枠の「オフラインモード中」が出て、上の行が「議事録を記録中（…オフライン）」になる。札は押せるように見えない（カーソルが指にならない）。パネルの「オフラインモードで始める」で始めた会議でも、録音中のページを開いた時から同じに出る。明るい・暗いの両方で読める。
