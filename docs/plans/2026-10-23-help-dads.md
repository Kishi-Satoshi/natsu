## 目的

2026-10-23 に、持ち主の DADS のスキル（`digital-agency-design-system`。審査役）で手元に作ったヘルプセンターを深く審査した（記録: スクラッチパッドの `help-audit/report.html`・`help-audit/dads-review/20261023-094500-natsu-help-local/findings.md`。致命的 0／重要 3／軽微 17、うち DADS の印 17）。持ち主がその質問に答えた（下の「持ち主の決定」）。この計画は、その答えのとおりにヘルプセンターを直し、最後に審査役にもう一度審査させて、重要 0 を確かめるところまで。

1. **リンクがリンクと分かる**（重要 2。WCAG 1.4.11・1.4.1）: DADS どおり青と下線（訪問済み・ホバー・押している間も）。
2. **検索の箱が見える**（重要 1。WCAG 1.4.11）: 1px の枠。
3. **検索の結果が画面を見ない人にも伝わる**（重要 3。WCAG 4.1.3）: 見えない `role="status"` に件数・見つからない・読めないを入れる。設計書の「読み上げソフトへの対応は作らない」に例外を1つだけ書く。
4. **キーボードの輪が DADS どおり**（軽微 4）: 黒 4px＋黄色。暗い版は白＋黄色。
5. **文字が小さすぎない・ブラウザの文字の設定に従う**（軽微 5・6）: 説明・目次・パンくず 16px、補足 14px 以上、rem。
6. **スマホで押しやすい**（軽微 7）: 48rem 未満で押す場所 44px。
7. **色と書体を DADS に寄せる**（軽微 8・10）: 灰色を DADS の札の値に、書体を Noto Sans JP・Noto Sans Mono に（同梱）。暗い版は残す。
8. **守るものを宣言する**: リポジトリの直下に `DADS-PROTECT.md`。
9. **残りの軽微（11〜20）** は、下の「利用者に確かめること」の答えのとおりに直すか残す（答えが来るまでは勧めの案で計画を書いておく）。

## 方針

1. **直し方は DADS のスキルの「直す役」（`references/roles/fix.md`）に従う。ただしこのリポジトリの決まりが勝つ。** 作り手は各タスクの前に `DADS-PROTECT.md` を読み（HD-0 で置く）、守るものを変えるときは直さずに返す。直す順は「重要（WCAG AA）→ DADS の印 → 軽微」。スキルの手順と違えるところ（理由つき）:
   - ブランチはスキルの `dads-fix/<日時>` ではなく `lane/help-dads`（このリポジトリの作業の枝の決まり）。
   - 直す前に落ちるテストを書く（設計書「作り方」の 4）。スキルは直してから再点検だが、ここではテスト → 直し → 再点検の順。
   - 修正前後のスクショ（`.dads-review/`）を commit するかは問い Q13（勧めは commit しない）。
   - push は `lane/help-dads` だけ。main への merge は持ち主のはっきりした言葉があるときだけ（CLAUDE.md）。
2. **最後に審査役（`references/roles/review.md`）に深い審査をさせる。** `scripts/audit/audit.sh` で同じ8ページを撮り直し、致命的・重要・DADS の印の残りを数える。新しい致命的・重要が出たら直す役に戻す（2回まで）。審査役は直さない。作った本人が自分を採点しない（スキルの「役を分ける」）。
3. **色は全部 `:root` の札を通す（今の決まりのまま）。** 新しい札はリンク（4つ）と輪（4つ）。札の値は DADS の札の値か、`DADS-PROTECT.md` のブランド色（暗い版の灰色）だけ。テストが一覧で照らす。
4. **白黒が基本のまま。** 色を使うのはリンクと輪だけ。紺の面・色付きのバッジ・グラデーション・影・角丸は今どおり使わない。例外は DADS の輪の黄色（`box-shadow` の 2px）と輪の角丸 4px だけ（`:focus-visible` の規則の中だけ。テストで固める）。
5. **書体は配布元のファイルをそのまま同梱する。** 自分で切り詰め（サブセット）をしない。外の配信（Google Fonts の CDN）は CSP（`style-src 'self'`・`default-src 'self'`）で使えないし、使わない。
6. **CSP と出力の決まりは変えない。** `style=`・`on…=`・インラインの script を書かない（HF3・RF52）。`relay/help-gate.mjs` の `HELP_CSP` は変えない。

**使うもの:** Node の `node:test`、今のテストの台（`test/helpers/simcss.js`・`simdom.js`・`html.js`・`help-tmp.js`）、`tools/help-build.js`・`tools/help-shots.js`・`tools/mutate.js`・`tools/risk.js`。作業環境の Playwright と Chromium（`/opt/pw-browsers/chromium-1194`。リポジトリの依存ではない）。DADS のスキルの `scripts/audit/audit.sh`（Playwright 1.56.1・axe-core 4.14.0）。書体は npm の `@fontsource/noto-sans-jp`・`@fontsource/noto-sans-mono` の配布物をスクラッチパッドに `npm pack` で取り、ファイルだけを写す（リポジトリの依存にしない）。npm の依存は足さない。

**設計書:** `docs/plans/natsu-design.md` の「利用者が決めたこと（ヘルプセンター。2026-10-20）」の D22、「回をまたぐ決まり」の「ヘルプセンター」（HC0）と「画面の使いやすさ」（作らないもの: 読み上げソフトへの対応）、「全体を通して守ること」（Notion の資産: フォントは OS 標準）、「作り方」。ヘルプの元の計画 `docs/plans/2026-10-20-help.md` の方針 3（白黒）と H-3「見た目」、R7（画面の写真）。

## 持ち主の試作から参考にしたこと（2026-10-17 の試作を読み直した）

読んだもの: スクラッチパッドに残っていた `storage-plan/poc/db-server.js`（179 行）と `state-store/upload/state-store.js`（約 100 行）。試作の `main.js`・`preload.js`・`README.md` は、この作業環境では見つからなかったので、0.9.4 の計画（`docs/plans/2026-10-22-094.md` の同じ節）と設計書「保存の土台」に書いた中身で読み直した。試作の名前と値はそのまま持ち込まない。

1. **項目ごとに決まった形だけを通し、外れたら名前を出して断る**（`state-store.js` の `SCHEMA` は項目ごとの検証器で、外れた項目だけを既定に戻し、どの項目かを記録する）。→ 今の「help.css の色はどれも灰色」の照らしを、**決まった一覧の色だけを通す照らし**に置き換える（DADS の札の値と、`DADS-PROTECT.md` のブランド色）。外れた色は「どの規則の、どの値か」を出して赤にする（HD-1）。
2. **見た目の設定は「明・暗・OS に従う」の3つで、既定は OS に従う**（`state-store.js` の `theme: 'light'|'dark'|'system'`、既定 `system`）。→ ヘルプの暗い版は今どおり OS の設定（`prefers-color-scheme`）に従うだけにする。サイトに切り替えのボタンは作らない（ヘルプのサイトは保存を持たない・localStorage を使わない: `site.js` のテスト）。
3. **画面から受けるのは決まった命令の一覧だけ。知らない命令は断る**（`db-server.js` の `handlers` と `Object.hasOwn`、`blocked: unknown command`）。→ 読み上げの例外は「検索の箱の中の `role="status"` 1つ」だけにし、**出力の HTML の `role="status"` は検索の箱の中にしか無い**ことをテストで固める（例外が知らないうちに広がらない。DF3）。
4. **検索は上限で切った数を返す**（`db-server.js` の `search` は `LIMIT 20`）。→ 件数の知らせは「出した数」を言う。今の検索は上から 8 件で切る（`help/assets/search.js:9` の `MAX = 8`）ので、8 件のときは「上から 8 件を表示しています」と言い、全体の数と偽らない（HD-5）。
5. **壊れたものは消さずに退け、置き換えは1回で行う**（`state-store.js` の `.corrupt-<時刻>` への退避と、一時ファイル → fsync → 名前の替え）。→ 書体の入れ替えは1つの commit で行う（古い IBM Plex のファイルは git の履歴に残り、戻すときは revert 1つ）。途中で fonts.css と fonts/ が食い違う commit を作らない（HD-4）。
6. **関係しないもの:** DB 専用の別プロセス・MessagePort・SQLite（WAL・移行・FTS の trigram・バックアップ）・1 秒のまとめ書き。ヘルプのサイトは静的で保存を持たないので使わない。
