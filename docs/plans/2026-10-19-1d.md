**目的:**
1. **会社の OpenAI の鍵を PC から無くす（D6・D13）。** 文字起こしは、Cloudflare Workers の中継（`relay/`）が会社の鍵を付けて OpenAI へ渡し、文字だけを返す。鍵は Worker の秘密の欄にだけ置く。PC・リポジトリ・チャット・記録には一度も出ない。
2. **メールアドレスと確認コードの登録（D7・D11）。** 会社のドメインのメールだけが登録でき（ドメインは Cloudflare の秘密の欄にだけ置く）、6 けたのコードをメール（Resend）で送り、合えばログインの札（トークン）を渡す。札は PC では `safeStorage` でしまう。後で Microsoft のサインインを足せる継ぎ目を残す。
3. **使いすぎと盗みの守り。** 確認コードの総当たり・メールの送りすぎ・1人と全体の1日の音声の上限・モデルの固定・大きさの上限・札の取り消し（RF32〜RF34・RF38）。
4. **中継が止まっても会議は残る。** 中継に届かない・落ちている・上限に達したときは、今のオフラインと同じく手元の whisper で文字起こしする（RF35）。
5. **D5 の仮の形を外す。** ［詳細設定（管理者用）］の鍵の欄と、PC から OpenAI へ直に送る道を消す（Q3）。`src/` に `api.openai.com` を書けなくする（ゲート）。

**方針（アーキテクチャ）:**
1. **中継は npm の依存の無い、素の JS のモジュールの Worker**（`relay/*.mjs`）。使うのは Web の標準の部品（`Request`・`Response`・`Headers`・`fetch`・`URL`・`ReadableStream`・`TextEncoder`・`crypto.subtle`・`crypto.getRandomValues`）だけで、`node:` も `Buffer` も使わない。だから同じファイルを Node 22／24 の `node --test` で、Worker を起こさずに `worker.fetch(request, env, ctx)` として呼べる（`test/helpers/relay-run.js`）。
2. **外への通信は、テストでは 127.0.0.1 の偽物だけ。** 偽の OpenAI は今の `test/helpers/fake-stt.js`（OpenAI と同じ形）をそのまま使い、偽の Resend（`test/helpers/fake-resend.js`）を足す。中継は `env.OPENAI_BASE`・`env.RESEND_BASE` が `http://127.0.0.1:<port>` の形のときだけそれを使い、ほかの値（無い・https・ほかのホスト）は本物の固定の URL にする（本番で取り違えても、ほかのホストへ鍵を運ばない）。テストは `globalThis.fetch` を「127.0.0.1 のほかは断る」で包む。
3. **D1 は小さな口の後ろに置き、テストでは `node:sqlite` で真似る**（`test/helpers/fake-d1.js`: `prepare(sql).bind(...).first()／run()／all()`・`batch([...])`。`batch` は1つのトランザクション）。中継のコードは D1 のこの部分だけを使う。
4. **確認コード・札・回数の数えは D1 に置く**（下の「調べた結果」の 6。KV は書いた値がほかの場所で見えるまで 60 秒ほどかかりうるので、1回だけ使えるコードと回数の数えには使えない。Durable Objects は強く一致するが、50 人には大げさで、出し方も増える）。
5. **文字起こしは「生の WAV」で受けて、中継が OpenAI の形に組み立てる。** アプリ → 中継は `POST /v1/audio/transcriptions` に本文 = WAV（`Content-Type: audio/wav`）、言語と認識ヒントは見出し（`X-Natsu-Language`・`X-Natsu-Prompt`）。中継は本文を読みながら数え（上限で 413）、WAV の頭を確かめ、`model`（固定）・`language`・`prompt`・`response_format=json`・`temperature=0`・`file` の multipart を自分で作って、長さの決まった本文で OpenAI へ送る。アプリから来た multipart を解かないので、客がモデルや欄を差し込めず、CPU もほとんど使わない（「設計書と違えたところ」の 1）。
6. **出し方は wrangler を使わない。** Node の小さな台本 `tools/relay-deploy.js`（Node に入っている `fetch`・`FormData`・`Blob` だけ）が Cloudflare の REST API で、D1 の用意・表の形・Worker の上げ・workers.dev の有効化・`/health` の確かめを行う。GitHub Actions の `relay-deploy.yml` から、手で押すか main に `relay/` の変更が入ったときに走る。トークンは環境変数で渡し、コマンドの引数にも記録にも出さない。秘密の欄（会社の鍵など）は利用者が Cloudflare の画面で入れ、台本は `keep_bindings: ['secret_text']` で残す（台本は秘密の値を一度も持たない）。
7. **アプリの通信は今までどおり Electron の `net.request` だけ**（RF2）。中継の URL は `src/relay.js` の1つの定数（workers.dev の住所。会社名を含まない名前にする: Q7）。テストの台は偽の `net.request` の書き換えで、その URL を 127.0.0.1 の中継（本物の `relay/` のコードを Node の http で包んだもの: `test/helpers/relay-local.js`）へ届ける。
8. **経路の決め方は「会議の印 → ログイン → 中継に届くか」**（今の「会議の印 → 鍵 → 届くか」の鍵をログインの札に替える）。届くかは中継の `GET /health`。

## 調べた結果（出典つき。確かめたことと、確かめられなかったこと）

**資料で確かめたこと（2026-10-19 に公式の資料を読んだ）**

1. **Resend は、確かめたドメインが無いと、アカウントの持ち主のアドレスにしか送れない。** 「`resend.dev` のドメイン（`onboarding@resend.dev`）は試しのためだけのもので、Resend のアカウントに結びついたメールアドレスにしか送れない」。ほかの人へ送るには、自分のドメインを確かめて `from` に使う（https://resend.com/docs/knowledge-base/403-error-resend-dev-domain ）。
   → **workers.dev だけでドメインが無い間は、ログインできるのは Resend のアカウントを作った利用者本人だけ。** だから利用者は、Resend のアカウントを**会社のメールアドレス**で作る（そうしないと、登録できるドメインの絞りと食い違い、本人もログインできない）。50 人に配る前に、送り元のドメインが要る（問い Q1）。
   - ドメインを確かめるには、Resend が示す DNS の行を足す: `send`（またはサブドメインの下の `send.<名前>`）に MX と SPF の TXT、`resend._domainkey` に DKIM の TXT（https://resend.com/docs/guides/dns/cloudflare.md ）。ドメインそのものでなくサブドメインから送ることを勧めている（https://resend.com/docs/dashboard/domains/introduction ）。DNS が Cloudflare にあれば、Resend の画面のボタンで自動で足せる（同じ Cloudflare の資料）。
   - 無料の枠: 1日 100 通・月 3,000 通（https://resend.com/pricing ）。API は1チームで毎秒 10 回まで、超えると 429（https://resend.com/docs/api-reference/introduction ）。
   - 送る口: `POST https://api.resend.com/emails`、見出し `Authorization: Bearer <鍵>`、本文は `from`・`to`・`subject` と `text`（または `html`）。`Idempotency-Key` の見出しで二重の送りを防げる（24 時間）。答えは `{ "id": "…" }`（https://resend.com/docs/api-reference/emails/send-email ）。
   - 鍵の権限は `full_access` と `sending_access`（送るだけ）。`sending_access` なら送り元のドメインも絞れる（https://resend.com/docs/api-reference/api-keys/create-api-key ）。→ 中継には `sending_access` の鍵を使う。
2. **Cloudflare Workers の上限**（https://developers.cloudflare.com/workers/platform/limits/ ）:
   - 無料: 1日 10 万回（UTC の 0 時に戻る。超えるとエラー 1027）。1回の CPU 時間 **10 ミリ秒**。外への要求は1回の呼び出しで 50 まで。
   - 有料（Workers Paid）: 回数の上限なし、CPU 時間は既定 30 秒（5 分まで延ばせる）。
   - 本文の大きさの上限は Cloudflare のアカウントの種類で決まる（Free と Pro は 100MB、Business は 200MB）。→ 75 秒の WAV（約 2.4MB）も OpenAI の上限の 25MB も内側。
   - CPU 時間は自分のコードが動いた時間で、通信の待ちは数えない。メモリは 128MB。秘密と変数は無料で 64 個まで。
   - 時間の上限は、相手がつながっている間は無い（75 秒の音声の返事を待てる）。
3. **料金**（https://developers.cloudflare.com/workers/platform/pricing/ ）: Workers Paid は1アカウント月 5 ドルから（月 1,000 万回・CPU 3,000 万ミリ秒を含む）。D1 の無料の枠は1日に読み 500 万行・書き 10 万行・5GB。KV の無料の枠は1日に書き 1,000 回。
4. **秘密の欄**（https://developers.cloudflare.com/workers/configuration/secrets/ ）: 画面の Workers & Pages → その Worker → 設定 → 変数と秘密 →［追加］→ 種類を「シークレット」にして名前と値 →［デプロイ］。入れた後は画面にも出ない。
5. **REST API で上げる**（wrangler を使わない）:
   - `PUT /accounts/{account_id}/workers/scripts/{script_name}`（multipart）。`metadata` の JSON に `main_module`（モジュールの形の入口のファイル名）・`compatibility_date`・`bindings`（`{ type: 'd1', name, database_id }` など）・`keep_bindings`（「前の版から残すバインドの種類の一覧」）・`observability`（`logs.invocation_logs` で呼び出しごとの記録を止められる）。モジュールの部分の型は `application/javascript+module`。要る権限は「Workers Scripts Write」など（https://developers.cloudflare.com/api/resources/workers/subresources/scripts/methods/update/ 、https://developers.cloudflare.com/workers/configuration/multipart-upload-metadata/ ）。`compatibility_date` を書かないと最も古い日付（2021-11-02）になる（同じ資料）。
   - workers.dev の有効化: `POST /accounts/{account_id}/workers/scripts/{script_name}/subdomain` に `{ enabled: true, previews_enabled: false }`（https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/subdomain/methods/create/ ）。アカウントのサブドメインは `GET /accounts/{account_id}/workers/subdomain` の `result.subdomain`（https://developers.cloudflare.com/api/resources/workers/subresources/subdomains/methods/get/ ）。住所は `<Worker の名前>.<サブドメイン>.workers.dev`（https://developers.cloudflare.com/workers/configuration/routing/workers-dev/ ）。
   - D1: 作る `POST /accounts/{account_id}/d1/database`（`name`・`primary_location_hint` は `apac` などを選べる。書かないと作った人の近く）、探す `GET /accounts/{account_id}/d1/database?name=…`、SQL を流す `POST /accounts/{account_id}/d1/database/{database_id}/query`（`sql`・`params`。セミコロンで区切った複数の文は一まとめで流れる）。要る権限は「D1 Write」（読むだけなら「D1 Read」）（https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/create/ ・…/methods/list/ ・…/methods/query/ ）。
   - トークンの権限の名前（https://developers.cloudflare.com/fundamentals/api/reference/permissions/ ）: アカウントの「Workers Scripts Edit（書き込み）」と「D1 Edit（書き込み）」。画面の表は「Edit」、別の表は「Write」と書くが、どちらも説明は同じ「書き込み」。→ **最小の権限は、この1つのアカウントだけに絞った「Workers Scripts: Edit」と「D1: Edit」の2つ。**
6. **D1・KV・Durable Objects の一致の違い:**
   - KV は「結果として一致する」もので、ほかの場所で見えるまで 60 秒以上かかりうる。書いた場所ですぐ見えることにも頼れない（https://developers.cloudflare.com/kv/concepts/how-kv-works/ ）。→ 1回だけ使えるコード・試した回数・送った回数には使えない。
   - D1 は読みの写し（read replication）を有効にして Sessions API を使わない限り、全部の問い合わせが1つの本体で走る（https://developers.cloudflare.com/d1/best-practices/read-replication/ ）。`batch()` は1つのトランザクションで、1つ失敗すると全部戻る（https://developers.cloudflare.com/d1/worker-api/d1-database/ ）。`run()` の答えに `meta.changes` がある・`first()` は最初の行か `null`（https://developers.cloudflare.com/d1/worker-api/prepared-statements/ ）。→ **D1 を使う。** 読みの写しは有効にしない（既定のまま）。
   - Durable Objects は無料の枠では SQLite の形だけ（同じ料金の資料）。→ 使わない（50 人の数えには D1 で足り、出す物も増やさない）。
7. **Workers の記録**（https://developers.cloudflare.com/workers/observability/logs/workers-logs/ ）: 新しく作った Worker は記録が既定で有効。呼び出しごとの記録（invocation logs）には「要求・返事とその周りの情報」が入る（見出しが入るかは書いていない）。`console.log` も記録に出る。残るのは無料で 3 日、有料で 7 日。→ 呼び出しごとの記録は止め（`invocation_logs: false`）、中継が自分で書く1行（件数・符号・状態だけ）だけを残す。
8. **Web Crypto**（https://developers.cloudflare.com/workers/runtime-apis/web-crypto/ ）: `crypto.getRandomValues`・`crypto.randomUUID`・`crypto.subtle.digest('SHA-256')` がある。`crypto.subtle.timingSafeEqual` は Workers だけの拡張なので使わない（Node のテストで動かない。比べは「ハッシュで行を引く」形にして要らなくする）。
9. **Request の本文**（https://developers.cloudflare.com/workers/runtime-apis/request/ ）: `Content-Length` は中の仕組みが付け、自分で付けた値は無視される。長さの決まった本文（文字・`TypedArray` など）なら長さが付き、ほかの `ReadableStream` なら chunked になる。→ OpenAI へは組み立てた `Uint8Array` で送り、長さを付ける。
10. **OpenAI の文字起こし**（https://developers.openai.com/api/docs/guides/speech-to-text ）: ファイルは 25MB まで（wav を含む）。`gpt-4o-transcribe` と `gpt-4o-mini-transcribe` は認識ヒント（prompt）を受ける。今の資料は、録った音声には新しい `gpt-transcribe` を勧めている。→ 中継の既定は今と同じ `gpt-4o-transcribe` にし、Cloudflare の秘密の欄 `STT_MODEL` で、アプリを出し直さずに替えられるようにする（問い Q12）。
11. **GitHub Actions の秘密**（https://docs.github.com/en/actions/security-for-github-actions/security-guides/using-secrets-in-github-actions ）: フォークから起きたワークフローには秘密が渡らない（`GITHUB_TOKEN` のほか）。秘密が記録に出ないよう気をつけること、秘密をコマンドの引数で渡さないことを勧めている。→ `pull_request` で走らせない・秘密は手順の `env` で渡す・`echo` と `set -x` を使わない。

### D1 の表の形 v1（W-1 で作る。`relay/schema.mjs`）

```sql
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS login_codes (
  email TEXT PRIMARY KEY,           -- 小文字に揃えたメール
  code_hash TEXT NOT NULL,          -- sha256hex(email + ':' + code)
  expires_at INTEGER NOT NULL,      -- UNIX 秒
  attempts INTEGER NOT NULL DEFAULT 0,
  created_at INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS sessions (
  token_hash TEXT PRIMARY KEY,      -- sha256hex(札)。札そのものは持たない
  email TEXT NOT NULL,
  idp TEXT NOT NULL DEFAULT 'email',-- 後で 'microsoft' を足す
  created_at INTEGER NOT NULL,
  last_used_at INTEGER NOT NULL,
  expires_at INTEGER NOT NULL,      -- 最初から 180 日
  revoked_at INTEGER                -- 取り消した時刻（NULL なら生きている）
);
CREATE INDEX IF NOT EXISTS sessions_email ON sessions (email);
CREATE TABLE IF NOT EXISTS blocked_emails (email TEXT PRIMARY KEY, at INTEGER NOT NULL);
CREATE TABLE IF NOT EXISTS counters (key TEXT PRIMARY KEY, win INTEGER NOT NULL, n INTEGER NOT NULL);
INSERT INTO meta (key, value) VALUES ('schema', '1') ON CONFLICT (key) DO UPDATE SET value = excluded.value;
```
- 数え（`counters`）の鍵: `s:e:<メールの sha256 の先頭 32 字>`（15 分）・`s:d:<同じ>`（1日）・`s:ip:<IP の鍵>`（1時間）・`v:ip:<IP の鍵>`（1時間）・`mail`（1日の通数）・`a:u:<メールの sha256 の先頭 32 字>`（日ごとの秒）・`a:all`（全体の日ごとの秒）。メールと IP は鍵にもそのまま書かない。
- 古い行の片付け: `/auth/start` のたびに、期限の切れた `login_codes` と、2 日より古い窓の `counters` を消す（1 回の batch に入れる）。期限の切れた `sessions` は `/auth/verify` のときに同じメールの分を消す。
- 1.x で表の形を変えるときは足すだけにする（`meta.schema` を上げる。出す台本が `CREATE … IF NOT EXISTS` と `ALTER TABLE ADD COLUMN` を流す）。

### 書きながら直したこと

- **アプリから来た multipart をそのまま流す形をやめた。** 客がモデルや欄を差し込めないようにするには、中継が multipart を解いて組み直すか、ファイルの後ろの部分まで見張る必要がある。生の WAV を受けて中継が組み立てれば、解かずに済み、CPU もほとんど使わない（「設計書と違えたところ」の 1）。
- **認識ヒントを URL に入れない。** ヒントは辞書と直前の発言（文字起こしの文）で、URL は会社の通信の検査の記録に残りうる。見出し `X-Natsu-Prompt` にした。
- **OpenAI の 401 を中継の 401 と分けた。** そのまま流すと、アプリが「ログインが切れた」と取り違え、全員の札を消してしまう（会社の鍵の誤りは 502 `upstream-auth`）。
- **Resend のアカウントは会社のメールで作る。** 送り元のドメインが無い間は、Resend のアカウントのアドレスにしか送れず、登録できるドメインの絞りと合わさると、ほかのアドレスでは誰もログインできないため。
- **会社のドメインも秘密の欄に入れる。** ふつうの変数（plain_text）にすると、出し直しのたびに台本が送り直すか消すかを決める必要があり、画面にも見える。秘密にすれば `keep_bindings: ['secret_text']` だけで残る。
- **中継の秘密の値を、GitHub に一度も置かない。** GitHub に置くのは Cloudflare のトークンとアカウントの ID だけにした（会社の鍵を GitHub から Cloudflare へ運ぶ道を作らない）。

### 点検で直したこと（書いた後に、疑う点検役の目で読み直した。2026-10-19）

- **（重い）1日の上限に達したとき、今の RF29 の形（WAV を残して後で送り直す）にすると、その日の会議の文字起こしが翌日まで空になり、要約も作られない。** 手元の whisper でその日の残りを続ける形にした（Q8）。OpenAI の短い 429 は今のまま待つ。
- **（重い）ログイン切れの区間を「失敗」として残すと、取り消された人の会議が文字のないまま終わる。** その区間から手元でやり直し、札を消して、次の会議も手元にした。
- **（中）`/auth/start` の回数の数えを、送れたときだけ進めると、Resend が断る間に何度でも打たせてしまう。** 送る前に進め、全体の通数だけは送れたときに数える形にした。
- **（中）`account:status` が `/auth/me` を呼ぶと、設定を開くだけで外へ通信する（第1c回の決まりに反する）。** PC にある札とメールだけで答える形にし、変異 `ra-status-offline` で守る。
- **（中）出す台本が答えの本文を出すと、Cloudflare の答えにトークンが写っていた場合に記録に出る。** 出すのは状態の番号と `errors[].code` だけにした（変異 `rl-deploy-print`）。
- **（軽い）メールとコードの欄の Enter に、IME の確定の Enter で送らない確かめが無かった。** A-4 の画面テストに入れた（設計書「全体を通して守ること」の IME）。

## 設計書と違えたところ（理由つき。違う答えなら直す）

1. **アプリ → 中継の文字起こしは、OpenAI と同じ multipart ではなく生の WAV と見出し**（依頼の文は「multipart の本文をそのまま OpenAI へ流す」）。客がモデルや欄を差し込めないようにするには multipart を解くか見張る必要があり、無料の Workers の CPU の 10 ミリ秒（調べた結果の 2）を考えると、解かずに中継が組み立てる形が確か。道の名前（`/v1/audio/transcriptions`）・429 の `retry-after` の流し方・ヒントの 400 の送り直しは今と同じ。
2. **中継から OpenAI へは、流しながらではなく、読み終えてから長さの決まった本文で送る**（依頼の文は「流す」）。75 秒の区間は約 2.4MB で、128MB の中に十分収まり、待ちは CPU に数えない。chunked で送ったときに OpenAI が受けるかを確かめられなかった（調べた結果の 9）ので、長さの決まる形にした。どちらにしても中継は音声を保存しない。
3. **取り消しは管理の口を作らず、D1 の画面で SQL を流す手順にした**（依頼の文はどちらかを選ぶ）。管理の口には管理用の秘密が要り、それが漏れると全員の札を操作できる。D1 の画面は Cloudflare のログインで守られていて、50 人の間は回数も少ない。
4. **会社のドメインと送り元のアドレスも「シークレット」の種類で入れる**（設計書は「サーバーの環境変数」）。秘密の欄も環境変数の1つで、画面に値が出ず、出し直しで消えない（調べた結果の 4・5）。
5. **1日の上限・中継の止まり・ログイン切れは手元の whisper で続ける**（第1c回 RF29 は「上限は WAV を残して後で送り直す」）。RF29 は無料の送り先の短い上限を想定していた。中継の上限は1日単位で、待つと会議の文字起こしと要約が翌日まで無いため。OpenAI の短い 429 は RF29 のまま。
