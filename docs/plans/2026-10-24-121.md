## 目的

1. **自分が会議（Teams・Zoom・Chrome・Edge）を出たら、聞かずに録音を止めて議事録を作る。** 見張る会議のアプリがマイクを放したのを、見張りの3回続けての読み（約 6 秒）で見たら、すぐ止める（問8「自分が退出したら止まるでいいんじゃないですか？」・問9「放したのを 3 回続けて見たら止める（約 6 秒）（おすすめ）」・LQ1「黙ってすぐ止める」）。帯・数え下げ・入り直しの待ちは無い。
2. **止めたことは Windows の知らせで1回だけ伝える。** 止めた直後に「会議を出たので録音を止めました。議事録を作っています。」を、窓が前にあってもなくても1回出し、押すとそのページを開く（LQ1 の続き・LQ10・LQ13）。議事録を保存したときの今の動き（録音バーの「議事録を保存しました」・ページを開く）はそのまま。
3. **短い放しでは止めない。** 放して見えたのが1回か2回で、次の読みでまたマイクを使っていれば止めない（問8 の「誤検知を避ける」・問9 の「参加の前の画面から入るときの放しに備える」）。待合室でどれだけ待った後でも同じ（時間の窓に頼らない）。
4. **データが無いときは止めない。** 見張りの記録が読めない・見張りが落ちた・読みが途切れた・一時停止の間・会議のアプリが一度もマイクを使わなかった録音では止めない（0.9.1 の決めたこと 7 と同じ「分からないときは止めない側」）。
5. **誤って止まったときの道を案内する。** 新しい議事録で録り直し（問4）、分かれた文字起こしは今の［コピー］でもう一方のページのメモに貼る（問5・問7）。ヘルプに手順を書く。2つの議事録をつなぐ機能は別の版の計画にする。
6. **止めた理由を後から追える。** 議事録の経過（0.10.0 の `stateLog`）に、止めたきっかけ「終了（会議を出たので自動）」を積む（持ち主の試作の考え）。

## 決めたこと（理由つき）

1. **L1 判断は小さな純粋な状態機械 `leaveStep`（新しい `src/meetleave.js`）。** 状態は2つ: `wait`（まだ会議のアプリを見ていない）・`in`（会議中）。`in` の中に「続けて放して見えた読みの数」`gone`（0・1・2）と、その最初の読みの時刻 `goneAt` を持つ。答えは `{ st, act }` で、`act` は `''`・`'found'`（この録音で初めて W ができた）・`'blip'`（放して見えたのが1回か2回で、次の読みでまた使っていた）・`'reset'`（データが無い・読みが途切れた・一時停止・設定で数え直した）・`'stop'`。理由: 0.9.1 の `quietStep`・0.9.3 の `nudgeStep` と同じく、表のテストで全部の移り変わりを固定でき、main は答えのとおりに止める・記録するだけになる。2版目の `grace`（猶予）・`hold`（相手の声で待つ）・`back`（入り直し）は問8 で無くした。
2. **L2 見張る会議のアプリ（W）にしてよいアプリ:** `LEAVE_IDS = ['teams', 'zoom', 'chrome', 'edge']`（Teams・Zoom ［LQ7］と、ブラウザは Chrome・Edge だけ ［LQ5］）。Firefox・Webex・Slack は入れない（Webex・Slack は持ち主の確かめが間に合えば足す: LQ12）。ブラウザもアプリと同じ決まりで黙って止める。NaTsu 自身のマイクは今どおり見張りの文が除く。
3. **L3 W の決め方:** パネルから始めた録音は、パネルのアプリ（main の `nudgeShown.id`。画面から受けない）が `LEAVE_IDS` にあれば初めから W に入れる（Chrome・Edge のパネルも同じ。Firefox・Webex・Slack のパネルなら初めは空）。どの録音でも（パネル・ホットキー・ページのボタン・トレイ ［LQ4・問2］）、録音中に `LEAVE_IDS` のアプリが**2回続けて**マイクを使っているのを見たら W に足す（録音を始める前から会議に入っていても、始めた後に入っても）。理由: 0.9.3 の「2回続けて見たら出す」と同じく、一瞬の使い（音声メッセージの試しなど）で取り違えない。W は増えるだけで、録音の間は減らない。会議のアプリが一度もマイクを使わなかった録音（対面の会議など）は `wait` のままで、止めない。W が初めてできたとき `act: 'found'`（記録に1行。アプリの名前は書かない）。
4. **L4 止める決まり（問8）:** W が空でなく、W のアプリが1つもマイクを使っていない読み（「放した読み」）が**3回続けて**来たら `act: 'stop'`（`LEAVE_GONE = 3`。問9）。1回目の読みで `gone = 1`・`goneAt = now`、2回目で `gone = 2`、3回目で `stop`。見張りは 2 秒ごとに読むので、出てから止まるまでは 4〜6 秒（「約 6 秒」）。アプリが 4 秒より短く放しただけでは止まらず、6 秒より長く放すと必ず止まる（その間は読みの時刻しだい）。入り直しの待ち・相手の声の確かめ・聞く・数え下げ・「見始めて最初の何秒は数えない」窓は無い（問5・問8・問9・LQ1）。`stop` は条件が続く間は毎回返す（止めるかは main が決める: `quietStep` と同じ）。理由: 問1「どちらも同じくらい」で、長く待って「分かれる」を減らす理由は無い。2回（約 4 秒）では、参加の前の画面から会議に移るときにアプリが数秒マイクを放すと、入った途端に止まりうる（問9）。持ち主は初めに「見始めて最初の 30 秒は放しても止めない」を選んだが、待合室で 30 秒より待つとその窓が切れて守れないので、待ち時間によらず効く「3回続けて」にした。
5. **L5 短い放し・ほかのアプリ:** `gone` が 1 か 2 の後の読みで W のどれかが使っていれば `gone = 0` に戻す（`act: 'blip'`。記録に1行。経過には積まない）。参加の前の画面から会議に移る時の数秒の放し（読み2回まで）はこれで止まらない。同じアプリの `Start` が変わっていても「使っている」（機器を素早く替えた・開き直した）。同じブラウザの実行ファイル（同じ id）なら、どのタブの使いでも「使っている」（Windows の記録はタブを見分けない）。Teams の2つの exe とパッケージは、今の一覧どおり1つの id `teams`。W に無いアプリ（Zoom を W に入れていない Teams の会議の録音での Zoom・Firefox など）の使いは数えず、止めるのを妨げない（LQ6 の答えの残る意味）。
6. **L6 時計は見張りの行・読みが途切れたら数え直す:** main に新しいタイマーを作らず、見張りの読み（2 秒ごとの `mic …` の行）を `leaveStep` に渡すたびに数える。だから見張りが落ちた・止まったら数えも止まり、**データの無いまま止めることが起きない**。`gone` が 1 か 2 の読みと次の放した読みの間が `LEAVE_GAP_MS = 10000` より空いたら（PC が眠った・PowerShell が固まった）、2つの読みを「続けて」と見ず、後の読みを1回目として数え直す（`act: 'reset'`・`goneAt` はその読みの時刻）。時計が戻った（`now` が前の読みより前）ときも、その読みを1回目として数え直す。
7. **L7 データが無いときは止めない:** 見張りの `err read`・`err proc` の行・形の悪い読みと、見張りが落ちた（`onMicWatchGone`）ときは `leaveStep` に `{ type: 'lost' }` を渡し、`gone` を 0 に戻す（`gone` が 1 か 2 だったなら `act: 'reset'`）。次に読めた放した読みは1回目として数える。
8. **L8 一時停止:** 一時停止の間は数えない（`{ type: 'pause', on: true }` で `gone` を 0 に戻し、一時停止の間の読みは数えない）。再開（`on: false`）の後の読みから数える（再開の後に放した読みが3回続けば止める）。理由: 一時停止は利用者がはっきり選んだ止め方で、休憩で会議を出て戻る人の録音を止めない（0.9.1 の決めたこと 14 と同じ）。
9. **L9 設定:** 「会議を出たら自動で止める」がオフなら、どの読みでも `act: ''`（`gone` を 0 に戻す）。録音中にオンにし直したら、次の読みから数える（W は覚えたまま）。
10. **L10 止め方:** `stop` を受けたら、`state === 'meeting'` で止めていないときだけ `stopByLeave()` → `stopMeetingBy('auto-leave')`（今の1つの道）。`STOP_BY['auto-leave'] = 'leave'`、経過は `auto-stop`（「終了」）できっかけ `leave`（「会議を出たので自動」）。`m.leaveStopped = true`・`m.leaveAt = goneAt` を付ける。0.9.1 の `m.autoStopped` は付けない（`quietDoneNotice` を出さない）。
11. **L11 止めた後の Windows の知らせ（LQ1 の続き・LQ10・LQ13）:** `stopByLeave()` が本当に止めたとき（`stopMeetingBy` の前の照らしを通ったとき）だけ、その場で Windows の知らせ LN4 を**1回**出す（`leaveStopNotice(m)`。題名は今の `APP_TITLE`）。録音中のページが見えていてもいなくても出す（LQ13「いつも 1 回出す」）。押すと本体の窓を出し、その会議がまだ作成中なら録音中のページ（今の `showLiveFromNotice`）、保存した後なら `page:open` でそのページを開く（開くページは main が覚えた会議から決め、画面から受けない）。閉じない（Windows の通知センターに残る）。`Notification.isSupported()` が偽なら記録だけ。議事録を保存したときの今の動き（録音バーの「議事録を保存しました」・`pages:updated`・`page:open`）は変えない。
12. **L12 話し声が無いときの聞き方（0.9.1）とのつながり:** 話し声の帯（「会議は終わりましたか？」）が出ている間に会議を出た決まりが `stop` を返したら、**会議を出た決まりが勝つ**。`stopByLeave()` → `stopMeetingBy('auto-leave')` → 今の `stopMeeting` が `closeQuietAsk(meeting)` で話し声の帯の録音バーの送り直しと Windows の知らせを閉じ、`meetingStatus().quiet` は `state === 'meeting'` でなくなるので帯は次の `meeting:update` で消える。経過のきっかけは `leave`（`quiet` でない）、止めた後の知らせは LN4 だけ（0.9.1 の `quietDoneNotice` は出ない）。今の `stopMeeting` が聞いている間の停止で付ける `m.quietTrim` はそのまま残り、所要時間は L13 で早い方。その後に 0.9.1 の `autoStopQuiet` は走らない（`stopMeetingBy` が `state` で照らす。止めるのは1回）。逆に、0.9.1 が先に止めたら（`auto-quiet`）、会議を出た決まりは何もしない。
13. **L13 所要時間:** 会議を出たので止めた議事録の所要時間は、**放した最初の読みの時刻**（`goneAt` → `m.leaveAt`。壁の時計）までにする（`meetingDurationSec(m, m.leaveAt)`）。その後の 4〜6 秒（3回目の読みまで）に録った区間と文字起こしの行は**消さず、要約からも特に外さない**。理由: 長さが数秒で、たいてい「失礼します」などの挨拶か無音しか入らない。外すために区間を切ったり要約の入力を分けたりすると、作りとテストが増えるのに、得るものがほとんど無い（持ち主の試作の「消さずに残す」とも合う）。0.9.1 の `quietTrim` の行は変えず、その後ろに別の文で足す（変異 `q-trim` の `from` を守る）。両方が立ったら早い方。
14. **L14 経過（議事録の `stateLog`）:** `src/statelog.js` に `BY_NAMES.leave = '会議を出たので自動'` の1つだけを足す。止めたら `auto-stop`（`leave`）。**2版目の `app-left`「会議のアプリがマイクを放した」・`app-back`「会議に入り直した」と、きっかけ `detect` は足さない。** 理由: 止まる 4〜6 秒前の「放した」は、すぐ後の「終了（会議を出たので自動）」と同じことを言うだけで、入り直しも無くなった。短い放し（`blip`）を経過に積むと、MCP の経過がつまらない項目で埋まる。調べたいときのために、`found`・`blip`・`reset` は engine.log の決まった行に残す（LN8）。経過の上限の数え（2版目の `LEAVE_LOG_MAX`）も要らなくなった。
15. **L15 設定:** 新しい鍵 `autoStopLeave`（`bool`・`notFalse`・既定 `true`）［LQ3］。ラベル「会議を出たら自動で止める」。カード「会議の検出」の2行目に置く（カードの数は 12 のまま）。オフにしたら `leaveStep` に `{ type: 'setting', on: false }`。
