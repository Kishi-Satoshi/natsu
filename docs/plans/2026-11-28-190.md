## 目的

1. 配る物（インストーラー・更新の zip・`natsu-update.json`・`get-installer.ps1`・`setup-local-engine.ps1`・文字起こしのエンジン）を、配るためだけの公開のリポジトリ `natsu-releases` から配る。アプリの更新の確かめ・［ダウンロード］・エンジンの取り込み・`get-installer.ps1` をそちらへ切り替える（D102）。
2. 後でソースのリポジトリを非公開にしても、0.19.0 からのアプリの更新・インストーラーの取り込み・エンジンの取り込みが壊れない形にする（D102 の目的「計画書・開発の履歴・会社の事情を見せたくない」）。非公開にすること自体は、この版ではしない（AQ190-1）。
3. Electron を 45 の最新の安定版へ入れ替える（D104・AQ190-4。44 の支えは 2027-03-02 まで、45 は 2027-04-27 まで）。インストーラーで一度入れ直してもらう。
4. 前の版を使っている人が、0.19.0 の入れ直しまで迷わず進める（AQ190-2）。

1. **配る側のリポジトリは、持ち主が GitHub の画面で作る公開の `natsu-releases`（README だけ）。**（AQ190-3）手順は「持ち主の手でする所」の手順 1。中にソースは置かず、リリースに配る物を付けるだけにする。配る側では Actions を切る（そこでは何も走らせない）。理由: リポジトリと鍵は外から見える・権限に関わる操作なので、持ち主の手で作るのが確か。失うもの: 持ち主の手が要る（手順 1〜5 で 30 分ほどの見込み）。
2. **0.19.0 から、アプリの確かめ先・［ダウンロード］・`get-installer.ps1` を配る側に向ける。** `src/updater.js` の `REPO` を `<持ち主のアカウント>/natsu-releases` にする（定数は1つのまま）。［ダウンロード］の URL・`readFeed` の既定・エンジンのテストの結び付きは、今どおり `REPO` から作る。`get-installer.ps1` の `$repo` も同じにする（`test/identity.test.js` が照らす）。理由: 定数1つを替えれば、アプリの中の確かめ先がみなそろい、画面から URL を受け取らない形（`test/repo.test.js` の「外部URL」）も保てる。接続先のホストは同じなので、会社の許可の頼み直しは要らない（R9）。失うもの: 0.19.0 を入れた PC は今のリポジトリを見なくなる（今のリポジトリだけに出した版は届かない）。`get-installer.ps1 -Version <0.18.x 以前>` は配る側に無い版なので取れない（前の版は今のリポジトリのページから取る。「この回でやらないこと」）。
3. **0.19.0 は、今のリポジトリと配る側の両方に、同じ実行で作った同じバイトの物を出す。**（AQ190-2）0.18.x のアプリは今のリポジトリの latest に 0.19.0 を見て、入れ直しの知らせと［ダウンロード］を出し（0.19.0 の `natsu-update.json` の `electron` は `>=45.x.y` なので、0.18.x の Electron 44 は満たさない）、［ダウンロード］で今のリポジトリの 0.19.0 のページが開く。入れた 0.19.0 は配る側を見る。今のリポジトリへも出す版は、`release.yml` の決まった一覧 `SOURCE_TOO`（AQ190-7。おすすめなら `0.19.0` だけ）で決め、一覧に無い版は配る側だけに出す。理由: 入れ直しは1回だけで、前の版のコードを変えずに済む。失うもの: 0.19.0 のリリースの流れが2か所へ出す形になり、流れとテストが増える。
4. **鍵は、配る側だけに効く細かい権限の鍵（Contents: write）を、ソースのリポジトリの環境 `dist`（Deployment branches は `release/*` だけ）の秘密 `DIST_TOKEN` に置く。**（AQ190-3）鍵を読む仕事は `release.yml` の `release`・`installer` と、`whisper-vulkan.yml` の `publish` だけにし、鍵は `gh` を呼ぶ段の `env` にだけ渡す（仕事の `env` に置かない。`npm test` の段と `ci` の仕事には渡さない）。下書きを作る前に、鍵で配る側を読めるかを確かめ、読めなければ下書きを1つも作らずに止める（「鍵の期限が切れたか、取り消されています。持ち主の手順 4 で作り直してください」）。GitHub の答えに鍵の期限の見出し（`github-authentication-token-expiration`）があれば、期限の 30 日前から、リリースの要約に「配る側の鍵の期限が近い（YYYY-MM-DD）」と出す。期限の長さは AQ190-10。理由: 毎日 `claude/*` や `lane/*` の枝を push するので、リポジトリの秘密の欄だと、どの枝のワークフローからも読める。環境なら `release/*`（main と同じく持ち主のはっきりした言葉の後だけ push する枝）の仕事だけが読める。失うもの: 期限ごとに持ち主が作り直す。リリースのたびに環境の「Deployments」の記録がソースのリポジトリに1つ増える（害は無い）。
5. **`release.yml` の形（作り方の細かいことなので、作り手が選んだ。持ち主に問わない）。**
   - **起こし方:** `release/natsu-v*` の push と、`release/*` の枝の上の Run workflow の2つにし、タグ `natsu-v*` の push で起こす形をやめる。理由: 環境 `dist` は `release/*` の枝だけを通すので、タグの実行は鍵を読めずに途中で止まる（今のリポジトリの下書きだけが残る）。この作業環境のプロキシはタグの push を通さない（README の「タグを push できない環境」）。失うもの: タグから起こす道が無くなる（README とテストを直す）。
   - **配る側を主にする:** `release` の仕事は zip と `natsu-update.json` を1回作り、まず配る側に下書きを作る（`--target main`。配る側の札は配る側の `main`（README の commit）に付ける。中身は今と同じ zip・`natsu-update.json`・`get-installer.ps1`・`setup-local-engine.ps1`）。配る側の下書きの題は「`natsu-v0.19.0`（下書き: <commit>）」にし、同じ札の下書きが別の commit の題なら止める（今のリポジトリの下書きの守り `targetCommitish` と同じ役。配る側には commit が無いので題に書く。下書きの題は外から見えない）。公開のときに題を札の名前に戻す。今のリポジトリには、`SOURCE_TOO` の版のときだけ今の段（守りもそのまま）で下書きを作る。理由: 0.19.1 から配る側だけに出しても、配る側の段だけで守りが効く。失うもの: 配る側の下書きの題に一時だけ commit の字が入る（公開で消える）。
   - **exe は1回だけ作る:** `installer` の仕事は、配る側のリリースにもう exe があれば作り直さず（今の「公開済みか確かめる」を配る側に向ける）、無ければ作って配る側に添付する。`SOURCE_TOO` の版では、今のリポジトリに exe が無ければ同じ exe（作ったもの、または配る側から落としたもの）を添付し、あれば配る側と同じバイトかを照らす。
   - **公開の前の照らし:** 配る側の zip を落とし、配る側の `natsu-update.json` の SHA-256 と大きさに合うかを照らす（アプリが当てるときの照らしを、公開の前に1回通す）。`SOURCE_TOO` の版では、2か所の資産（zip・`natsu-update.json`・ps1 2つ・setup.exe）が名前ごとに同じバイトかを照らす。どれかが違えば公開しない（下書きのまま）。
   - **公開の順:** 配る側を公開（`--title "$TAG" --draft=false --latest`）→ 鍵の無い要求で `https://api.github.com/repos/<配る側>/releases/latest` の `tag_name` が札になったかを確かめる（アプリが見るのと同じ形。少し待って数回）→ `SOURCE_TOO` の版では今のリポジトリを公開。理由: 0.18.x の人が今のリポジトリで 0.19.0 を見た時には、入れた 0.19.0 が見る配る側に 0.19.0 とエンジンがもうある。配る側の公開で止まれば、今のリポジトリは前の版のまま（0.18.x の人には何も変わらない）。失うもの: 2か所の公開の間の数十秒、配る側だけが新しい。
   - **変えない所:** ヘルプの出し直し（`help-redeploy`。今のリポジトリの `help-deploy.yml` を起こす）・一時ブランチの片付け・版の照合・ゲート・チェックリスト・`publish=false` で下書きのまま止める入力・失敗したときの赤い要約。配る側の名前は `node -p "require('./src/updater').REPO"` で読み（アプリと流れの名前が1か所）、今のリポジトリと同じ名前なら止める。
6. **0.19.0 ではソースのリポジトリを非公開にしない。**（AQ190-1）非公開にするのは、前の版の人が移り終え（今のリポジトリの 0.19.0 のインストーラーの取り込みの数と、Teams での確かめで見る）、持ち主が GitHub のプランと費用（R6: 環境の秘密が無料のプランで効かなくなる・Actions の分の費用）を確かめた後の、別の作業にする（「後の作業」）。理由: 移り終える前に非公開にすると、その人の更新とエンジンの取り込みが止まる（R4）。失うもの: 0.19.0 を出した後もしばらく、計画書と開発の履歴が見えたまま。
7. **エンジン（`whisper-vulkan-d1be6fd`）は、同じバイトの zip を配る側の先行版 `whisper-vulkan-d1be6fd` に置き、`src/engine-manifest.js` の URL の持ち主の所だけを配る側に替える。**（AQ190-5）大きさ（20,440,811）・SHA-256・`dir`・`id`・中のファイルの表は変えない（R12 のとおり、取り込んだ PC は落とし直さない）。今のリポジトリの先行版は消さない（0.15.1〜0.18.x が取る）。先行版は latest にしない（配る側の `releases/latest` は `natsu-v` の札だけ）。写し方は AQ190-8（おすすめは持ち主が画面で写す: 手順 5）。写した後、作り手が配る側の URL から落として大きさと SHA-256 をピンと照らし、DS-1 の CI の `engine-smoke --pins` でも照らす。理由: 後でソースを非公開にしても、0.19.0 からのエンジンの取り込みが止まらない。失うもの: エンジンの置き場が2つになる（中身は同じ）。

## 持ち主の手でする所（持ち主が GitHub の画面でする。承認の後、DS-1 の前に）

作り手（AI）は鍵の値を見ない・受け取らない。どの手順も、鍵の値をチャット・計画・コードに書かない。終わったら「手順 1〜5 が終わった」とだけ知らせてもらう。

**手順 1 配る側のリポジトリを作る（5 分）**
1. GitHub にログインし、右上の［＋］→［New repository］を押す。
2. 「Owner」は今の NaTsu のリポジトリと同じ自分のアカウント、「Repository name」は `natsu-releases` にする。
3. 「Description」に「NaTsu の配布用（インストーラーと更新のファイルだけ。ソースは置いていません）」と書く。
4. 「Public」を選ぶ（非公開にすると、アプリが更新を確かめられない）。
5. 「Add a README file」（または「Initialize this repository with a README」）をオンにする。「.gitignore」と「license」は「None」のまま。
6. ［Create repository］を押す。
7. できたリポジトリの `README.md` を開き、右上の鉛筆の印を押して、中身を次の字に替え、［Commit changes...］→「Commit directly to the main branch」で保存する。
   ```
   # NaTsu の配布用リポジトリ

   NaTsu のインストーラー（NaTsu-<版>-setup.exe）と、アプリの更新のファイルを置く場所です。ソースは置いていません。

   - 最新版: 右の「Releases」から、いちばん上の natsu-v<版> を開き、NaTsu-<版>-setup.exe を落として実行します。
   - 入れた後の更新は、アプリの［設定］→［更新］でできます。
   - 「whisper-vulkan-…」の先行版は、アプリが取り込む文字起こしのエンジンです。手で落とす必要はありません。
   ```
8. ［Settings］→「General」の「Features」で、「Wikis」「Issues」「Projects」（と、あれば「Discussions」）のチェックを外す（問い合わせは今までどおり Teams で受けるため）。
9. ［Settings］→ 左の［Actions］→［General］の「Actions permissions」で「Disable actions」を選び、［Save］を押す（配る側では何も走らせない）。

**手順 2 鍵（Fine-grained token）を作る（5 分）**
1. 右上の自分のアイコン →［Settings］→ 左のいちばん下の［Developer settings］→［Personal access tokens］→［Fine-grained tokens］→［Generate new token］を押す。
2. 「Token name」は `natsu-dist-release`、「Description」は「NaTsu の release.yml と whisper-vulkan.yml が natsu-releases にリリースを作るため」にする。
3. 「Resource owner」は自分のアカウントにする。
4. 「Expiration」は AQ190-10 の答えの長さにする。おすすめの (a) なら［Custom］を選び、作る日のちょうど1年後の前の日を選ぶ（例: 2026-12-01 に作るなら 2027-11-30）。選んだ日を控える（手順 4 で使う）。
5. 「Repository access」は［Only select repositories］を選び、「Select repositories」で `natsu-releases` だけを選ぶ（ほかのリポジトリを選ばない）。
6. 「Permissions」の「Repository permissions」を開き、「Contents」を［Read and write］にする。「Metadata」は自動で「Read-only」になる。ほかは「No access」のまま。
7. ［Generate token］を押す。出た `github_pat_` で始まる字を、手順 3 の 4 で貼るまでだけ写しておく（この画面を閉じると二度と見られない）。チャットやメールには貼らない。

**手順 3 ソースのリポジトリに環境を作り、鍵を入れる（5 分）**
1. 今の NaTsu のリポジトリ（ソースのリポジトリ）を開き、［Settings］→ 左の［Environments］→［New environment］を押す。「Name」に `dist` と打ち、［Configure environment］を押す。
2. 「Deployment branches and tags」で［Selected branches and tags］を選び、［Add deployment branch or tag rule］を押す。「Ref type」は「Branch」、「Name pattern」は `release/*` と打ち、［Add rule］を押す。（「Required reviewers」と「Wait timer」は付けない）
3. 同じ画面の「Environment secrets」で［Add environment secret］を押す。
4. 「Name」に `DIST_TOKEN`、「Value」に手順 2 の 7 で写した字を貼り、［Add secret］を押す。
5. 写しておいた字を消す（メモ帳などに残さない）。
6. 確かめ: ［Settings］→［Secrets and variables］→［Actions］の「Repository secrets」に `DIST_TOKEN` が無いこと（鍵は環境 `dist` の中だけに置く）。

**手順 4 鍵の期限の前に作り直す（年1回。AQ190-10 の答えで回数が変わる）**
1. 手順 2 の 4 で控えた期限の日の **30 日前** に、カレンダーへ「NaTsu の配る鍵（natsu-dist-release）を作り直す」と入れる。
2. リリースの流れも、期限の 30 日前から、リリースの Actions の要約に「配る側の鍵の期限が近い」と出す（決めたこと 4）。期限が切れると、リリースは下書きを作る前に「鍵の期限が切れたか、取り消されています」で止まる（何も壊れない）。
3. 作り直すとき: 手順 2 を同じ設定でもう一度行って新しい鍵を作る（名前は `natsu-dist-release-2027` のように変えてよい）→ 手順 3 の画面で `DIST_TOKEN` の［Update］（鉛筆の印）を押して新しい字に替える → ［Fine-grained tokens］の一覧で古い鍵を［Delete］する → カレンダーに次の期限の 30 日前を入れる。
4. 鍵が漏れたかもしれないときは、すぐに一覧で鍵を［Delete］し、3 と同じに作り直して、取りまとめ役に知らせる（配る側のリリースの資産が差し替えられていないかを照らす）。

**手順 5 エンジンを配る側に写す（10 分。AQ190-8 が (a) のとき）**
1. 今の NaTsu のリポジトリの［Releases］で `whisper-vulkan-d1be6fd`（先行版）を開き、`whisper-vulkan-bin-x64-d1be6fd.zip`（約 19.5MB・20,440,811 バイト）と `whisper-vulkan-bin-x64-d1be6fd.zip.sha256` の2つを落とす（名前を変えない。開かない）。
